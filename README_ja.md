# chipvoice

<p align="center">
  <a href="README.md">English</a> &bull;
  <a href="README_ja.md">日本語</a>
</p>


5つのクラシック音源チップをサイクル単位でエミュレートし、参照コアと実機用テストROMで検証します。ブラウザーでもサーバーでも動作し、人もエージェントも、実機で鳴っていたように聞ける音楽を書けます。

遊ぶなら **[chipvoice.dev](https://chipvoice.dev/ja)**。使うなら `npm i chipvoice`。

[プレイグラウンド](https://chipvoice.dev/ja)は完全な編曲から始まります。Marioはファミコン本来の4声、ZeldaはMIDIの全4パート、Sonicは全14パートです。曲か日本版ゲーム機のロゴを選ぶ最初の操作で再生します。再生／一時停止、先頭へ戻る、曲全体のシークスライダー、クリックできる楽譜で探索できます。プリセットのフルミックスは、同じJavaScriptエンジンで生成したロスレス音声です。カーソルは音声出力の時計に従い、機種、テンポ、ソロを変えても、次の音を準備する間、楽曲内の位置を保ちます。Loopを切ると1回だけ再生します。

MIDIをローカルで読み込み、楽器を分離し、実機由来のMarioを独立したNSFレンダラーと比較できます。各移植は省略した音と代替音色を報告し、伴奏を勝手に足しません。読み込みには準備とレンダリングの進捗を表示します。再利用できるSDKの流れは `importMidi → planPerformance → renderPerformance`。[手順と限界](scores/arrangements/README_ja.md)では、元ゲームの検証、MIDI採譜、機種間の編曲を区別します。

**Make a loop**を開くと、同じページでエディター、鍵盤、パッド、録音、元に戻す、コード、書き出し、共有を使えます。保存した下書きもここへ復元し、共有リンクは引き続きその楽譜を開きます。モード変更時には前の楽器を一時停止します。C64は公開セレクターから隠していますが、SDKと保存済み楽譜の対応は維持しています。

[試聴ラボ](https://chipvoice.dev/ja/lab)にはエンジン比較を置き、旧 `/lab/arrangements` はホームへリダイレクトします。[About](https://chipvoice.dev/ja/about)ではブラウザー合成、制約、評価、クレジットを説明します。ゲーム機のマークは自前配信のカラーSVGです。[出典一覧](apps/web/public/machines/README_ja.md)を参照してください。

サイトは[英語](https://chipvoice.dev)と[日本語](https://chipvoice.dev/ja)に対応し、作曲画面、試聴ラボ、アクセシビリティのラベル、共有メタデータまで含みます。言語変更で楽器は中断しません。JSONカタログ、ルーティング、網羅性の検査は[国際化](docs/INTERNATIONALIZATION_ja.md)を参照してください。アカウントは不要です。[現在のプレイグラウンド仕様](docs/UNIFIED-PLAYGROUND_ja.md)もあります。

<a id="why"></a>
## なぜ作るのか

1980〜90年代のゲーム機やホームコンピューターには、それぞれ独自の声を持つ音源チップがありました。NESの2つのパルス波と三角波、Game Boyの波形チャンネル、Mega DriveのFM、SNESのサンプル、C64のフィルター。その制約の中で一世代の音楽が書かれ、今は2つの形で残っています。録音は特定のテレビを通してどう聞こえたかを残し、レジスターダンプはプログラムがチップへ書いた全バイト、つまり音楽が*何であったか*を残します。録音は音を保存します。ダンプは楽器を保存しますが、正確に再生できるものが存在する間だけです。

エミュレーターは古いゲームを遊ぶためチップを生かします。しかし、人が今いる場所、ブラウザー、Webページ、エディターで、頭に曲がある人やプロンプトを持つエージェントが新しい音楽を書くためのものは不足しています。ブラウザーで「8ビット音」を提供するライブラリは、帯域制限した矩形波や独自のノイズ生成器で似た音を合成し、それをチップと呼びます。でもチップそのものではなく、その機械で育った人には違いが聞こえます。

chipvoiceはチップ自体をソフトウェアにし、形容詞でなく測定に照らします。それぞれ固有の時計で動き、実機プログラムと同じバイトを同じレジスターへ受け取り、実物に照らして比較します。参照エミュレーターとはサイクルごと、シリコンを調べるためコミュニティが書いたテストROM、実機の録音とも比較します。各チップのシートに、検証済みと未検証を明記します。目的は音だけでなく楽器の保存、そして人でも機械でもその楽器を手に取り演奏できるようにすることです。

<a id="what-it-is"></a>
## 何を提供するか

- **クロック単位でエミュレートするチップ。** ブラウザーのAudioWorkletで動かすか、サーバーでオフラインのファイルへ描き出します。現在はNESのRicoh 2A03、Game BoyのDMG APU、Mega DriveのYM2612とSN76489、SNESのS-DSP、C64のSID 6581の5つ。Mega DriveとSNESは参照コアの移植で、検査したコーパス上で一致します。ほかは文献から実装し、コミュニティのコアと比較しています。
- **その上のドライバーとトラッカー。** 曲は旋律、和音、ベース、打楽器の4行と、各行の音色を示す単語で書けます。同じ4行と単語を、各チップ固有の語法で演奏する[移植可能な楽譜](docs/SCORE_ja.md)です。下層の楽器は、実機ドライバーと同じフレームごとのテーブルです。
- **実機がすべてのゲームに課した制約。** 効果音が音楽のチャンネルを奪い、音楽が途切れます。音楽と効果音はエミュレートされた発音数の予算を共有します。
- **音だけでなくバイトも出力。** 曲が作るレジスター書き込みを、NES、Game Boy、Mega DriveではVGMとして出力し、対応プレイヤーで再生できます。SNESとC64のファイル出力は未完了です。
- **APIとスキル。** エージェントが作曲、検証、リンクとMP3の取得、他の人の曲のフォークを行えます。[chipvoice.dev](https://chipvoice.dev/ja)がエディターとAPIです。

`conform`が2026-09-04に出力した数値です。各列の意味：

- **機種**：ゲーム機またはコンピューター。**チップ**はパッケージ内の名称です。
- **完了**：後続四指標の平均を概数として示します。契約となるのはこの数字でなくシートです。
- **デジタル**：参照エミュレーターと一致するデジタル出力の割合。ステップ時刻で整列するエッジの連続区間の割合を使い、参照側固有の規約に耐える尺度とします。100%はこのコーパスと参照実装についての値で、実機の網羅的な正確さではありません。
- **ROM**：ハーネス内のCPUで合格するコミュニティのテストROM。存在しなければダッシュです。
- **アナログ**：DAC後のミックス、フィルター、ゲーム機の出力段を、どこまで実機で測定したか。
- **ドライバー**：チップの全チャンネルのうちドライバーが鳴らせるもの。残りも存在し検証済みですが、曲から到達できません。
- **シート**：各セルの詳細を示す適合性シート、または予定機種のロードマップ段階。

**NES、ファミコン**（Ricoh 2A03、0.1.0〜）。デジタル参照はNes_Snd_Emu 0.1.7（blargg）。13ログ、92.2Mサイクル。ステップ時刻で整列する区間は97.7%（6665/6820）、完全一致サイクルは3.9%。残りは参照側の規約で、シートに説明します。ROMはblarggの`apu_test`、`apu_reset`、`dmc_tests`、`apu_2005`の29/29が合格。ミキサーは本人の実機録音と比較しましたが、フィルターとその後のDACは未測定で、実機ライン出力が必要です。DMCとの打ち消しは矩形波-32.7 dB（実機-32.2）、三角波-33.0 dB（-30.9）、ノイズ-13.8 dB（-16.2）、dmc-31.0 dB（-27.2）。ドライバーはDMC以外に対応し、DMCへ届く楽器はまだありません。残りはクロック付近のエンベロープ、スイープ、三角波を確認する第二参照、実ゲームのコーパス、フィルター測定用の実機です。

**Game Boy**（DMG APU、0.8.0〜）。Gb_Snd_Emu 0.1.4（blargg）、7ログ、145.1Mサイクル。整列区間97.5%（12645/12969）、完全一致サイクル57.4%。差の規約はシートへ。blarggの`dmg_sound`は12/12合格。アナログ未測定で、出力段は測定で置換する仮実装です。全四チャンネルを使い、ベースは波形、ドラムは実機エンベロープ。残りはより強い参照SameBoy、実機ライン出力、まだ楽器から使わないスイープと長さカウンターです。

**Mega Drive、Genesis**（YM2612 + SN76489、0.11.0〜）。Nuked-OPN2 1.0.12（Nuke.YKT）、7ログ、1798.7Mサイクル。整列区間100.0%（36580/36580）、完全一致サイクル100.0%。参照規約の詳細はシートへ。YM2612はNuked-OPN2を行単位で移植して比較したもので、このコーパス上の参照一致であり、シリコンを直接取得した結果ではありません。PSGは文献から実装し、参照は未導入。アナログ未測定で、Nuked自身のDACモデルも未検証、ミックスとModel 1フィルターは仮実装です。旋律とベースがFM、和音がPSG、キットがノイズで、十チャンネル中四つ。残りはPSG参照、編曲器のLFO・SSG-EG・DAC利用、実機ライン出力です。

**Super Nintendo**（S-DSP、0.12.0〜）。snes_spc 0.9.0（blargg）、5ログ、23.9Mサイクル。整列区間100.0%（183/183）、完全一致サイクル100.0%。参照規約はシートへ。S-DSPはsnes_spcを行単位で移植し、エコーとFIRを含め出力ストリームをサンプルごとに比較しています。アナログは未測定で、DACと本体フィルターは仮実装です。DSP出力を取得できればストリームと直接比較できます。ドライバーはビルド時生成のBRRサンプルバンクと実機エンベロープを使い、旋律、ベース、打楽器に加え、共通音量予算で最大五つの和音ボイスを同時に使います。残りは実機ライン出力とSPC書き出しです。

**Commodore 64**（MOS 6581 SID、0.13.0〜）。6581としてのreSID-fp（libsidplayfp、drfiemost）、7ログ、30.5Mサイクル。整列区間100.0%（1207/1207）、完全一致サイクル100.0%。規約はシートへ。SIDは文献から実装し、GPLのreSID-fpはハーネス内だけで比較します。全チャンネルのDAC前波形とエンベロープカウンターという二つのデジタル値で一致します。アナログは文献ベースの未測定プロファイルで、6581の非線形DACラダー、測定済みカットオフ曲線に沿うフィルター、出力段のコーナー周波数を持ちます。8580は未実装。全三チャンネルを使い、第三を和音とキットが共有し、C64曲同様ドラムが和音を切ります。残りは編曲器のフィルター利用、8580、実機ライン出力、6510上でのVICEのSIDテストです。

**今後**（PC Engine、GBA、Amiga、POKEY、YM2151、YM2610）。五機種の後、需要に応じて進めます。

<a id="running-it"></a>
## 実行方法

```bash
pnpm install
pnpm build            # パッケージ、その後サイトをビルド
pnpm dev              # http://localhost:3010 のエディターとAPI
pnpm test:unit        # 検証器、数式と時計、ドライバー、VGM、ゴールデンハッシュ
pnpm --filter chipvoice-conform check   # 参照とのコーパス比較。基準から回帰しないこと
pnpm --filter chipvoice-web test # ローカルの本番ビルド、一時DB、実ブラウザー音声測定
```

パッケージの`pnpm test`は新規インストール試験も行います。tarballを作り、空のプロジェクトへインストールし、ブラウザーで動かします。これがリリースの合格条件で、CIは各pushで単体テストを行います。

<a id="how-accurate-is-it"></a>
## どれほど正確か

形容詞でなく測定で示します。全チップが[`docs/CONFORMANCE.md`](docs/CONFORMANCE_ja.md)の手順に従うシートを持ち、何をどの参照で検証し、どの差が既知かを記載します。2A03の[`docs/chips/2a03.md`](docs/chips/2a03_ja.md)では、コーパス全曲のパルス波がblarggの参照とサイクルごとに一致し、ハーネスの6502上で29個すべてのAPU ROMが合格し、実NES録音とのミキサー打ち消しも実機並みです。Game Boyの[`docs/chips/dmg.md`](docs/chips/dmg_ja.md)はSM83上で`dmg_sound`の12/12が合格。Mega Driveの[`docs/chips/md.md`](docs/chips/md_ja.md)は、ダイの解析に基づくNuked-OPN2とコーパス全サイクルのYM2612が一致。SNESの[`docs/chips/snes.md`](docs/chips/snes_ja.md)は全出力サンプルがsnes_spcと一致。C64の[`docs/chips/c64.md`](docs/chips/c64_ja.md)は、文献実装のSIDが各声の2デジタル値でreSID-fpと一致します。全5機種で正直に**未検証**と残るのは、実機ライン出力が必要なアナログ段です。[ロードマップ](docs/ROADMAP_ja.md)はその行を変える順序、[バックログ](docs/BACKLOG_ja.md)は今週の対応です。

<a id="where-it-is-going"></a>
## 目指すもの

1つの楽譜、多くのチップ。[ロードマップ](docs/ROADMAP_ja.md)に各段階を記載します。各チップは文献から実装してコミュニティのROMで検証するか、実シリコンで検証されたコアから借ります。契約はシートです。製品は、人やエージェントが1度書けばNES、Game Boy、Mega Drive、SNES、C64それぞれの語法で鳴る[移植可能な楽譜](docs/SCORE_ja.md)です。全5機種が今動き、デモでは1操作で音を比べられます。音符とドラムのタップを量子化してループへ録音でき、テイク単位のUndo、任意のMIDI入力、制御された変奏、制作向け書き出しもあります。実機スマートフォンの使いやすさ確認は未完了。第6チップは現在の優先事項ではありません。

<a id="melody-studies-in-the-composer"></a>
### 作曲画面の旋律研究

[プレイグラウンド](https://chipvoice.dev/ja)と[試聴ラボ](https://chipvoice.dev/ja/lab)に、Marioの50小節、導入付きZeldaの24小節、Sonic主題の完全な24小節周期を含めます。出典を記した旋律採譜で、**ベース、和音、ドラムは創作して足していません**。Sonicの独立したイントロは含めません。

固定した原典台帳で、415個すべての音高、開始、解放、休符を、全機種のコンパイル済み楽譜とシーケンサーに照らします。4分音符あたり12ステップで3連符も保ちます。収録範囲、原典ハッシュ、実測の時刻許容差、MIDI抽出、`pnpm scores:compare`は[原典の手順](scores/README_ja.md)へ。

移調とドラム活動量のスライダーには数値入力、Undo、Resetがあります。旋律のみの楽譜ではドラム活動量を無効にします。編集した音は共有と書き出しへ残し、検証した原典カートリッジと編集版をUIで区別します。

オフライン音声は楽曲時刻0から始まり、全ループの書き出しで最後の音を保ちます。そのため音声のゴールデンスナップショットを意図的に更新しました。ライブ起動の先読みは変更していません。
