# 参照基準：MAMEのsn76496

<p align="center">
  <a href="README.md">English</a> &bull;
  <a href="README_ja.md">日本語</a>

MAMEのSN76489系デバイス（`src/devices/sound/sn76496.cpp`）である`sn76496.cpp`／`sn76496.h`をネイティブビルドし、レジスターログで駆動します。メガドライブのドライバーが実際に使うSega VDP PSG、`segapsg_device`として構成します。<https://github.com/mamedev/mame>からコミット`76c7d197ed46e844ffb1fbad5cc21c9ab3cdc9c0`固定で同梱し、ファイル自身のヘッダーが掲げるBSD-3-Clauseライセンスです（[LICENSE](LICENSE)）。リポジトリ内の検証道具で、この参照のファイルは`chipvoice`パッケージに入りません。独自実装コードはMITです。

<a id="what-is-mames-and-what-is-not"></a>
## MAMEのコードと本プロジェクトのコード

`sn76496.cpp`と`sn76496.h`はMAMEの無変更コードです。それ以外はすべてこちらのものです。

- `emu.h`は、同梱したファイルが使うMAMEデバイスAPIの一部だけを最小限に模したものです。`device_t`、`device_sound_interface`、`sound_stream`、`machine_config`、`device_type`、`emu_timer`、`attotime`、`save_item`、`logerror`、`fatalerror`、`BIT()`など。末尾で`#define private public`と`#define protected public`を、模したクラスをすべて定義し終えた後に置くため、`sn76496.h`／`sn76496.cpp`とその後に取り込む`main.cpp`だけがアクセス制限の緩和を受け、それより上の模したクラス群は本来のアクセス制御を保ちます。これにより`main.cpp`はMAME自身にはないアクセサを足すことなく`m_register[]`や`m_output[]`を直接読めます。
- `main.cpp`はログを読み、マスター時計基準（下の「この参照実装について」参照）でデバイスを駆動し、PSG4ボイスの全変化をハーネス自身のボイス番号で`<cycle> <voice> <value>`として出力します：6（psg1）、7（psg2）、8（psg3）、9（noise）。ログ中のYM2612への書き込みは別チップのものなので読み飛ばします。
- `LICENSE`はこのディレクトリ用に書いた素のBSD-3-Clauseテキストです。MAME自身のリポジトリには逐語的にコピーできる単一のBSD-3-Clauseファイルがなく（ルートの`COPYING`はライセンスの異なるプロジェクト全体を扱います）、そのため同梱したファイル自身のヘッダーが掲げる表記に従い「Nicola Salmoria and the MAME team」を著作者名とし、`sn76496.cpp`／`sn76496.h`だけを対象にしています。このディレクトリの他のファイルはすべてchipvoice自身のもので、リポジトリのライセンスに従います。

初回にシステムC++コンパイラーで`build/`へ作ります。

<a id="what-this-oracle-is"></a>
## この参照実装について

`segapsg_device`として構成し、`sn76496_base_device(mconfig, SEGAPSG, tag, 0x8000, 0x01, 0x08, false, false, 8, false, true, owner, clock)`（`sn76496.cpp:225-228`）で構築します：フィードバックマスク`0x8000`、白色ノイズのタップ`0x01`と`0x08`、反転なし、ステレオなし、クロック分周8、NCR方式でなくSega方式。これはメガドライブのドライバー自身が使う種類で、VDPから`SEGAPSG(config.replace(), m_snsnd, DERIVED_CLOCK(1, 15))`として構成され（`315_5313.cpp:248`）、VDP自体は`MASTER_CLOCK_NTSC`から駆動され（`megadriv.cpp:763`）、`psg_w`はデバイスへの単純な素通しです（`315_5124.h:66`）。したがってこの参照実装はPSGをマスター時計のちょうど1/15、`53693175 / 15 = 3579545` Hzで走らせ、`dsp.ts`自身の`PSG_STEP`と一致します。

時間基準：`segapsg_device`はサウンドストリームを`clock() / 2`で走らせ、内部でさらに8分周する（固定の`clockdivider`）ため、実質的な内部の1歩、すなわち各チャンネルの周期カウンタの1回のデクリメントは、生のPSGクロック16サイクルごとに1回起き、これは`sn76489.ts`自身の`/16`分周器と正確に一致します。これを変えずに再現するため、`main.cpp`は生のPSGクロック2サイクル（マスター30サイクル）ごとに1回`sound_stream_update()`を呼びます。もっと多くまたは少なく呼べば、MAME自身の無変更コードが出す音程が変わってしまいます。すべてのスタンプにこの窓の半分（マスター15サイクル）の一定の位相補正を加えています。`sn76489.ts`自身の分周器は0から始まり上へ数えるのに対し、MAMEの`m_current_clock`は`clockdivider - 1`にあらかじめ読み込まれ下へ数えるため、MAMEの最初の実質的な歩みが生のPSGクロック1つ分早く来るからです。この補正により、この参照実装のスタンプは最初の歩みだけでなく毎回、`dsp.ts`自身の規約と揃います。

ボイスの値の写像：`output[c] ? (15 - register[2c+1]) : 0`とし、MAMEの生の減衰レジスターを直接読みます。ミキサー向けのdBテーブル音量である`m_volume[]`ではありません。これはchipvoice自身のデジタルトレースが報告する量と同じです：`packages/chipvoice/src/chips/md/sn76489.ts`の`outputs()`はトーンについて`output[i] ? 15 - attenuation[i] : 0`を、ノイズについて`lfsr & 1 ? 15 - attenuation[3] : 0`を計算しますが、これはMAMEの`m_output[3]`（毎シフトで`m_RNG & 1`に設定される）が反映するのと同じビットです。

<a id="known-limits-of-this-oracle"></a>
## この参照の既知の限界

以下の各項目はいずれも、MAMEの`segapsg_device`と`sn76489.ts`との間にある、ビルド済みの参照バイナリに対して確認済みの実際の相違であり、この参照実装がデバイスの状態を読み違えたり駆動し違えたりしている欠陥ではありません。各所見の全文と、それぞれを示すコーパスログは[シート](../../../../docs/chips/md.md#psg-parity-against-mames-sn76496)にあります。

- 周期0または1のトーン：MAMEの`sound_stream_update()`には特別扱いがなく、実質的な歩みごとに常にリロードとトグルを行うため、周期0または1は分周器が出せる最速の音、約111861 Hzになります。`sn76489.ts`の`clock()`は`period[i] <= 1`を特別扱いして出力を一定のハイに保ちます。SMS PowerのSN76489資料は両方の読み方を記しています。
- リセット時の出力極性：MAMEの`device_start()`はトーンチャンネルに`m_output[0..2] = 0`を設定しますが、`sn76489.ts`の`reset()`は`output.fill(1)`とします。両モデルとも各チャンネルのカウンタを0から始めるため最初のリロードは同じサイクルで起きますが、その共有のリロードは両モデルを逆方向へ反転させます。リセット以降初めて無音解除されたチャンネルが最初の自然なリロードより前だと、この一度きりの反転がその音符の間ずっと持続します。
- tone 3のノイズレート：`(register[6] & 3) == 3`のとき、MAMEはtone 2の周期を倍にし（`m_period[3] = m_period[2] << 1`）毎リロードでLFSRをシフトしますが、`sn76489.ts`の`noisePeriod()`はtone 2の周期をそのまま返し、1つ置きのリロードでのみシフトします。両方式は定常状態では同じ正味のシフト速度になりますが、どちらのモデルもレジスタ6へのモードのみの書き込みでカウンタや出力フラグをリセットしないため、このモードを（再）設定した後の残留位相は履歴に依存し、両者で異なり得ます。
- リセットからの白色ノイズLFSRの周期：このデバイスに対して直接走らせた使い捨ての測定プログラムで別途確認済みで（コーパスには含めていません。完全な周期には約4億4千万マスターサイクルが必要です）、正確に57337シフトで、本シートの数式テストの数値と一致します。周期モードは正確に16シフトで、これも一致します。

この参照実装はPSG4ボイス（psg1、psg2、psg3、noise）のすべてについて信頼できます。上記の相違はいずれもMAME自身のコードを忠実に読み取ったものであり、この参照実装がデバイスの実際の状態を誤って報告しているわけではないからです。MAMEと`sn76489.ts`が食い違う箇所では、基準値は今日のコーパスがどれだけ一致しているかを記録するものであり、将来の変更をそれと比べて測るためのものであって、どちらか一方の読み方だけが正しいという主張ではありません。
