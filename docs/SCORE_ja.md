# 移植可能な楽譜

<p align="center">
  <a href="SCORE.md">English</a> &bull;
  <a href="SCORE_ja.md">日本語</a>
</p>


**状態：5機種で出荷済み。** 最初の移植可能な楽譜は0.9.0で出荷しました。設計判断16に起源を記録し、以下に編曲器の能力と今後の作業を区別して記載します。

<a id="the-problem"></a>
## 問題

1つの曲を多くの機種へ。チップごとに声の数、楽器の意味、制約から育った慣習が違います。移植は編曲であり、歴史的には手作業でした。同じゲームでもMega Drive版とSNES版の音楽は、別の人による別の仕事でした。

chipvoiceの初期形式、固定楽器の4行、16分音符ごとのトークンは、自覚のない2A03向け編曲でした。必要なのは音楽が*何か*と、チップが*それをどう扱うか*を分けることでした。

<a id="two-layers"></a>
## 2つの層

**楽譜**は役割、音符、各役割の*意図*、つまりどう鳴ってほしいかの単語を示します。波形もチップも知りません。`packages/chipvoice/src/score.ts`の`Score`で、APIの転送形式も楽譜です。

**編曲**はチップが楽譜へ行う処理で、2か所にあります。

- **編曲器**は`chips/{nes,gb,md,snes,c64}/arranger.ts`で、意図を機種の楽器へ固有の語法で写します。`arrange(score, chip)`は同じ行とその機種の楽器を持つ`Song`を返します。
- **チップのドライバー**は役割を声へ写し（`ChipSpec.roles`）、各音のフレームをレジスターへ変換します（`ChipDriver`）。ベースを波形へ、音量変更を再トリガーへ、ドラム減衰を実機エンベロープへ変えます。設計判断15を参照。

独自音色が必要なら、楽器を明記した`Song`も再生できます。楽譜導入前の公開曲の音は変えていません。意図なしの楽譜は従来の楽器へ編曲します。

<a id="roles"></a>
## 役割

`lead`、`chord`、`bass`、`perc`。形式が常に使ってきた名前と4役割で、SN76489以降の各チップが何らかの形で担えます。`chord`をharmonyへ改名すると、良い単語のためだけに全保存曲を壊すことになります。

より多い声を持つ機種が必要とした場合に限り、将来は第2旋律、持続パッド、重複の指示を加えます。

<a id="intents"></a>
## 意図

役割ごとに1語。検証器、OpenAPI、スキルの表で共有する単一カタログ、`score.ts`の`INTENTS`から選びます。

| 役割 | 単語 |
| --- | --- |
| `lead` | `soft`（既定）、`bright`、`round`、`sweep` |
| `chord` | `plucked`（既定）、`held` |
| `bass` | `round`（既定）、`hollow`、`bright`、`resonant` |
| `perc` | `tight`（既定）、`soft`、`punchy` |

パラメーターでなく単語です。両方を書いて判断しました。エージェントは`brightness: 0.8`より「明るいリード」を確実に書け、単語なら編曲器へ機種固有の余地を残せます。明るい旋律は2A03とGame Boyなら12.5%パルス、YM2612なら高いモジュレーターレベルのパッチ、SNESなら特定のサンプルです。数値はすべてを同じ誤った答えへ押しがちです。

ベースで語法の違いがよく分かります。NESは三角波だけなので単語にかかわらずそれを使います。Game Boyは波形チャンネルで、単語がRAM内の波形を選びます。`"hollow"`はGame Boyを変えてNESは変えません。その機械の性質なので、スキルにもそう記載します。

`"punchy"`は打楽器の語法で同じことが起きる単語です。自前の合成で打楽器が作れるチップでは、ノイズやサンプルの代わりにそれを使います。Mega Driveならチャンネル6のFMドラムで、サンプルでも汎用的な代用品でもありません。その能力を持たないチップは普段のキットに戻ります。単語が指すのは仕組みでなく結果なので、後から同じ能力を得たチップにも新しい単語は不要です。

| --- | --- | --- | --- | --- | --- |
| 2A03 | パルス1、デューティーで音色 | パルス2、フレームレートのアルペジオ | 三角波 | ノイズ、存在すればDMCサンプル | アルペジオ和音と三角波ベース |
| DMG | パルス1、デューティー、音量変更で再トリガー | パルス2のアルペジオ | 意図をRAM波形にする波形チャンネル | 実機エンベロープに合わせたノイズキット | 波形チャンネルのベース |
| YM2612 + SN76489 | FMパッチ、`"bright"`ではLFOも | PSGアルペジオ | FMパッチ | tone 3でクロックするPSGノイズ、または`"punchy"`ならチャンネル6のFMドラム | FM音色 |

<a id="the-voice-budget"></a>
## 発音数の予算

最初に試したのはC64の4役割に対する3声でした。旋律とベースに各1声を残し、和音と打楽器が第3を共有します。規則はドライバーでなくシーケンサーに置きます。ドライバーは予約時に音を一括展開し、後から取り戻せないためです。ドラムで和音を切り、次のドラムまで戻します。各区間をドラムの1フレーム前に終え、和音のnote-offがドラムのgateへ当たらないようにします（`roles.chord === roles.perc`のときの`Sequencer.scheduleStep`）。C64のドラム入り曲と同じで、忙しいドラムには和音の余地が少ないことをスキルでも伝えます。3声PSGで典型的なベース／和音交替も、必要な機種では役割を変えた同じ規則になります。S-DSPの8声のように役割より多い声は、他の役割と1声を共有する代わりに実三和音、重複、エコー声を可能にします。`canPlay`と`claim`はチップ自身の声IDを使います。

<a id="structure"></a>
## 構造

従来どおりパターンとorderを使います。未完了はループ点、調、名前付きセクション。検証器に調べるものができたらループ点と調を加え、必要になるまでセクションを入れないという軽量方針は変えません。

<a id="validation"></a>
## 検証

2段階で、両方に`silent`フラグを残します。

- **楽譜レベル**は機種非依存。音名が解析でき、各行長が一致し、役割別音域が妥当で、ループが十分長く、全意図がカタログにあり存在する役割を指すこと。
- **編曲レベル**は機種別。このチップがこの楽譜でできないことを調べます。基音や和音／楽器アルペジオの極値がレジスター範囲外なら、役割、パターン、ステップ付き`pitch_range`警告を、和音の音数がチップの和音ボイス数を超えれば`chord_capacity`を出します。どちらもメッセージに加えて`measured`と`limit`を持ちます。レジスターが表現できない変調は、黙ってクランプせず診断します。ボイスを音域外に振るビブラート（`vibrato_range`）やその音高で1レジスターステップ未満に潰れるビブラート（`vibrato_resolution`）、ドライバーの60Hzフレームクロックが解決できないビブラートレート（`vibrato_rate`）、保持音を音域外へ運ぶスライド（`slide_range`）や周期テーブルの粗い区間を横切るスライド - 特に2A03とゲームボーイのテーブルの低音端（`slide_resolution`）、レジスターに届く前にチップが丸める小数のボリュームステップ（`volume_step`）です。声の予算も同じ形で診断します。SIDの和音と打楽器がともにv3を使うような、物理ボイスを共有する役割に打楽器が重なる場合（`voice_share`）、2A03の単一ノイズチャンネルのようにキットの1パートが1ボイスを共有するチップで、前の音の減衰が終わる前に次のドラムが来る場合（`perc_voice`）です。共有レジスターも同じ形で診断します。SIDのフィルターはそれを求めるすべてのボイスに対してカットオフ、レゾナンス、モードが1つずつしかないため、リードの`sweep`とベースの`resonant`が同時に鳴っても、フィルターは2つではなく1つで、実際に後から書き込まれたボイスの値がそのまま鳴ります。`filter_conflict`は、異なるフィルター設定を求める2つのトラックが同時に鳴る最初のステップを、耳で見つけさせるのではなく名指しします。ルール自体 - 後から書き込んだ方が勝つ、それ以上の調停はしない - は変わらず、楽譜の責任ではなく`SidDriver`が守るべきものです。楽譜も出力音もどちらも変わりません。これらはすべて診断であり、修正ではありません。未知サンプルバンクの診断は完全ではありません。

<a id="export"></a>
## 出力

レジスターイベント列からのVGMはNES、Game Boy、Mega Driveで出荷済み。SNES／C64は未完了。NSFやGBSなどにはファイル内のドライバーが必要で、機種ごとに後で対応します。

<a id="what-comes-next"></a>
## 次の作業

原文では空き声を使うSNES三和音とFM打楽器をP8-13としています。SIDのフィルターはもう公開済みで、旋律の`sweep`とベースの`resonant`です（P7-9）。NESのスイープ機構による滑らかなビブラートは実装済みです。新機種は需要に従い、編曲の仕上げや実機検証のためにチップを増やす必要はありません。
