# ネイティブ楽曲の忠実度 — 2026-09-07

  <a href="NATIVE-SONGS-2026-09-07.md">English</a> &bull;
  <a href="NATIVE-SONGS-2026-09-07_ja.md">日本語</a>

<a id="finding"></a>
## 発見

Sonic に関するユーザーの指摘は正確でした。以前のメガドライブ版は GM 系音色に置換し、原典 MIDI の 291 音を省略していました。元の VGM にある 448,596 件の DAC サンプル書き込みも含んでいませんでした。Zelda も MIDI 採譜であり、MIDI 台帳との一致はゲームの楽器の検証ではありませんでした。

解決策は元の機種でネイティブコマンドを再生し、編集・他機種版の移植用観測を分離することです。曲の選択で元の機種を選び、Mario、Zelda、Sonic すべてに独立した A/B 参照を用意します。

<a id="evidence"></a>
## 証拠

| 楽曲 | 元のバージョン | ネイティブ比較 |
| --- | --- | --- |
| Mario | NTSC ファミコン・NES | 41,999 コマンド。アドレス、バイト、順序、絶対 CPU サイクルは変更なし |
| Zelda | NTSC NES、NSF トラック 2 | 28,306 コマンドが独立 GME 実行と一致。バンク切り替え対応、1,920 フレームの反復周期全体を検証 |
| Sonic | NTSC メガドライブ、Green Hill Zone VGM | 展開した FM・PSG・DAC の 458,039 コマンドが元の VGM サンプル時刻で独立 GME デコードと一致 |

Zelda は最初の演奏と反復周期を含め 63.2625 秒です。Sonic は 53.1993 秒で 14.7993 秒からループします。Zelda は NES 版であり、追加音源を持つファミコン ディスクシステム版ではありません。

Sonic では、GME の VGM デコードから独立して再構成したバスをネイティブ Nuked-OPN2 に入力します。全内部クロック後の FM 6 声と DAC 両出力をハッシュ化し、**68,010,485 クロック**、1,088,167,760 バイトを対象とします。両実装の SHA-256 は `cf257205e4336af9751be4c0b46c2ca76c73a319dd7c3aa56d42eabd30916cb2` です。これは記載した FM バス方針でのデジタル出力の検証であり、アナログ PCM の一致ではありません。

<a id="a-necessary-integration-regression"></a>
## 必要な統合回帰テスト

最初のネイティブアダプターで別の問題が見つかりました。VGM は複数の論理レジスター書き込みを同じサンプル時刻に置けます。アドレスとデータを隣接する YM クロックで送ると処理待ち設定が失われ、要求したオペレーター倍率が電源投入時の値のままでした。同じ誤った直列化を与えた独立コアも一致してしまうため、デジタルダイジェストだけでは不十分だと分かります。

修正後は Nuked のバッファ方式に従い、FM ポートの各バイト間を 15 内部クロック空けます。回帰テストはログ中のバイトの存在だけでなく、実際に動くコアの倍率、エンベロープ、周波数状態を検証します。原典検査では論理時刻を変更せず、物理バスの直列化を明示します。Sonic のアドレスの最大遅延は 353,430 マスターサイクル、6.5824 ms です。VGM から元の CPU 時刻を復元したという意味ではありません。

最後の FM バイトが記録の長さ内に消費できない入力は拒否します。ネイティブのソロは共有ラッチと PSG 音源 3 のノイズ用クロックを保持し、FM3 が非選択ならタイマーで発音する CSM キーオンもマスクします。テストは最後の DAC データの適用と実際の CSM 状態を調べ、FM3 を選択した場合も含めます。

![Sonic の変更前、修正後のネイティブ再生、独立参照](native-sonic-spectrograms.png)

時間をずらさず、RMS をそろえた最初の 10 秒です。スペクトログラムは FM 設定の欠落を見つけるのに役立ちました。音楽構造と音色の記述的な証拠であり、万能な忠実度の百分率ではありません。

<a id="reproduce"></a>
## 再現

出典付き素材の取得、固定したエミュレータービルド、キャプチャーコマンドは[原典の手順](../../scores/arrangements/README_ja.md)にあります。固定参照は原典ファイル、初期化手順、移植抽出、論理コマンド、物理バスイベント、独立 PCM を別々に結び付けます。

```sh
pnpm --filter chipvoice build
node scores/test-capture-nsf.mjs
node packages/chipvoice/test/vgm-import.mjs
pnpm arrangements:check
node scores/arrangements/verify-native-songs.mjs
node scores/arrangements/verify-ym-native.mjs
pnpm arrangements:eval
node scores/arrangements/verify-publication.mjs
SITE=http://127.0.0.1:3074 node apps/web/test-native-songs.mjs
```

完全な音声を 2 回レンダリングし、ロスレスで公開します。ブラウザーテストではネイティブと参照の出力、元の DAC のソロ、最初に選択される機種、読み込み完了、モバイルのはみ出しを測定し、`.artifacts/native-songs/browser/` に画像と動画を保存します。ユーザーの機械は混雑しているため、所要時間を性能ベンチマークとはしません。

<a id="completed-checks"></a>
## 完了した検証

12 本の完全なミックスで、再レンダリングの一致、有限かつクリップのない PCM、原典・エンジン・参照のハッシュ、ロスレス FLAC の完全な長さを確認しました。スーパーファミコン版 3 曲は内部ミキサーのクランプが 0 です。SDK 単体テスト、本番 Web ビルド、英語・日本語 631 キーの監査も合格しました。

本番ビルドのブラウザーで測定した短い出力区間は次のとおりです。音が出ることの確認であり、音色スコアや同じ曲位置での音量比較ではありません。

| 曲 | Chipvoice RMS | 独立参照 RMS |
| --- | --- | --- |
| Mario | 0.02798 | 0.01362 |
| Zelda | 0.03180 | 0.02609 |
| Sonic | 0.05206 | 0.03615 |

Sonic の元の DAC ソロは worker でレンダリングし、RMS 0.04953 を測定しました。3 曲とも元のハードウェアを選び、ソロでは全曲参照の A/B を無効にします。モバイル幅 320/390/768 と日本語の 390/1280 で横はみ出しはなく、未処理のページエラーもありません。シーク、一時停止、先頭への復帰、曲末、ループ、機種・テンポの連続変更も合格し、映像と可聴クロックの観測された最大差は 12.39 ms でした。単一のブラウザー実行結果であり、普遍的な遅延上限ではありません。

確認した画像：[Sonic デスクトップ](native-sonic-desktop.png)、[日本語モバイル](native-sonic-mobile-ja.png)。スペクトログラムのネイティブ区間は、最終 FLAC の最初の 10 秒とサンプル単位でも一致します。

<a id="limits"></a>
## 限界

Sonic の図では Chipvoice 側、特に 8–10 kHz 付近に追加の高域成分が見られます。現状の出力段は多重化された DAC ピンを出力サンプルごとに平均します。最終出力の一致を主張する前に、分離した参照キャプチャーでリサンプリングの折り返し成分、フィルター、PSG のバランスを切り分ける必要があります。この図だけでは残る差の原因は確定できません。

GME は独自のフィルターとリサンプラーを使います。ネイティブコマンドやデジタル出力が一致しても最終 PCM のビット一致や実機の忠実度測定にはなりません。PSG 精度とアナログバランスには適合性検証の限界が残ります。他機種版やテンポ変更・移調は観測した音楽データを使い、FM エンベロープ、ステレオ、余韻、DAC ドラムの種類の復元は不完全です。移植用 DAC バーストは汎用打楽器に割り当てます。元のサンプルを保持するのはメガドライブのネイティブ再生とネイティブのソロです。
