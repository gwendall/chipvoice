## Change and acceptance

A real chat response announced an eight-bar, six-part piece matching the inline skill example. It showed intent, not proof of copied output. Skill 0.13.0 separates original composition, full audio delivery and authorized publication. The musical fixture is optional; the main executable renders the agent's own project. Requests for shorter loops remain valid. Publication still requires user intent and credentials, and local composition continues during owner pairing.

## Executable checks

The production build passed. `test-agent-guide.mjs` fetched the optional example and ran the exact served rendering helper on every discovered target. WAV bytes matched direct SDK rendering. A 48-second duration fixture verified full output beyond the server preview limit; this repeated technical fixture is not an example of musical development. Strict voice exhaustion remained an error. The served HTTP recipe published to a disposable local database and downloaded pinned WAV and tagged MP3. Browser playback was audible to the signal probe (RMS 0.05246), without JavaScript errors or mobile horizontal overflow. Desktop/mobile screenshots were inspected. English/Japanese documentation navigation and heading checks passed.

Local evidence: `.artifacts/agent-guide/` (audio, reports, browser screenshots). No SDK or DSP changes. The bundled Codex skill validator rejected the web skill's pre-existing `compatibility` and `homepage` fields; its narrower frontmatter whitelist is not a validator for this HTTP skill format. Those fields were preserved.

## Independent composition trial

A separate agent received only the revised skill, the request “crée moi une chanson via le skill Chipvoice”, local SDK/capability access and an isolated temporary workspace. Publication, account actions, listening tools and chat uploads were unavailable. It authored **Les toits après la pluie**, 32 bars at 128 BPM, 60 seconds on NES, with four parts and an introduction, theme, bridge, developed return and cadence. It did not load the musical example or implementation source.

| Observation | Result |
| --- | --- |
| Source / rendered notes | 599 / 599; strict allocation |
| Measured audio | Entire 60 seconds at 44,100 Hz |
| Peak / RMS | 0.235754 / 0.046789 |
| Clipped samples | 0 |
| Repeat render | Identical WAV bytes |
| Delivered local artifacts | Project, evaluation, WAV and MP3 |

The agent shortened and spaced bridge bass notes after inspecting triangle volume limitations. It retained palette, percussion-effect, timing and mix diagnostics. It explicitly disclosed that it had not listened and could not attach files in this trial. Files exist, but this does not qualify remote chat attachment delivery or subjective musical quality.

Three additional decision-only scenarios respected a requested 10-second loop, used pairing while continuing composition for an authorized page request without credentials, and requested publication authorization before obtaining full server audio in an HTTP-only environment. These were reasoning probes, not executed authentication tests. Existing artist lifecycle tests cover the real pairing API.

Local trial evidence: `.artifacts/song-delivery/trial/`. WAV SHA-256: `a93af4fc918575d0da2aab6c1ccf0f07f2731124e55a8ea792686cb0c3087b72`. This single independent trial is useful behavioral evidence, not a guarantee that every agent will follow the skill or compose well.
