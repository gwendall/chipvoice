## Findings and changes

| Frequency / path | Finding | Correction |
| --- | --- | --- |
| Every output sample, GB/MD/SNES | `end()` constructed a two-element stereo tuple, immediately destructured and discarded | Each core supplies its own reusable double-precision tuple; numeric operations remain in the same order |
| Every enabled Game Boy wave output | Lookup table literal inside `Wave.output()` | One module-level lookup table |
| NES/GB length clocks and NES enable writes | Temporary arrays of channel references | Stable GB channel list and direct NES channel access; reset semantics preserved |
| C64 oscillator clock | Array destructuring/iteration on the per-cycle path | Direct indexed access |
| Every musical frame, MD/SNES encoders | Register-writer closures recreated in the frame loop; MD frequency conversion returned a temporary object | Writers scoped once per note; FM pitch returned as its packed register word |
| Every BRR candidate search | Up to 52 candidate arrays per 16-sample block, plus winner objects | Two call-local candidate/winner buffers swapped on improvement; scalar winner state |
| Every MP3 frame | Redundant copy of already-owned lamejs output; full-block typed-array views recreated | Retain owned encoder output, reuse PCM buffers directly for full blocks, only view the final partial block; no right PCM buffer for mono |
| Every UI poll | Fresh position object, filtered/mapped voice arrays, JSON serialization, and closure-based availability checks | Optional caller-owned position storage, scalar/voice-mask comparison, new React snapshots only when state changes |
| Every sequencer pump | Constructed a position snapshot only to discard it | Timeline expiry uses an internal reader without creating a public snapshot |
| Every playhead/ownership update | Retokenized score, recalculated pitches/geometry and recreated note styles | Geometry memoized by pattern identity |
| Scope animation / idle page | Per-frame callback closures; animation before any audio node existed | Indexed drawing loop; scope draws its initial flat line once; UI polling begins when an output node exists |

These describe source-level construction sites and ownership, not measured GC
counts: a JIT may already eliminate some short-lived objects. At 44.1 kHz the
old stereo construction site was reached 44,100 times per rendered second per
stereo core. The new core path passes one persistent tuple. No dependency or
global mutable scratch pool was introduced.

## Ownership and deliberate limits

- Scratch storage belongs to a core, one encoder invocation, or the caller.
  Independent chips and encodes cannot overwrite each other's scratch results.
- `Chip.position()` still returns an independent snapshot by default. Passing
  `position(into)` opts into reuse; null leaves `into` untouched. React receives
  fresh state snapshots when values change, never the mutable polling buffer.
- Output stages preserve their default snapshot-returning behavior. Scratch
  tuples use JavaScript numbers, avoiding premature Float32 rounding.
- Register events and musical frames retained for later scheduling/restoration
  remain independent records. Recycling them before consumption would corrupt
  future writes. The external/custom driver ownership contract is unchanged.
- Offline `subarray()` calls are zero-copy views into final PCM output, at block
  frequency. Replacing them with a scratch buffer and a PCM copy would add data
  movement. Initialization/reset allocations and diagnostic trace buffers are
  separate from continuous audio rendering.
- Local numeric variables remain local. Moving every `const` out of a loop is
  not evidence of lower heap pressure and can obscure ownership or arithmetic.
- The scope and polling loop stay active after audio starts so previews and
  effects work with music stopped. Animation cleanup is separate from disposal
  of the chip/context, preserving repeated machine switching.

The MP3 ownership check used the installed, locked lamejs source: `encodeBuffer`
and `flush` return a new `Int8Array` copied from their internal buffer. Its type
declarations currently say `Uint8Array`; concatenation accepts both correctly.

## Qualification

- Production build and typechecking passed.
- Complete unit suite passed, including five unchanged song goldens and
  block-size/Stop/effect regressions. The final C64 indexed-access cleanup was
  additionally checked with its digital tests and unchanged song golden.
- New hot-path tests verify scratch/snapshot equivalence and independence,
  caller-owned position storage without timeline aliasing, expiry without a
  position reader, and ten pre-refactor BRR hashes (empty/partial/multiple
  blocks, extreme PCM values, deterministic noise, loop/no-loop).
- MP3 output compared byte for byte with a separately bundled `f654876` encoder:
  mono/stereo, full and partial MPEG blocks all matched.
- Production API and Chromium desktop/touch-emulated browser journeys passed
  locally: all five machines make measured sound, Stop remains silent, effects,
  switching, editing, sharing, recovery and copied code work; the stereo WAV
  remains byte-identical to the library render. The complete five-corpus/ROM/
  mixer checks remain part of the PR's current-revision CI. Browser screenshots,
  videos, live audio measurements and exported WAV are written to
  `.artifacts/demo/` by the existing test harness.
- Desktop/mobile screenshots and an extracted desktop video frame were
  inspected after the geometry/polling change: note placement, playhead,
  machine controls and the horizontally scrollable editor remain intact.

The user's host is heavily loaded. This audit does not assert a numerical
latency/CPU improvement or a globally allocation-free application. Representative
device CPU/GC profiling remains necessary to quantify the effect. The changes
remove specific avoidable construction/copy sites while preserving behavior.
