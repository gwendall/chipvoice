# 作成者フローの検証 — 2026-09-08

<p align="center"><a href="CREATOR-JOURNEY-2026-09-08.md">English</a> &bull; <a href="CREATOR-JOURNEY-2026-09-08_ja.md">日本語</a></p>

模擬プロバイダーによるローカルE2Eは合格しました。別の実Astra試験では60秒・4パートの曲と復号可能なMP3を生成しました。本番デプロイの証跡は[PR #50](https://github.com/gwendall/chipvoice/pull/50)に記録します。ローカルの成功だけでは本番を保証しません。

<a id="coverage"></a>
## 対象範囲

| シナリオ | 確認内容 |
| --- | --- |
| 発見 | 配信された`/skill.md`、OpenAPI、依存不要の`/skill/compose.mjs`を取得 |
| アーティスト認可 | 所有者が`/connect`で要求を確認し、アーティストを選択・命名して権限を認可 |
| エージェントの独立性 | 子プロセスに配信クライアント、限定トークン、音楽入力だけを渡す。リポジトリや所有者・DB・モデル認証情報は渡さない |
| プロンプト作曲 | 生成、進行確認、全曲MP3取得、同じディレクトリーでの再実行による曲ID一致 |
| 直接作曲 | 同じクライアントで完成した楽譜を投稿、公開、MP3取得 |
| 作者表示 | API、ライブラリー、曲ページ、プロフィールが選択した作者を表示 |
| 作成方法 | ギャラリーのグループ化後も生成・直接のラベルを区別。編集した子孫も由来を保持し、クライアントによる偽装を拒否 |
| 共有 | 非公開・公開・限定公開を切り替えても曲と音声を保持。匿名での非公開音声取得や別アーティストの公開を拒否 |
| ブラウザー | モバイル・デスクトップ画像、再生、MP3復号、ページエラーなし、英日ラベル、横はみ出しなし |
| 作曲UI | 進行表示、再読み込みからの復元、選択した作者、ライブラリーリンク、編集下書きの維持 |
| 異常系 | 併用する生成テストで拒否、不正出力、エラー、中止、権限失効、同時実行、上限、冪等性競合を確認 |

<a id="reproduce"></a>
## 再現方法

```bash
pnpm --filter chipvoice-web build
cd apps/web
node test-generation.mjs
node test-creator-journey.mjs
```

ローカルは使い捨てSQLiteと模擬HTTPモデルを利用し、OpenAI料金は不要です。証跡は`.artifacts/creator-journey/local-*/`に保存します。

明示的な本番モードには`CHIPVOICE_EVAL_PRODUCTION=1`、`CHIPVOICE_EVAL_SITE=https://chipvoice.dev`とGit対象外の環境ファイルから非表示で読み込むDB認証情報が必要です。有料モデルを2回呼び、試験用と明示した曲を一時公開します。制御側が専用所有者を用意し、その後の認可は本物のブラウザーで行います。最後にその所有者の試験曲を取り下げ、認証情報を失効させます。既存の作者や曲は変更しません。証跡は`.artifacts/creator-journey/production-*/`です。

<a id="limits"></a>
## 限界

この試験ではメール配信と外部チャットサービスへの添付は行いません。エージェントは実際にローカルMP3を取得し、自身のチャットツールで添付できます。専用所有者の準備は、エージェントが所有者認可を迂回できることを意味しません。「直接作曲」はChipvoiceへの投稿方法を示し、人間だけによる作曲を証明しません。API・ブラウザー・復号試験だけでは音楽の好み、プロンプトへの忠実性、実機への忠実性を保証できず、別途音楽・エミュレーター評価が必要です。

ローカルDBの競合試験では、別プロセスの読み取り・書き込み中にも処理が完了し、有料呼び出しが重複しないことを確認します。SQLiteは永続WALモードを使用し、拒否された単独文の後は接続を更新して保持されたスナップショットを解放します。リトライは明示的なBUSY系エラーだけを短時間に限定し、本番のlibsql接続には適用しません。
