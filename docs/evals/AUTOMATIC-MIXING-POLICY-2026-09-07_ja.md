<a id="development-evidence"></a>
## 開発用の検証結果

固定したゼルダの区間では、メガドライブのベースがメロディーより 4.89 dB 小さくなり、
NES のネイティブ再生の 5.50 dB に近づきました。修正前はベースが 6.42 dB 大きい状態でした。
和音は −29.80 dBFS で、NES ネイティブの −29.90 dBFS に近づきました。
このステム比較は本 SDK のネイティブコマンド再生を使い、独立した実機録音とのサンプル一致を示すものではありません。

![元音源、修正前、自動ミックスのステム音量の実測](automatic-mixing-zelda-levels.png)

従来の実装は FM ボイスに空きがあっても、明示した FM 和音パッチに PSG を割り当てていました。
楽器との互換性を役割の優先ボイスより先に考慮するよう修正しました。回帰テストは修正前に失敗し、
修正後に成功しています。ノイズのステムは NES より約 6.91 dB 小さいままです。移植先 PSG の
制御値が上限に達するため、`mix-headroom` で実現できない目標を明示します。
曲ごとのゲインで隠してはいません。メガドライブの出力修正には
[独立した参照実装との別の検証結果](AUTOMATIC-MIXING-FOUNDATIONS-2026-09-07_ja.md)があります。

最初の開発評価は 70 組の曲・コンソールを対象とします。固定した 3 シードについてメロディー、
ベース、打楽器が主役のケースとソロを生成し、ゼルダとソニックを加え、SDK の全 5 チップで検査しました。
各組で従来制御と自動ミックスを比較しています。音符の追跡と自動ミックスの PCM 完全再現が成功し、
対象区間では不正値、最終出力のクリッピング、観測した SNES 内部加算の飽和がありませんでした。
`development-evidence.json` に結果を保存し、全スペクトルと WAV は
`.artifacts/automatic-mixing/development/` に保持します。全入力への保証ではありません。

<a id="response-and-performance-checks"></a>
## 応答と性能の検査

90 個の標準音色・ボイスプロファイルは合成した楽器の測定に基づき、曲への係数合わせではありません。
グリッド外の独立したプローブは音高 54/78、長さ 0.25 秒、ベロシティ 32/64/96/127 からの制御値を使います。
この選択範囲での RMS 予測誤差の絶対最大値は NES 1.96 dB、ゲームボーイ 1.98 dB、メガドライブ 0.40 dB、
SNES 0.68 dB、C64 1.62 dB です。48 kHz の同様の結果は、そのレートの標準校正の認証ではありません。
同等の NES パルスボイスは検査条件で 0.01 dB 未満の差、FM1/FM6 の発音開始位置による差は最大 0.25 dB でした。

同一ホストでウォームアップ後に交互実行したベンチマークでは、2 秒の生成フィクスチャの自動計画は
0.19–0.39 ms、同じ割り当て器の従来制御は 0.12–0.23 ms でした。ゲーム用の単音フレーズは
0.006–0.021 ms でした。これはこのホストでのポリシーの追加コストを分離した結果で、
代表的なスマートフォン、コールドスタート、過去の SDK の測定ではありません。
生成した標準 JavaScript は約 190 kB、gzip で 37 kB です。Worklet で校正は実行しません。

テストはコピー・凍結された上限付きキャッシュ、逆応答、将来の音符に依存しないゲイン、
同時発音数の平滑化、主役の明示指定、入力の所有権、ハードウェアの無音、制限付きフレーズ準備も検査します。
SDK の全ユニットテストが成功し、MD 以外のゴールデンレンダリングは変わっていません。

<a id="acceptance-still-in-progress"></a>
## まだ進行中の受け入れ検証

ローカルの Musha Aleste MIDI、未使用曲による検証、ブラウザ、デプロイ、公開パッケージの確認は
別途追跡し、この開発結果だけで完了とは判断しません。`scores/mixing/listening.mjs` は
RMS を合わせた 15 組のブラインド比較を作り、ローカルで観察を保存できます。
人間の好みの評価や実機のスマートフォン・Safari 測定を行ったとは主張しません。
RMS、スペクトル、過渡応答の要約は説明用の指標で、普遍的な音楽品質の点数ではありません。
