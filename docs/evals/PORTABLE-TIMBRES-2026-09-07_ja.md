# 移植用音色とドライな SNES — 0.16.3

<p align="center"><a href="PORTABLE-TIMBRES-2026-09-07.md">English</a> &bull; <a href="PORTABLE-TIMBRES-2026-09-07_ja.md">日本語</a></p>

報告された問題は、有限値・クリップなし・決定論的な出力という従来の検証では
検出できなかった編曲上の問題です。今回は測定可能な原因を修正しました。
これらの検証を、あらゆる音楽を評価できる審査員とみなすものではありません。

<a id="reproduced-failures"></a>
## 再現した問題

- 短い SNES リード音で、エコーは直接音より **9.84 dB 低いだけ**でした。
  遅い余韻も持続音に対して −28.30 dB あり、曲で指定していない空間効果が付いていました。
- Sonic の FM 和音は元のチップでは基音が約 **392 Hz** でしたが、移植は
  レジスターの基本周波数約 **98 Hz** を使用し、2 オクターブ低くなっていました。
- 同じ FM 音色のローカル ID を変えるだけで、NES・Game Boy・SNES の音が変わりました。
  ID を General MIDI の楽器番号と誤解釈していました。
- DAC 観測では連続する発音が結合され、すべての区間をキックにしていました。
  DAC の有効状態と、シークなしの最初の発音も正しく扱っていませんでした。

![元のパッチ、旧移植、修正した移植のスペクトル](portable-fm-pitch-comparison.png)

形を比較するため、各スペクトルを個別に正規化しています。音高の修正を示すもので、
音色の同一性や知覚上の音量一致を証明するものではありません。

<a id="corrections"></a>
## 修正

SNES の標準ドライバーはドライになりました。自動音量予算をドライ加算用の
120/128 とし、リリースと書き込みずれへの保護を維持します。生レジスターによる
ネイティブなエコー再生は DSP の全機能を保ちます。標準音色 90 プロファイルを
再校正しました。SNES のコンパクトスコアのゴールデン値はエコー除去に伴い更新し、
他のチップのゴールデン値は同一です。

FM の事前処理は異なる音色を 220 Hz と 440 Hz で測定し、安定した周期、音量変化、
大まかな移植先音色を求めます。`portableTimbres` が結果をプランナーへ渡し、
再生中に分析や追加レンダリングは行いません。古い元音色シグネチャーは拒否します。
パルス音では細い装飾的な波形より基音の明瞭さを優先し、表示にも測定した基音を使います。

Sonic では 25 音色の記述で 808 個の FM 音符区間を処理します。測定した音高差は
229 区間が −12 半音、181 区間が +12、291 区間が +24、107 区間が 0 です。
これは波形周期の推定であり、原作で意図された GM 楽器名の特定ではありません。

DAC はシーク位置と繰り返される 32 バイトの PCM 発音を使い、連結されたサンプルを
分離します。有効状態を追跡し、冗長な有効化を無視し、シークなしの先頭を保持し、
波形から打楽器の種類を推定します。Sonic は未分類の 141 区間から、**キック 96 回と
スネア 76 回**になりました。4/128 RMS 未満の静かな候補は別途記録します。
打楽器パターンを創作して埋める処理はありません。

<a id="validation"></a>
## 検証

- 実 PCM の回帰検証：測定した元の基音が NES・Game Boy・SNES の出力に現れます。
  音色 ID の変更に不変で、古い記述は拒否されます。
- 合成 DAC ケース：連結、シークなし、無効状態、冗長な有効化、無効化から再有効化。
- **開発用の完全な楽曲／機種 70 組**：音符台帳、再現性、有限値、SNES 内部飽和。
- **サイトの完全な編曲 12 件**と独立リファレンス 3 件。
  Mario・Zelda・Sonic のネイティブ録音はバイト単位で同一です。
- **試聴ラボの SNES 6 ケースを新規評価**し、全ループとステムを独立した S-DSP
  オラクルと比較しました。他の 24 ケースはコンパクトレンダラーとチップコアが同一のため、
  既存の証拠を保持します。各行に再評価か継承かの来歴を記録します。
- SDK 全ユニット／ゴールデン検証、校正の来歴、5 機種の音響条件、校正点外の検証、
  空の利用側プロジェクトへのインストール、Web 全体の検証。
- 対象を絞ったブラウザー検証：各 Sonic 移植の実ファイルハッシュ、音声出力、
  再生を維持した機種変更、デスクトップと日本語モバイルの画像・動画。

API と事前処理手順は[英語](../MIXING-API.md)と[日本語](../MIXING-API_ja.md)にあります。
生の検証結果、スペクトル、時刻を揃えた 7 組の比較試聴は `.artifacts/timbre-review/` に保存し、
配布用の証拠をリリースに添付します。比較は固定ゲインで RMS を合わせ、動的圧縮はしません。
比較素材を準備したことは、人が評価したことを意味しません。

<a id="independent-review"></a>
## 独立レビュー

**規約面：** DAC の境界・状態に関する 2 件を検出し、合成回帰検証とともに修正しました。
追加の規約違反や音声ホットパスの退行は見つかりませんでした。

**仕様面：** 同じ 2 件と、有効化の冪等性を確認しました。追試で修正と実 PCM 検証を確認し、
明示した分析範囲内で追加の具体的な不具合は見つかりませんでした。

<a id="remaining-limits"></a>
## 残る制限

測定は調和的な音色の 2 音高と 0.8 秒の音量区間です。非調和 FM、キースケーリング、
その後の音量変化、完全なリリース、ステレオ、原作サンプルバンクには、より豊かなモデルが必要です。
確信度が低い測定は音楽的な音高の証明になりません。移植先の音色は近似であり、NES と
Game Boy は音声数の制約から Sonic の低優先度音符 410 個を省略します。

人による統制された比較試聴と物理的なモバイル端末の確認は別の検証です。
0.16.2 の保留評価は過去の記録で、今回は未知の音色ベンチマークとして再利用しません。
