# アーティスト機能の評価 — 2026-09-08

<p align="center"><a href="ARTIST-LIFECYCLE-2026-09-08.md">English</a> &bull; <a href="ARTIST-LIFECYCLE-2026-09-08_ja.md">日本語</a></p>

対象は[アーティストとエージェント](../ARTISTS-AND-AGENTS_ja.md)です。SDK/DSP は 0.17.0 のままです。本番ビルドの Next、使い捨て SQLite アカウント、オリジナル曲で評価し、実メールを送らず本番の作品も作成しません。

<a id="results"></a>
## 結果

30 本の web 検証スクリプトが成功しました。参照音声のハッシュ、旧アカウントの移行、多声作曲、ネイティブ曲の再生、途切れないトランスポート、MIDI インポート、英語・日本語のモバイル画面を含みます。最後の排他制御と実行例の修正後、公開とエージェントの重点テストを再実行しました。

新しいブラウザシナリオでは `/connect` からエージェントを承認し、ユーザー名とピクセルアバターを変更し、同じ曲を 2 回評価します。コンソール別に公開し、MP3 をダウンロード・デコードし、古い WAV から変換した後にアクセスを取り消します。期限切れ・読み取り専用トークン、拒否、使用済み認証要求、異なるオリジンからの承認、所有者セッションの要件、非公開アーティストの分離、旧 API への迂回、所有者のお気に入り、処理の競合、MP3 キャンセル、有効なアクセスと履歴を検証します。

| 測定 | 結果 |
| --- | --- |
| HTTP 評価ソース | オリジナルの Super Famicom 2 秒フィクスチャ、元の音符 17 / 割り当て後 17 |
| 評価の繰り返し | ミックスと損失台帳を含めて同一 |
| 評価音声 | 44100 Hz、RMS 0.04307、ピーク 0.13374、クリップ 0 |
| 公開音声 | Famicom への移植、ステレオ WAV、352844 バイト |
| ブラウザでデコードした MP3 | ステレオ、コーデックの余白を含め 2.03755 秒、RMS 0.03659、ピーク 0.20888 |
| MP3 変換後の元 WAV | 全バイトを保持 |
| モバイル | 390 ピクセル幅で認証、作品、日本語ライブラリが横にはみ出さない |
| 翻訳チェック | UI キー 979 個、文書の対訳とアンカーを検証 |

異なる機種のレンダーです。Super Famicom の測定値は Famicom MP3 との **忠実度の A/B スコアではありません**。短いフィクスチャはサービス仕様と音声処理の確認用であり、全曲の美しさ、原作の音色、オーケストラのリアリティを保証しません。冒頭がきれいに鳴っていても全体の割り当て損失を明示します。

<a id="independent-review"></a>
## 独立レビュー

規約レビューでは管理者キーの判定順、標準プロフィールを作る際の上限、MP3 キャンセルの問題を発見しました。仕様レビューでは古いコンソール版の優先、MP3 キャンセル、取り消した履歴に埋もれる有効なアクセスを指摘しました。すべて修正し、再レビューで確認しました。ワーカーの締め切りにも修正を加え、時計を進める回帰テストを追加しました。処理枠の固定キーを明示することで、競合時は SQLite CHECK エラーでなく再試行可能な応答になります。

<a id="reproduce-and-inspect"></a>
## 再現と確認

`pnpm --filter chipvoice-web build` の後に `pnpm --filter chipvoice-web test` を実行します。公開 skill の JavaScript を全対応機種で実行し、Bash の例では WAV とタグ付き MP3 を取得します。ソース、画像、レポートに永続認証情報は含めず、コミットの秘密情報スキャンも成功しました。

`test-artists.mjs` は `.artifacts/artist-lifecycle/` に `report.json`、`full.wav`、`full.mp3`、`connect-mobile.png`、`song-mobile.png`、`library-ja-mobile.png`、`library-desktop.png` を出力します。CI でも評価資料として保存します。ライブラリのスクリーンショットは読み込み中ではなく、曲のカードが表示されてから確認しました。
