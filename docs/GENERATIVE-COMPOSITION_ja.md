# 生成による作曲

<p align="center"><a href="GENERATIVE-COMPOSITION.md">English</a> &bull; <a href="GENERATIVE-COMPOSITION_ja.md">日本語</a></p>

**状態：サーバー統合、プロンプトUI、エージェント配信を実装し、最初の実Astra試行に成功（2026-09-08）。** デプロイ検証と実環境の証跡は[PR #50](https://github.com/gwendall/chipvoice/pull/50)に記録します。通常の曲ホスティングを再利用します。

<a id="product-decision"></a>
## 製品方針

曲のホスティングは既にあります。追加するのは**プロンプト → モデル → 通常の`MusicProject`**だけです。既存のアーティスト、非公開保存、レンダージョブ、WAV/MP3保存、曲ページ、エディター、明示的共有を再利用します。プロンプトは所有者限定で、作成方法とモデル名は閲覧可能な曲に表示します。これらは音楽ソースのハッシュ外に置きます。別ギャラリー、音声保存先、楽譜形式、アカウント、スケジューラーは追加しません。

初期アダプターはOpenAI Responses API経由でGPT-6 Astraを呼びます。設定はサーバー環境変数です。プロバイダーのインターフェースは`generate`メソッド1つで、別プロバイダーでもプロジェクト保存や軽量SDKは変更不要です。実装済みはOpenAIのみで、全モデルへの互換性は保証しません。

<a id="implemented-contract"></a>
## 実装済みの契約

設定、例、正確な上限、評価の再現方法は[ローカルでのプロンプト作曲](LOCAL-COMPOSITION_ja.md)を参照してください。生成OpenAPIと`/skill.md`は設定済みサーバーのAPIを説明します。

| ルート | 動作 |
| --- | --- |
| `POST /api/v1/generations` | 認証付きプロンプト、機能一覧のターゲット、10〜90秒、ループ意図、任意の所有アーティスト。冪等キー必須 |
| `GET /api/v1/generations/{id}` | 認可された進捗、プロンプト・モデル、利用量、評価、通常プロジェクトとレンダーへの参照。ポーリングで処理を進める |
| `DELETE /api/v1/generations/{id}` | 未完了の作曲とレンダリングを中止 |

所有者は既存の認証情報を使います。エージェントには`generate`、`projects:write`、`render`が必要で、権限は自動追加しません。モデルは1回で厳格な構造化音符、名前付きパート、楽器、強弱を返します。サーバーは通常の`Performance`へ変換し、`allowLoss:false`で全割り当てを検証、冒頭2秒を評価、指定した公開範囲（既定は非公開）で保存し、既存の全曲レンダーを実行します。モデルによる自動修正はありません。公開には明示的指定が必要です。既存プロジェクトへのPATCHで楽譜と音声をコピーせず公開範囲を変更できます。

同じ再送は失敗後も同じジョブを使います。同時リクエストでも同一ジョブは二重送信されません。中断して結果不明なら自動課金の再試行ではなく失敗扱いです。日次受付、同時実行、応答・トークン・音符上限、中止、権限失効、期限で処理を制限します。金額の会計システムではないため、共有環境の前にプロバイダー予算を設定してください。ポーリングとコールバックは既存レンダーと同じ協調実行の制限があります。

<a id="evidence-and-limits"></a>
## 証跡と限界

模擬HTTPプロバイダーのE2Eは実アダプターのリクエスト、厳格検証、同時再送、通常DBとレンダー保存、WAV/MP3、ブラウザー再生、所有者限定プロンプト、画面画像、上限、ワーカー使用中からの再開、中止、権限失効、プロバイダー失敗を検証します。CIはモデル料金を使いません。

任意の実評価では設定済みモデルに1回リクエストし、編集可能ソースと全音声を保存、全PCMの測定とMP3復号を行います。実Astraのローカル試行では「Starwake Courier」を生成しました。60秒、4パート、完全なステレオMP3、PCMクリッピングなしです。統合フィクスチャはモデル互換性や音楽の良さを証明しません。

`ready`はソース検証と全曲レンダーの成功です。HTTP音響レポートは冒頭2秒だけで、全曲バランス、展開、依頼への適合、原作の忠実性、滑らかなループを認証しません。モデルが無効または説得力のない音楽を返す場合もあります。エージェント向け文書とUIでもこの限界を明記します。

<a id="delivery-order"></a>
## 実施順序

以前のチケットIDを維持しつつ、受け入れ範囲を簡略化します。

| チケット | 状態と次の作業 |
| --- | --- |
| GEN-02、GEN-06〜08 | ローカルアダプター、通常保存、上限付き実行、3ルート実装済み。最初の実Astraローカル試行に成功 |
| GEN-01、GEN-05 | 最初の実出力後、少数の多様なオリジナル依頼を比較し、遅延と利用量を記録、全曲試聴。必要に応じてベンチマークを拡大 |
| GEN-03 | 共通評価に全曲音響チェックを追加。後半のクリッピング、無音、終わりを扱い、音楽的判断は分離 |
| GEN-04 | 保留。実測の失敗が必要性を示した場合のみ、候補ソースと費用を追跡した上限付き修正を追加 |
| GEN-09 | 実装済み。`/create`にプロンプト、作者・長さ、進捗・再読み込み・中止、下書き保持、保存曲へのリンク |
| GEN-10 | skill/OpenAPIと取得可能クライアントを実装。一連評価でエージェント・API・ブラウザーを扱い、広い予算・音楽評価は別途実施 |
| GEN-11〜12 | 後続。既存の派生関係とソース同一性を用いた不変の部分修正と評価済み機種別版 |
| GEN-13 | 実際の音楽と運用評価後に一般公開。フィクスチャ成功だけで有料推論を公開しない |

[作成者の一連評価](evals/CREATOR-JOURNEY-2026-09-08_ja.md)で作者、作成方法、公開範囲、全MP3取得を検証します。直接投稿は使用経路の記録であり、人間だけによる作曲の証明ではありません。エミュレーターの忠実性と決定的な機種適応は、この任意の作曲レイヤーから独立して進めます。
