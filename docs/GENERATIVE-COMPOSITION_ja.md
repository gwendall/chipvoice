# 生成による作曲

<p align="center"><a href="GENERATIVE-COMPOSITION.md">English</a> &bull; <a href="GENERATIVE-COMPOSITION_ja.md">日本語</a></p>

**状態：2026-09-08時点の提案仕様。この文書によって生成エンドポイントやホスト型モデルが実装されたわけではありません。** 今回の依頼は仕様作成です。実装、モデル選定、一般公開は別の段階です。以下の数値上限は検証対象となる初期の製品判断であり、測定済みの処理能力やプロバイダー料金ではありません。

<a id="product-decision"></a>
## 製品の方針

人またはエージェントが音楽のプロンプトを送り、編集可能な`MusicProject`、曲全体のWAV/MP3、限界を明示した評価レポートを含むオリジナルのインスト曲を受け取ります。モデルは音楽構造を書き、既存のChipvoiceエミュレーターが演奏します。音符、独立したパート、機種別の移植が製品の中心なので、録音だけでは不十分です。

まず内部プロトタイプで音楽的な有用性を評価し、その後`/create`で認証付きの非公開ベータを提供します。ホスト型推論を軽量な`chipvoice`パッケージに入れません。既存のローカル作成、エージェント自身が書くプロジェクト、匿名試聴はこの機能から独立しています。実機への忠実性改善も生成機能に依存させません。

初版では検出した一機種向けに一曲全体を生成します。長さ、ループ意図、構造化ソース、完全な音声、取消、復旧、評価、明示的な公開を含みます。会話による修正と評価済みの機種別バージョンは後続です。歌声、歌詞合成、音声アップロードや採譜、モデル学習、自動一般公開、マーケットプレイスは対象外です。

<a id="user-experience"></a>
## 利用体験

`/create`の既存手動作成に**曲を説明する**入口を追加します。サイトのコンパクトなレトロ部品を使い、英語・日本語のUIとメタデータを揃えます。プロンプトはユーザーの言語で受け付けます。プロンプト欄、機能カタログ由来の機種選択、長さのスライダーと数値入力、ループ切替を表示します。既定は60秒、範囲は10〜90秒です。送信前に機種を必ず表示し、編集中の機種または設定された対応既定機種を使います。リクエストごとに隠れた機種を推測しません。

送信前に、プロンプトをホスト型モデルへ渡すことと利用枠を示します。未ログインでも入力でき、入力を失わずログインできます。ベータは有効化された所有者アカウントが必要で、エージェントにメールアカウントを作らせません。容量や設定が不足する場合は生成できない理由を示します。

送信後は実際の段階、経過時間、取消を表示します。モデル処理は完了率が不明なのでスピナーを使い、数値進捗は計測できるレンダリングだけに使います。待ち順を捏造しません。ページを閉じて開き直した場合は保存されたジョブを再開し、別の有料要求を送りません。

生成中も現在の曲を再生し続けます。完成後に**聴く**、**エディターで開く**、**ダウンロード**、**公開**を提示します。ユーザーが結果を選ぶまで未保存の編集や再生音を置き換えません。結果を開くとローカル編集用コピーを作り、生成済みソースと音声は不変に保ちます。サーバー保存が七日間であることを説明し、JSONをダウンロード可能にします。失敗しても現在のプロジェクトを残し、対処可能な理由を表示します。

結果にはタイトル、実際の長さ、機種、短い音楽説明、重要な移植上の注意、評価範囲を示します。詳細診断は展開パネルに置きます。生成曲は既存の公開操作を別途実行するまで非公開です。ループは一周期全体を書き出し、通常曲はプレビュー切断ではなく意図的な終止を持ちます。再生にはブラウザーの操作要件を守ります。

<a id="generation-pipeline"></a>
## 生成処理

1. 認証、検証、受付を原子的に実施します。対象能力、モデル、プロンプト、コンパイラー、エンジン方針を固定し、予算を予約してジョブを保存してからモデルを呼びます。
2. モデルにオリジナルの方針と構造化作曲データを求めます。テンポ、調性の意図、セクション、動機、パート、音符、強弱を含めます。例を繰り返して時間を埋めず、音楽を展開します。必須の六パートではなく、曲と機種に合う編成にします。
3. 切り離した`Performance`ソースの`MusicProject`へ変換・検証します。所有権と安全なメタデータ既定値はサーバーが決めます。モデルは公開許可、アカウント変更、ツール選択をできません。生成JavaScriptをサーバーで実行しません。
4. 既存プランナーで曲全体を準備します。無効な音符・時刻、利用できない機種資源、主対象の音符欠落を拒否します。主結果は`allowLoss:false`で受理します。音色代替とミックス限界は明示し、厳密な割り当てを忠実性の証明としません。
5. 上限付きWorkerで曲全体を生成・計測します。候補を非公開で保存し、冒頭だけで成功と判断しません。
6. 修正可能な技術失敗や具体的な音楽診断があれば、簡潔な構造化フィードバックで候補を修正します。各候補と理由を残します。初回後の修正は最大二回、全体の時間・費用予算内です。失敗を成功に変えるだけの`allowLoss:true`切替は禁止します。
7. 技術的に有効な候補を選び、完全なMP3を作り、非公開結果マニフェストを原子的に確定します。修正上限に達したら型付き失敗を返し、安全な診断・プロジェクトを未受理候補として明示できます。失敗候補を完成音声として公開しません。

直接の構造化`Performance`出力が安定するなら、まずそれを使います。試行でトークン量や整合性の明確な改善が確認された場合だけ、内部の`CompositionPlan`を導入します。導入するなら、バージョン付き動機、セクション配置、整数tick、上限付き反復、決定的展開を持つJSONとします。再帰、任意式、外部参照、新しい公開楽譜形式は不要です。音符を確保する前に展開上限を検証し、存在しない和声やベースをコンパイラーが勝手に追加しません。

公開要求にはプロバイダー固有のtemperature、システム指示、ツール設定を露出させません。当初は一つのプロバイダー実装と記録応答によるテスト実装を使い、比較で必要なら別の実プロバイダーを追加します。取消、構造化結果、利用量、型付き失敗を備えた小さな内部インターフェースにI/Oを置きます。この実装はDB、公開経路、無制限のツールにアクセスしません。

<a id="proposed-http-contract"></a>
## HTTP契約案

この節の経路はすべて**新規・未実装**です。出荷まで本番スキルやOpenAPIで利用可能として列挙しません。

```http
POST /api/v1/generations
Authorization: Bearer <authorized credential>
Idempotency-Key: <unique request revision>
Content-Type: application/json
```

```json
{
  "prompt": "A driving space-boss theme with a memorable answering melody",
  "target": "md",
  "durationSeconds": 60,
  "loop": false
}
```

`target`はカタログのID（例では`md`）を使い、別の別名表を作りません。プロンプトは前後空白除去後1〜2000 Unicodeコードポイント、長さは整数10〜90、loopの既定はfalseです。所有者は自分の`profileId`を指定でき、エージェントは承認されたアーティストに固定され、上書きできません。不明・未対応フィールドは拒否します。`visibility`や自動公開指定はありません。

202と`id`、`status`、`stage`、`statusUrl`、`createdAt`、`deadlineAt`、`expiresAt:null`を返します。終端状態になってから七日後を成果物期限とし、確認間隔に`Retry-After`を使います。同一要求の再試行には同じジョブを返し、モデル呼出や予算予約を増やしません。キーは所有者単位です。同じキーでアーティスト、本文、改訂元を変えると409です。既定値を正規化してハッシュ化し、後から設定が変わっても初回に選んだ方針を保持します。

| 経路 | 契約 |
| --- | --- |
| `POST /api/v1/generations` | 非公開ジョブ一件を受付。意図的な新規試行には新しいキー |
| `GET /api/v1/generations` | 自分のアーティスト範囲の最近のジョブ。カーソルページング、一般検索には出さない |
| `GET /api/v1/generations/{id}` | 認証付き状態、段階、経過時間、試行、使用量、期限、結果 |
| `DELETE /api/v1/generations/{id}` | 待機・実行中を取消。取消済みなら現在状態を返し、ready/failed/expiredは409 |
| `GET /api/v1/generations/{id}/project` | 不変の受理済みプロジェクト。失敗時は明示した診断候補 |
| `GET /api/v1/generations/{id}/evaluation` | 計測範囲、候補履歴、限界を含む全レポート |
| `GET /api/v1/generations/{id}/audio?format=wav|mp3` | 受理済み完全音声だけ。毎回アクセス検証 |

完成マニフェストは`projectUrl`、`evaluationUrl`、`wavUrl`、`mp3Url`、`seconds`、`target`、ハッシュ、`expiresAt`を含みます。公開物ができるまで一般向けの曲・プロフィールURLはありません。ダウンロードはprivate/no-storeで、URLにBearerトークンを埋め込みません。チャットのエージェントは認証してバイト列を取得し、自分の添付ツールで送ります。

HTTPエラーは固定コードです。401は無効な認証、403は権限・ベータ資格不足、404はアクセスできないジョブ・アーティスト、409は冪等性・終端状態競合、410は自分の期限切れ成果物、413は本文超過、422は無効な入力、429は割当・容量不足で`Retry-After`付き、503は無効化・設定不足です。対象外の音楽依頼、プロバイダー拒否、無効な生成楽譜、修正上限、予算・時間上限、中断は受付後の型付きジョブ失敗として記録します。

公開には既存の`/api/v1/projects`、`projects:write`権限、明示的な公開範囲を使います。受理ソースを既存検証器に通し、出典を保ち、ユーザーが選ぶまでライセンスは`reserved`です。自動的にCC0にしません。公開音声は既存の公開処理で固定し、生成成果物の期限で公開物を壊しません。将来音声を再利用する場合は、クライアントのURLではなくプロジェクトとエンジンのハッシュを検証します。

<a id="state-execution-and-access"></a>
## 状態、実行、アクセス

ライフサイクルと説明用段階を分けます。状態は`queued`、`running`、`ready`、`failed`、`cancelled`、`expired`です。実行段階は`composing`、`validating`、`rendering`、`evaluating`、`repairing`、`encoding`です。候補変更で段階進捗は戻り得るので、偽の全体百分率にしません。`cancelRequestedAt`で取消処理中を示し、完了と混同しません。

DBの条件付き更新とリース付き実行世代で遷移を制御します。遅れて返ったWorkerやモデル応答は、取消済みジョブや別世代の候補を上書きできません。全成果物の保存後、現世代で取消されていないことを最終トランザクションで確認してreadyにします。可能ならモデル呼出を中断し、CPU処理を終了してからリースを解放します。既に消費したモデル処理には費用が発生し得るため、取消を返金保証としません。

モデル待ちで共有音声CPUリースを保持しません。ベータでは既存の音声同時実行上限を保ち、通常の生成・評価を飢餓状態にしない公平な受付を追加します。モデル呼出数は別に制限します。全体期限は待機、モデル、修正、レンダリングを含みます。待機中に期限を超えたらモデルを呼ばず終了します。

状態確認は読み取り専用で、モデルを呼ばず、唯一のスケジューラーにもなりません。内部プロトタイプは明示的なローカルrunnerで構いません。ホスト型ベータは永続キューと独立起動のrunner・復旧走査を必要とし、デプロイ方式を有効化前に検証します。現在のNext `after`だけで必ず実行されると仮定しません。呼出前に試行を記録します。曖昧なタイムアウトをプロバイダー側で安全に照合できなければ、`provider_outcome_unknown`で失敗させ、二重課金につながる再呼出ではなく予算予約を保持します。

非公開ジョブは所有者とアーティストに属します。`generate`をこのライフサイクルと内部評価・生成の明示的な権限として追加します。公開や外部のevaluate/render経路への権限は付与しません。既存トークンを無断で拡張しません。新たなモデル呼出やCPU段階の前に、期限、失効、アーティスト権限を再確認します。許可済みの実行中処理は完了し得ますが、後のアクセスには認証が必要です。人のセッションは同一オリジン検査を維持し、他アーティストのIDは404にします。

<a id="bounds-storage-and-provenance"></a>
## 上限、保存、来歴

初期ベータは招待された所有者だけに限定します。所有者ごとに実行一件、待機二件まで、一日十件まで受付し、モデル呼出は全体で同時二件までです。同じ所有者の全エージェント・プロフィールを合算し、DBで原子的に制限します。失敗・取消でも受付数を残して回避を防ぎ、同一再試行は二重計上しません。既存の生成以外の割当は別です。

全体期限600秒、修正・再試行込みモデル要求三回、各要求の出力16,000トークン、モデル・プロジェクト本文4 MB、展開後20,000音符、音楽90秒を上限とします。既存の生成240秒・40 MB上限は残り全体予算の内側に適用します。保存成果物の合計は40 MBまでとし、不採用候補の音声はハッシュと診断を残して削除します。合成前に過大な展開を拒否します。

ホスト型試行前に、プロバイダーの料金・会計方針のバージョンと、ジョブ単位・全体一日単位の有限な金額上限を設定します。未設定なら受付を無効にします。呼出前に保守的上限を予約し、実使用量で精算します。使用量不明なら照合まで予約を保ち、無料と仮定しません。プロトタイプで数値上限と費用・遅延のp50/p95を測定してからベータへ進みます。この仕様はプロバイダー、モデル、料金、請求条件を選びません。

非公開プロンプト、受理ソース、音声は完了後七日間保存し、実際の期限を返します。再起動後も期限内の待機・実行ジョブを復旧します。定期削除で期限切れバイト列、プロンプト、候補を消し、遅れた再試行で再生成・再課金せず410を返すため、最小限の冪等性・アクセス記録を終端状態から30日間保持します。この再試行記録期間を説明します。アカウント削除も同じ削除経路を使います。モデルに無関係な下書き、メール、トークン、他の曲を送りません。

要求、正規化した方針、モデル・プロバイダーバージョン、プロンプト方針、構造化応答、機能ハッシュ、コンパイラー、エンジン、候補ソース・音声ハッシュ、上限付き修正理由、実時間、使用量、計測範囲を記録します。生のプロンプト・応答は非公開で保存し、公開メタデータと通常ログから除きます。秘密はサーバー設定だけに置きます。CIは記録応答を使い、実モデル評価は明示的な上限付き運用作業にします。

同じ保存済みプロジェクト、検証済みエンジン、設定のレンダリングは再現可能です。自然言語要求の繰り返しは、モデルseedがあっても同じ作曲を保証しません。初期公開契約に誤解を招く決定的`seed`を設けません。後の改訂や機種変更では開始元ソースを正確に保存します。

<a id="evaluation-and-release-gates"></a>
## 評価と公開条件

三種類の証拠を分離します。スキーマと決定的PCMは必要ですが、良い音楽やゲーム固有の原音色を証明しません。

| 層 | 検査 | 効果 |
| --- | --- | --- |
| 必須技術条件 | 完全・有効なソース、主旋律と発音対象の全ソース音符の割り当て、有限PCM、フルスケール以上のサンプルなし、無音でない全体、PCM長さが指定±0.25秒以内、完全WAVとデコード可能なMP3 | 失敗ならready不可。修正または失敗 |
| 音楽診断 | 展開と反復、意図的休符、各パートの聞こえ方とマスキング、低音の密集、対比、終止・ループ接続、余韻 | 修正と試聴の証拠。万能な単一品質スコアではない |
| 人の盲検試聴 | 依頼との一致、記憶に残る展開、バランス、遷移、再び聴きたいか | 一般公開前に必須。LLM審査は任意の補助 |

全ミックス、独立パート、全セクションの短時間窓を計測します。PCM時間とMP3のエンコーダーパディングは分けます。閾値・バージョンはフィクスチャーで定義し、静かな導入、疎な編成、ドローン、意図的な不協和を自動失敗にしません。ループは末尾から先頭、通常曲はリリースと不意の切断を評価します。現行の二秒評価で検証済みと主張しません。音符欠落なしでも音色代替や機種のミックス制限はあり得るため、両方を報告します。

活発なテーマ、穏やかな曲、疎な編成、密な編曲、短いループ、展開する曲を含むオリジナル依頼12件を用意し、最初の候補で各三回生成します。追加八件はプロンプト調整から隔離します。同じ長さ・機種の保存済みエージェント作曲を基準に含めます。盲検では順序を無作為化し、好み比較用の試聴音量を揃え、技術検査用の生PCMも保持します。最低三人が代表的で偏りのない部分集合を評価し、平均だけでなく個別判断、不一致、範囲を記録します。コード完成後でも試聴で公開を止められます。

ベータ条件案は、すべてのready成果物の技術合格、ベンチマーク依頼の90%以上が上限内で完了、認証・取消・費用上限の回帰なしです。一般公開条件案は、未使用依頼への評価の70%以上が再作曲なしで使えること、どのカテゴリも50%未満でないこと、基準との好み比較・不確実性と費用・遅延p50/p95を報告することです。達成済み結果ではなく、プロトタイプ後に議論する目標です。失敗なら反復改善または非公開を維持します。

<a id="revisions-and-console-variants"></a>
## 改訂と機種別バージョン

初期ベータ後に、アクセス可能な受理生成物と「打楽器を減らす」「第二主題を展開する」などの指示を参照する、不変の改訂要求を追加します。意味的なプロジェクト差分を計算します。限定的な変更なら他の音符・セクション・設定を保ち、広範な再作曲が必要なら置換前に範囲を説明します。保存済み結果やエディター作業を無断で上書きしません。改訂も通常予算と新しい冪等性キーを使います。

他機種では、まず同じ標準ソースを対象設定で生成し、損失とミックスを確認します。ソースが同一の版は既存グループ化の対象になります。小さな機種向けに音符を変える必要があれば、元ソースと関連付けた別の縮約として保存し、同一ソース版と誤表示しません。要求された各機種で旋律保持と音色・ミックスの妥協を検証します。毎回全機種を生成する既定にはしません。

<a id="decisions-to-revisit-after-the-prototype"></a>
## プロトタイプ後に再検討する判断

構造化楽曲、非公開結果、全音声、明示公開、認証付きベータ、上限付き修正、軽量SDKは初期方針として固定します。実装が依頼されたら、GEN-01〜04開始のために追加のユーザー判断は不要です。

GEN-05でモデル・プロバイダーとデータ取扱方針、金額上限、許容遅延を実測に基づき決定します。GEN-13でベータ利用を踏まえ無料・有料枠と一般容量を決定します。GEN-07完了前に永続runnerのデプロイ方式を選んで試験する必要があります。仕様だけを作る今回の依頼は、契約、購入、一般公開を暗黙に許可しません。
