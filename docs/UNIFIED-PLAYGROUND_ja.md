# 1つのプレイグラウンドと曲全体の再生制御

<p align="center">
  <a href="UNIFIED-PLAYGROUND.md">English</a> &bull;
  <a href="UNIFIED-PLAYGROUND_ja.md">日本語</a>
</p>


2026-09-06のユーザー仕様。初回を旋律だけにする既定動作を置き換えます。

- `/`はMarioの完全なネイティブ・ファミコン編曲で開き、ZeldaとSonicも全原典パートを保持します。日本版機種マーク4つで、公開C64選択は置きません。固定4トラックを埋めるために和音、ベース、ドラムを創作しません。
- 曲、機種、パート分離、MIDI読込、テンポ、移調は同じ楽器の機能です。`/lab`には技術試聴を残し、`/lab/arrangements`はホームへ戻します。プレイヤーを開くのに音符ごとの証拠レポートは不要です。
- 再生／停止で位置を保ちます。先頭へ戻る、経過／全時間、アクセシブルな全曲シーク、楽譜クリックで全体を移動できます。ループを無効にでき、ネイティブループは初回以降イントロを飛ばします。
- 機種、テンポ、移調、ソロ変更は楽曲位置と再生意図を保ちます。新曲と読込ファイルは冒頭から。準備中は旧音を続け、最後の要求を優先し、一時停止は停止したままにします。
- カーソルはシーク、再開、録音置換後も、出力遅延を含め音声機器に従います。割当で省略した音を、鳴っているかのように点灯しません。装飾的なカーソル補間はしません。
- Make a loopで既存エディター、鍵盤、パッド、録音、Undo、コード、出力、共有を同じページへ出します。モード変更で一度に1楽器だけが鳴ります。下書きとhash／公開リンクの形式を保ち、作曲へ入ると下書きを復元し、共有hashは直接作曲へ入ります。
- JavaScript音源チップエミュレーションを即座に説明します。ネイティブMarioの命令検証と、MIDI採譜や機種間の音色を区別します。
- ローカルMIDIは選択をすぐ受け付け、準備と実レンダー進捗を報告し、エラーを保ち、MIDIをアップロードしません。
- 本番ビルドをE2Eで評価します。実出力RMS、音声時計とDOMカーソル、初回、停止／シーク／先頭／ループ／終了、機種／テンポ、作曲への引継ぎ、旧エディターと共有リンクの回帰、長いMIDI、PCと320／390／768 pxの画像・動画を含めます。

<a id="design-decisions"></a>
## 設計判断

完全編曲エンジンは多声の`Performance`、創作トラッカーは4役割の`SongDocument`を使います。損失を伴う相互変換は意図的にしません。見えるモード切替が発音権を管理します。作曲中も編曲セッションを停止状態でマウントしたままにして、読込と再生位置を保ちます。作曲のローカル下書きはアンマウントをまたいで残ります。

`BufferPlayback`がデコード、有界なソース重なり、クロスフェード、位相、シーク、終了、ループを持ちます。数値の時刻区間の有界な履歴で、まだ出力機器へ届いていない連続シークを扱い、古い音声ノードは保持しません。デコード済みキャッシュは最大8件です。

時計は`getOutputTimestamp()`を現在のアニメーションフレームへ外挿し、使えなければ報告されたbase／output遅延を使います。タイムスタンプは出力遅延を含むので、もう一度引いてはいけません。[MDNの契約](https://developer.mozilla.org/en-US/docs/Web/API/AudioContext/getOutputTimestamp)を参照。ブラウザー推定では未報告の外部スピーカー／Bluetooth遅延は認証できません。混雑する開発機から壁時計のレンダー性能を推定しません。

ビルド時の投影データで、機種別の省略も含む軽いカタログと静的音符ビューを作ります。workerの変種も同じ投影を出します。楽譜はサイズ／選択変更ごとに1回ラスタライズし、アニメーションはカーソル1本を動かし、各パートの音符区間を二分探索します。重い全証拠、原典の表情、ネイティブ命令列は必要時だけ読みます。
