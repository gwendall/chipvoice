# SNES音色パレットの反復改善

<p align="center">
  <a href="SNES-PALETTE.md">English</a> &bull;
  <a href="SNES-PALETTE_ja.md">日本語</a>
</p>


基準はmainの`c0ad640`、試聴証拠は`.artifacts/listening/current`です。ネイティブDSPと移植可能な楽譜形式を保ち、標準編曲を改善します。特定ゲームの楽器や、未測定の実機アナログ出力を再現する主張ではありません。

フェーズ1（`feat/snes-sampled-palette`）は基準1〜3、5、6を扱い、PR #24でマージ済みです。フェーズ2（`feat/snes-polyphonic-arrangement`）は評価済みパレットを使って基準4を実装します。

<a id="acceptance-criteria"></a>
## 受け入れ基準

1. 独自の旋律、和音、ベースのサンプル系統を用意し、作成したアタックと別個の決定的なBRR持続ループを持たせます。既存の名前付き波形は明示楽器で引き続き使えます。著作権のあるゲームバンクは取り込みません。
2. サンプルの調律メタデータをドライバーと音域診断で共有します。BRR符号化とループ後も保持音の音高が正しく、境界でアタックを繰り返したり、不連続のスパイクを作ったりしないこと。
3. 標準サンプルの生成／BRR符号化は初回再生時でなくビルド時に行います。ディレクトリとバンクを64 KBのSPC RAMのエコーバッファーより下に収めます。
4. 次の編曲改善で三和音に3声、拡張和音に最大5声を同時使用し、控えめな音量とステレオ配置にします。全割当声へStop、cut、seek、mute、captureの意味を適用し、他機種の音声はバイト一致を保ちます。
5. 毎回、実デモ3曲を役割分離でレンダーし、旧証拠と音量を揃えて比較します。ネイティブDSPと取得再生の完全一致、dry／echo入力の非飽和、有効なPCMを保ちます。既定ミックスだけでなく、保持音と全音色を調べます。
6. マージ前に仕様と規約でレビューし、客観結果と主観評価の限界を記録します。自動指標は人の好みを認証しません。

技術参照：[BRR samples](https://snes.nesdev.org/wiki/BRR_samples)、[S-DSP registers](https://snes.nesdev.org/wiki/S-DSP_registers)、[DSP envelopes](https://snes.nesdev.org/wiki/DSP_envelopes)。

<a id="phase-1-measurements"></a>
## フェーズ1の測定

初回パレットはネイティブ一致に合格しましたが、デモミックスで-24.8〜-27.8 LUFSと静かすぎました。原サンプルをビルド時にピーク調整し、マレット／ハープの持続部を上げると、2回目は-21.1〜-22.6 LUFSで、dry／echo入力の測定飽和は0でした。信号とバランスの観察であって、人の好みの判定ではありません。最終設定の旋律ビブラートは遅めの5 Hzです。

新RAM画像はディレクトリ込み21,472バイトで、57,344のエコーバッファーより下です。符号化はビルド時だけ。8楽器系統ごとに独立したBRRループアドレスを持ち、入口は予測器へ依存しません。アタック後のネイティブレート分離ループは完全反復し、110／440／880 Hzの保持音の誤差は自己相関推定で5セント未満です。

拡張で起動バグを発見しました。完全無音の楽譜が修正前はピーク0.183のPCMを出しました。エコー書込を止めるだけでは、DSP初期遅延中の読込がサンプルRAMへ回り込みました。今は遅延終了までエコー音量を0にし、同じ無音回帰が正確な無音を出します。ネイティブDSPの挙動は変えていません。

音色作成中は`scripts/snes-bank-source.ts`を編集後に再ビルドします（`pnpm --filter chipvoice build`）。通常の開発watchはこのビルド時レシピを監視せず、実行中デモは旧バンクを保つためです。

レビュー後、BRRデコード境界の傾きを、持続部への初回進入と次の2回の折返しで原PCMと比較しました。最悪境界誤差はサンプルピークの0.4%（上限1%）。故意に壊したBRR入口は3境界すべてで50%超となり拒否されます。周期性だけで不連続スパイクなしとは判断しません。

<a id="phase-2-measurements"></a>
## フェーズ2の測定

SNES和音はv1/v4/v5/v6/v7を使い、v0/v2/v3を旋律／ベース／打楽器へ残します。各音程に独立した音高とエンベロープを与え、振幅予算を均等に分け、控えめなステレオ配置にします。5音超は容量警告とともに全音程をアルペジオで保持します。他チップの編曲方針は不変です。

`.artifacts/listening/snes-polyphony-v1`の完全なデモ3ループは、最終フェーズ1に対し-22.92／-21.54／-22.90 LUFS（overworld／boss／midnight）。全3曲がネイティブS-DSPと完全一致し、レジスター取得を正確に再生し、観測したdry／echo入力の加算clampは0です。このカウンターはチップの全飽和段を覆うものではありません。

回帰は同時三和音と5音和音、容量フォールバック、ミュート行、和音バンク全体のcut／stop、保持和音内とcut後へのseek、和音内部の1声を効果音に貸す場合を含みます。最後は復元時の実DSP音高／エンベロープと停止後の無音を検査します。標準意図の全36組み合わせも5音和音でdry／echo入力の余裕を検査し、意図的な過負荷レジスターは同じ観測器で失敗する必要があります。SNESのゴールデンは同時和音、ステレオ、丸めた音量予算のため意図的に変更し、他4チップは固定します。

音楽面の残作業は明示します。望むスタイルやゲーム風音色を選び、音量を揃えた人の試聴メモを集めます。完全一致のネイティブ参照も信号検査も、その好みや未測定の実機アナログ出力を証明しません。

レビュー修正：時刻付き和音cutは独自`ChannelClaim`の所有権に従います。SNES音量はレジスター変換まで小数を保ち、振幅を分ける前に各和声音を4ビット整数へ量子化しません。静かな三和音と5音和音はgain 0.1でも聞こえ、0.2／0.3で増えます。従来チップのフレーム量子化は維持し、この2修正では既定SNESゴールデンは変わりません。

エンジン`377636b`の最終証拠は`.artifacts/listening/snes-polyphony-reviewed`。全15デモループが完全再生し、SNES3ループがネイティブ一致、全件で信号警告なし。非SNESの60ミックス／ステムWAVハッシュはパレット前と同一、SNESの18ミックス／ステム／ネイティブWAVはレビュー修正後も評価済みフェーズ2の既定値と一致します。レポートはビルド済みエンジンを後続の文書専用コミットとは別に識別します。`verification.json`に検査を記録し、PC／モバイルのA/B画像とブラウザー確認は`browser/`へ保存します。

<a id="phase-3-evaluation-protocol-declared-before-the-bank-changed-next-24"></a>
## フェーズ3の評価プロトコル（バンク変更前に宣言、NEXT-24）

NEXT-24は標準バンクのブラス、ストリングス、ピッキングベース、キック、スネア（実際の利用者が測定した弱点）を書き直し、S-DSPのエコーを無効な隠し定数から、公開文書化された`space`選択肢へ変えます。本節はバンクやドライバーを変更する前にコミットするため、以下のプローブ、指標、比較対象は新バンクが存在してそれに合わせて調整される前に固定します。後のコミットで「フェーズ3の測定」に実測値を追記しますが、本節自体は編集しません。

44.1 kHzでレンダーする5つのプローブ：
- 実デモ3曲（`apps/web/src/studio/presets.ts`の`overworld`／`boss`／`midnight`、基準5自身の参照集合）を、それぞれ`lead`役に分離（他の声部を休符にし、和音／ベース／打楽器と混ざらず単独で測定）。
- 持続和音プローブ：C4メジャートライアドを4秒間保持する単独の音。
- ドラムループプローブ：120 BPMで8拍ごとにキック／スネア／ハイハットを鳴らし、解放とエコーが現れる余地として2拍分の無音尾を付加。

各プローブは3系統でレンダーします：`2a03`（本チケットの影響を受けない対照）、本チケットの変更前に保存した`dist`ビルドによるmainブランチのバンクを積んだSNES、そして新バンクのSNES。S-DSPコア自体はNEXT-24で変更しないため、同一プローブでの2A03とSNESの差はチップエミュレーションの差ではなくバンク・編曲の効果です。新バンクのSNESレンダーは`space: "dry"`と`space: "room"`の2通りを取得します。下記のエコー指標は両者の比較としてのみ意味を持つためです。

`packages/conform/src/bench/fft.mjs`のFFTで計算する指標（すべてのスペクトル測定はアタックから100ms以上後、リリースから100ms以上前の4096サンプルHann窓を使用）：

| 指標 | 何を切り分けるか |
| --- | --- |
| スペクトルフラットネス | 2A03の矩形波／三角波は固定で狭い倍音の櫛状スペクトルですが、サンプル系の、デチューンされたアンサンブル音色は各倍音の周囲の多くのビンへエネルギーを広げ、フラットネスを上げます。 |
| 奇偶倍音バランス | 2A03の矩形波と三角波は奇数倍音が支配的ですが、帯域制限された非矩形のサンプル音色はそうなりません。 |
| スペクトル重心の移動 | 単一の反復BRRサイクルは、持続部内で200ms離れた2つの4096サンプル窓の間で動きませんが、複数パーシャルのデチューンされたアンサンブルループはうねり、重心が移動します。 |
| アタックトランジェントエネルギー | ノートオン直後30msのRMSエネルギーと、続く200msの持続部のRMSエネルギーの比（dB）。単一サイクル波形には独立したトランジェントがほとんどありませんが、作成されたアタック（ボウノイズ、ピック、ブレス）にはあります。 |
| エコーテールエネルギー | プローブ最後のノートオフから50ms後に始まる200ms窓のRMSエネルギー。クリーンな解放から無音への区間を持つ持続和音プローブとドラムループプローブのみで測定します。これは上記4つの音色指標ではなく、エコーの既定値を決める指標です。 |

後述の「フェーズ3の測定」は、最初の4指標について2A03対照／SNES main／SNES new（dry）を並べて報告し、エコーテールエネルギーについてはSNES new（room）を追加します。検証する主張は、新バンクが4つの音色指標で2A03対照から離れること、そして`space: "room"`がエコーテールエネルギーをdryの両方およびSNES mainより測定可能なほど上げることです。「測定可能」なしきい値は、5プローブ全体で実測したばらつきに明記したマージンを加えて、数値が出た後に定め、特定のプローブを通すために緩めることはしません。あるプローブが自分の指標に落ちた場合、修正はバンクかプローブ側で行い、理由をここに記録します。数値の方を動かしません。

ゼロショットの「どの機種か」分類チェックは任意であり、ここでは実行しません。本チケットには対照群がなく（同じプロンプトで未変更の2A03レンダーを「NES」と判定することを先に示さないチェックは証拠になりません）、これらの楽器を指摘した実際のkami利用者のブラインド試聴基準こそが真の受け入れテストであり、それはkami側で彼ら自身の鍵を使って実行します。本ブランチの鍵ではありません。NEXT-24の最終報告はその実行のための正確なコマンドと圧縮したtarballを示すのであって、そこから引用した結果ではありません。

**受け入れ基準6にもとづく誠実な読み方。** アタックトランジェントエネル
ギーとエコーテールエネルギーは、プロトコルが予測した方向で明確に分離す
る2指標です。アタックは書き直した両ブラスプローブでmainからnew dryへ4
〜6 dB跳ね上がり、2A03対照は終始1〜2 dB付近にとどまります（単一サイク
ルの矩形波は独立したトランジェントをほぼ持たないため）。エコーテールは
和音プローブで`room`がdryとmainより4〜5桁上に位置し、ドラムプローブで
はdryとmainに正確に一致します。`EON`が設計どおりキットボイス（v3）を
除外しているためです。スペクトルフラットネスと重心移動は2A03対照に対
して一貫した方向へ分離しませんでした。フラットネスは4プローブ中3つで
SNESバンク（mainもnewも）を対照より「フラットでない」と測定し、boss
だけ「よりフラット」と出ます。また重心移動の2スナップショット・200ms
間隔という測定方法は、これらの音高でのブラスアンサンブル自身のうなり
周期（E5のデモリードプローブでおよそ255ms、ブラスレシピの
`loopCycles`／`detuneCents`から)に近く、うなり周期のどこを捉えるか次
第で値が振れるため、「音色が時間とともに動くか」を安定して追えていま
せん。これは本バンクのこれらのプローブにおけるこの2指標の限界として
ここに記録するのであり（受け入れ基準6「自動指標は人の好みを認証しな
い」のとおり）、数値をよく見せるために指標やプローブを書き換えるので
はありません。上記プロトコルは`c4b1899`から変更していません。奇偶バラ
ンスは書き直した全ファミリー（ブラス、ストリングス）のプローブで動き
ましたが、こちらも対照に対して単一方向ではありません。2A03自身の奇偶
バランスがパッチごとに大きく異なるためです（ブラスを鳴らす2つのデモプ
リセットのcontrolで0.46〜0.51 dB、和音プローブのcontrolで17.47 dB）。
マレットはmainとnew dryが上表の全指標で小数第2位まで一致し、アンサン
ブル式の`unison: 1, detuneCents: 0`の場合が音声を変えずにレンダリング
することを、ソース差分だけでなく実測でも確認しています。

`space`の既定値そのものの決定とその全証拠（この測定だけでは捉えられな
い歴史的なPR #44の回帰を含む）は[DECISIONS_ja.md](DECISIONS_ja.md)の決
定53に記録しています。
