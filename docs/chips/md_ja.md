# メガドライブ：YM2612 + SN76489 (`md`)

<p align="center">
  <a href="md.md">English</a> &bull;
  <a href="md_ja.md">日本語</a>
</p>


メガドライブは4オペレーターFMを6チャンネル持ち第6にDACを備えるYamaha YM2612と、映像チップ内の矩形波3音＋ノイズのTexas Instruments SN76489を使います。方法は[CONFORMANCE.md](../CONFORMANCE_ja.md)を参照してください。

| | |
| --- | --- |
| **機種** | Mega Drive、Genesis（NTSCマスター53693175 Hz、YM2612は1/7、PSGは1/15） |
| **状態** | **作業中**：全スクリプトのFM出力はダイ解析由来の参照と一致。全役割を再生可能で、FMドラムキットと両ドライバーのLFO、ネイティブドライバーのチャンネル3特殊モードも含みます。PSGはMAMEの`sn76496`と比較し3件の相違を診断済み（周期0／1、リセット時の極性、tone 3レートのノイズ位相）。アナログ段は未測定 |
| **コア** | YM2612はNuked-OPN2の逐行移植（`packages/chipvoice/src/chips/md/ym2612.ts`）、SN76489はSMS Powerの資料から実装（`sn76489.ts`） |
| **コアのライセンス** | `ym2612.ts`はNuked-OPN2由来のLGPL 2.1。独自コードはMIT。パッケージに両方を表示 |
| **更新日** | 2026-09-27、手動および`conform` |

**数値の意味。** `script-algorithms`、`script-detune-lfo`、`script-envelopes`、`script-ssg-ch3-dac`はPSGに触れないため自明に100%です。残る4ログはMAMEと一致せず、いずれもハーネスの不具合ではなく`sn76489.ts`とMAMEの`segapsg_device`の実際の違いに起因します。

- **周期0または1は、本実装では一定出力、MAMEでは最速のトーンです。** `sn76489.ts`の`clock()`は`period[i] <= 1`を特別扱いして出力をハイに固定しますが、MAMEの`sound_stream_update()`にはその分岐がなく常にリロードとトグルを行うため、周期0または1は分周器が出せる最速の音、約111861 Hzになります。SMS PowerのSN76489資料は両方の読み方を記しています。トーン生成については「レジスタ値が0または1なら出力は+1の一定値」、一方サンプル再生については半波長1で「波形がフリップフロップしない」と別項で述べつつ、同じ式から111861 Hzという値もMAMEと同じ形で導いています。本実装は一定出力の読み方を採り、MAMEは同じ資料が許すもう一方の読み方を採っています。`script-psg-edges`はこれを直接示します（tone 0を周期0から64まで1つずつ保持）。
- **リロード前にチャンネルがどちらの極性で始まるかが異なります。** `sn76489.ts`の`reset()`は`output.fill(1)`とし、全チャンネルが無音のままハイで始まりますが、`sn76496.cpp`の`device_start()`はトーンチャンネルに`m_output[0..2] = 0`を設定します（`m_output[3]`だけはノイズLFSRのビットそのもの）。両モデルとも各チャンネルのカウンタを0から始めるため最初のリロードは同じサイクルで起きますが、その共有のリロードは本実装の出力を下げ、MAMEの出力を上げます。リセット以降初めて無音解除されたチャンネルが最初の自然なリロードより前だと、この一度きりの反転がその音符の間ずっと持続します。`script-psg-edges`はこれをはっきり示し（tone 1と2を小さな周期へ直接無音解除）、`script-psg`の最初の音符も示します（psg1とpsg2がともに51〜56%付近、反転した矩形波が自分自身と重なる割合です）。どちらの資料も電源投入時の極性を規定しておらず、これはどちらの文書にも書かれていない実装上の選択です。
- **tone 3のノイズレートには、MAMEと本実装で食い違う残留位相があります。** `(register[6] & 3) == 3`のとき、MAMEはtone 2の周期を倍にし（`m_period[3] = m_period[2] << 1`）毎リロードでLFSRをシフトしますが、`sn76489.ts`の`noisePeriod()`はtone 2の周期をそのまま返し、自身のトグル出力の「立ち上がり」にあたる1つ置きのリロードでのみシフトします。両方式は定常状態では同じ正味のシフト速度になりますが、どちらのモデルもレジスタ6へのモードのみの書き込みでカウンタや出力フラグをリセットしないため、このモードを（再）設定した直後の最初のリロードの正確な位相は、互いに共有されない履歴に依存します。これはこのモードが有効な間、大きいが一定のオフセットとして現れ（`song-bright`のパートでは約1440サイクル、増大はしません）、ドリフトや小さな差にはなりません。どちらの読み方も自分の資料とは整合しており、参照実装側では修正できません。
- **リセットからの白色ノイズLFSRの周期は、MAMEでも57337シフトであることを別途確認しました。** MAME自身の`segapsg_device`をリセットから使い捨ての測定プログラムで走らせ（コーパスには含めていません。完全な周期には約4億4千万マスターサイクルが必要で、そこに収めるには長すぎます）、シフトレジスタが種に戻るまで正確に57337シフト、周期モードでは正確に16シフトを数えました。どちらも本シートの数式テストの数値と正確に一致します。`script-psg-edges`は通常のハーネス測定用に短めの白色ノイズ区間（約29000シフト）を含み、さらにノイズが既に動作中にレジスタへもう一度書き込んでシフトレジスタが再びリセットされることを確認します。本実装もMAMEもレジスタ6への書き込みはすべて無条件にリセットするため、上記のtone 3レートの位相差を除いて、その区間全体で両者は一致します。
- **減衰のマッピングは一致します。** MAMEの生レジスタ値`m_register[2c+1]`を`output[c] ? 15 - m_register[2c+1] : 0`として読む値は、`sn76489.ts`自身の`outputs()`が計算する量（`output[i] ? 15 - attenuation[i] : 0`）と同じです。`script-psg-edges`の音量スイープの各段、および`script-psg`を通じてpsg3（一度も無音解除されないため極性の相違の影響を受けません）は、MAMEとサイクル単位で一致します。

1つ未解決の疑問があり、これ以上は追っていません。`song-bright`、`song-golden`、`song-punchy`(同じ2曲に対し3曲目だけ`perc: "punchy"`)は`script-psg`の最初の音符とまったく同じように、リセット以降初めてpsg1の無音を解除しますが、3曲ともpsg1は99.9999%一致します(約2130エッジ中12、20、20を除いて完全一致)。一方`script-psg`のpsg1は56%付近にとどまります。曲はドライバーが最初に鳴らす音符の前に、周波数と音量を異なる順序で書き込むか、何か別の方法で再同期している可能性がありますが、これ以上は追跡していません。

## ドライバーの対応範囲

`packages/chipvoice/src/chips/md/driver.ts`の`MdDriver`を`test/md-driver.mjs`で検証します。リードはFM 1、ベースはFM 2、和音はPSG 1、ドラムはtone 3を時計とするノイズ、または`perc: "punchy"`ならFM 6です。noiseボイスの各フレームは、キットがFMのときだけ`FmPatch`を持ち、`note()`がそれを読んで音符自体とその後のキーオフの両方をFM 6へ振り替えます。LFOはリードのパッチ(`"bright"`)かFMキットのハイハットのどちらかがそれを求めているとき、まだ求めている中で最も小さい番号のチャンネルで動きます。`syncLfo()`が音符ごとに再確認します。`$22`はチャンネルごとではなくチップ全体で1つのレジスタなので、両方が求めているときは番号の小さいチャンネルの速度が勝ちます。リードの`pms`(周波数4、FM 1)がFM 6より先なので、両方が同時に鳴るとハイハット自身の`lfoFrequency`(6)はリードに上書きされ、ハイハットはリード側の速度で鳴ります。これはバグではなくハードウェアの規則であり、ハイハット自身の速度が必要な曲は、その間リードのLFOを止めておく必要があります。ノイズキットは既定のままです。ここで求められることは他の5役割に何のコストもかけずに満たせますし、他のすべてのチップのキットが既にその音にしているので、名実ともに楽譜を移植可能にします。`"punchy"`は、FMチップ自身にリズムセクションも担わせたい曲のためのものです。

| ボイス | 使用する機能 | 使用しない機能 |
| --- | --- | --- |
| fm1、fm2 | 意図ごとにパッチを各チャンネルへ1度ロード。フレームごとのblock／F-numberとキャリアtotal level、キーオン／オフ、LFO(`"bright"`自身の`pms`) | SSG-EG、チャンネル3モード、DAC、パッチのキースケール、残り4チャンネル |
| fm6(noiseボイス経由、`perc: "punchy"`) | ネイティブキットと同じFMドラムパッチ、キーオン／オフ、LFO(ハイハットの`ams`) | パン、音符ごとのパッチ(キットは固定) |
| psg1 | フレームごとの周期と減衰 | psg2／psg3の音程付き使用 |
| noise | 2A03の16レートに対応するtone 3時計の白色ノイズ、フレームごとの減衰 | 周期ノイズ、固定3レート |

チャンネル3の特殊モードは移植可能な編曲器には出てきません。1つのFMボイスの単一音高を、3つの独立した音高に交換する機能で、デチューンしたユニゾン、1チャンネルの4オペレーターに広げた和音、速い分散アルペジオでしか割に合わず、いずれも4役割の楽譜(リード1つ、ベース1つ)が求める形ではありません。ネイティブドライバーはそれに届きます。ゲーム自身の作曲者がその形を直接求められるからです。詳しくは後述します。

ネイティブdriver(`native-driver.ts`の`compileMdVoices`)は`test/md-native.mjs`と`test/golden-md-native.mjs`で検証し、`MdDriver`が使わない機能に届きます。ゲームはこれに直接書きます([MD-NATIVE-DRIVER.md](../MD-NATIVE-DRIVER_ja.md))。

| ボイス | 使用する機能 | 使用しない機能 |
| --- | --- | --- |
| fm1〜fm6 | 音符ごとのパッチを前回との差分で書き込み。完全な左右定位。フレームごとのレベル、ベンド、グライド、ビブラート、スイープ。レガート。`ssg`によるSSG-EG。キースケール。LFO(`ams`、`pms`、オペレーターの`am`、`lfoFrequency`)。fm3のチャンネル3特殊モード(`ch3`) | - |
| psg1〜psg3 | dB単位のフレームごとエンベロープ付きの音程 | - |
| noise | tone 3時計または固定3レートの白色・周期ノイズ | - |
| dac | FM 6上の約13.3 kHzのPCMストリーム、バス上で書き込みごとに1サンプル | - |

<a id="known-deviations"></a>
## 既知の差異

| 内容 | 意図的か | 理由 | 影響 |
| --- | --- | --- | --- |
| 書き込みは指定マスターサイクル以後に開始する内部サイクルで到着し、内部サイクルごとに1件 | はい | 68000はそれ以上速く書けず、参照側も同じ規約 | 最大1内部サイクルの到着時刻 |
| 周期0または1のトーンは分周器の最速レートでトグルせず、出力を一定に保つ | はい | SMS PowerのSN76489資料は両方の読み方を記す。MAMEの`sn76496.cpp`はもう一方を採る | 周期0／1のトーン |
| 全チャンネルの出力はリセット時にロー（トーンチャンネル）またはLFSR自身のビット（ノイズ）から始まり、ハイではない | いいえ、未文書化 | SMS PowerもMAMEのコメントも電源投入時の極性を規定していない。MAMEの`segapsg_device`はトーンチャンネルをローで始める | リセット以降初めて無音解除され、最初の自然なリロードより前のチャンネル：一度きりの永続的な位相反転 |
| tone 3のノイズレートはtone 2の周期を倍にせず、LFSRを1つ置きのリロードでシフトする | はい、正味のレートは一致 | SMS Powerの資料は正確なリロード規約を与えない。両方式は定常状態では一致するが、モード変更をまたぐ残留位相は一致しない | レジスタ6へのモードのみの書き込み後、tone 3レートが有効な間のノイズ位相 |
| ラダーDAC付き単体YM2612を使用し、YM3438ではない | はい | Model 1と初期Model 2の音。`type`で別種を選択可能 | ピン出力。デジタルボイスは変えない |

<a id="power-on-state"></a>
## 電源投入状態

`reset()`はNukedの`OPN2_Reset`です。全オペレーターがエンベロープ底部のリリース状態、倍率1、左右パン有効、PSGは全減衰器で無音です。ドライバーはゲーム同様、LFOをオフ、チャンネル3を通常、DACと全キーをオフにします。
