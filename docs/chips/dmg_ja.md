<p align="center">

**数値の意味。** 先頭列だけでなく末尾列を見てください。各ボイスのほぼ全区間は、区間ごとの一定シフトでエッジ時刻と値が参照と揃います。矩形波のデューティと速度、上下両方向のエンベロープ、3段階の波形出力、両ビット幅のノイズ系列を確認できます。一致サイクル数が低いのは、音の開始規約が系統的に異なるためです。参照はトリガー直後に最初のステップを出しタイマーを再ロードしませんが、実機は再ロード後1周期待ちます。フレーム時計も分周器のビットでなく時刻ゼロで動き、50%／75%デューティの配列も回転しています。その一定ずれだけで各サイクルが不一致に数えられます。

残りの未対応エッジには、参照にないゾンビエンベロープ、周波数適用が1周期遅いスイープ、直ちに初サンプルを出す波形チャンネルが含まれます。[参照README](../../packages/conform/oracles/gb-snd-emu/README_ja.md)に列挙しています。これらはPan Docsやサイクル単位のROM検査に対するchipvoiceの逸脱ではありません。ROMは成功しています。この参照はROMが検査しない短周期ノイズの形とエンベロープの段階を確認できます。より強い参照は次節で、サイクル精度のコアに同じコーパスをかけます。

**数値の意味。** SameBoyはトリガーされたボイスのタイマーを再ロードし、フレームシーケンサーを分周器のビット12そのもので刻み、デューティ配列もPan Docsの順です。したがってGb_Snd_Emuの一定シフトの原因（独自の256 Hz時計、タイミングのないトリガー、回転したデューティ）はどれも当てはまりません。代わりに残るのは、ほぼ全ログに共通する、これまで診断されていなかった支配的な原因が1つと、より狭い範囲の所見が4つです。それぞれ両方の値、サイクル、引用元を添えて以下に示します。いずれもPan Docsやblarggの成功し続けているROMに対するchipvoiceの逸脱ではありません。全てのサイクル・ボイス・値の組は[`corpus/dmg/parity-sameboy.json`](../../packages/conform/corpus/dmg/parity-sameboy.json)にあります。

- **トリガー直後の矩形波・ノイズボイスは実機では瞬時ではなく、本実装はそれをモデル化していません。** これがほぼ全ログの残差の大半です（`script-envelopes` 35.92 %、`script-pulses` 49.67 %、`script-noise` 52.11 %）。`script-pulses`の最初の相違、サイクル419430では、`本実装`はNR14のトリガービットが立った瞬間に15を返しますが、SameBoyはそこで0を返し続け、サイクル457327（pulse 1、`script-sweep`）またはそれに類する間隔まで0のままで、その後デューティ位置と音量が示す値へ一気に飛びます。`vendor/apu.c`のNR14/NR24トリガー処理は`delay`フィールド（無音からなら`6 + lf_div * ...`、既に鳴っていたなら`4 - lf_div + extra_delay`）をタイマー再ロードに設定し、チャンネルを`sample_surpressed`として、その最初の自然なティックが来るまでマークします。コメントは「NRx4のサウンド開始による音量変化は即座に効くが（＝直前から鳴っていた音への効果）、再生自体は瞬時ではないため、それ以外の場合はサンプルを更新しない」というものです。`dsp.ts`の波形チャンネルは既にこれと全く同じ挙動をモデル化していますが（下記「トリガー後の初フェッチが6サイクル遅れる」の行）、`Pulse`と`Noise`はそうなっておらず、トリガーが立った瞬間の現在のデューティ／LFSRビットを読んでしまいます。これは修正に値する実在の差ですが、別チケット（P2-1）の対象であり、本チケットでは直しません。
- **スイープは、shift・periodが小さい領域で、オーバーフローがチャンネルを無音化するかどうかで食い違います**（[Pan Docs, "Sound Channel 1 - Pulse with period sweep"](https://gbdev.io/pandocs/Audio_Registers.html#ff10--nr10-channel-1-sweep)）。`script-sweep`の最初の区間（NR10 = `$11`：period 1、加算、shift 1、サイクル419430で周波数856から開始）が最も明快な例です。`本実装`は周波数を3回上げた後、サイクル483327で完全に無音になります（周波数が2047を超えたため）。これはPan Docsの「新しい周波数が2047以上ならこのチャンネルは停止する」という記述、およびコーパスの他4区間（両トレースがよく一致する）と整合します。一方SameBoyは、次のトリガーであるサイクル3774874（330万サイクル後）まで、周期32768サイクルの一定した音を出し続けます。`vendor/apu.c`の`sweep_calculation_done`に付いた本人のコメントがその理由を説明しています：「APUのバグ：スイープの周波数はスイープ差分を2回加算した後にチェックされる」。SameBoyは、シャドウ周波数と2倍にしたスイープ差分（`shadow_sweep_sample_length`、`sweep_length_addend`。いずれも`trigger_sweep_calculation`と遅延した`square_sweep_calculate_countdown`にまたがって組み立てられる）に対してオーバーフローを判定します。これは文書化されたDMGの癖で、shiftが小さいと、本実装の単純な（2倍にしない）判定なら捕まえるはずのオーバーフローを覆い隠すことがあります。blarggのROM 05「sweep details」はまさにこの2倍加算を狙ったものです。コーパスの残り5つのスイープ区間（shiftやperiodが大きい、あるいは減算方向)ではこれは現れず、他のボイスと同程度の小さな残差シフトの範囲に収まります。
- **長さカウンターは一致しています**：`script-lengths`はコーパス中最良のログです（92.88 %）。channel 3の1946個のエッジは全て完全一致、channel 4は99.00 %で、256 Hz時計と「NRx4書き込み時の追加時計」の癖（[Pan Docs, "Length Timer"](https://gbdev.io/pandocs/Audio_Registers.html#length-timer)、blarggのROM 07）は両者で同じです。channel 1・2に残るずれ（98.08 %、95.80 %）は上記と同じコールドトリガー無音化が原因で、長さカウンター固有のものではありません。このログはNR52で電源を切ることが一度もないため、電源サイクルをまたぐ保持の検証はどちらの側でも行われていません（結果ではなく、コーパスの穴です）。
- **波形チャンネルのトリガー直後の初サンプルは一致し、後続の1サンプルが時折1段早く出てすぐ自己修正します。** `script-wave`自身のトリガー、サイクル6710886では、両トレースとも同じサイクルで2を読みます。SameBoyの`wave_channel`の遅延モデルと`dsp.ts`のもの（下記「既知の差異」）は、この駆動系のタイミング分解能では区別できないほど近く、今回の実行は「6サイクル遅れる」という主張を裏付けも新たに否定もしません。このログで唯一の本当の相違はトリガーから離れた再生途中で起きます。サイクル6720891で`本実装`はサンプル値10を読みますが、SameBoyは11を読み、1段先取りしています。SameBoyの次のサンプル（500サイクル後、6721391）は10に戻り、以降のサンプルからは両トレースが再び完全一致し、恒久的なずれは残りません。この形（1サンプル早く出て、すぐ正確に再同期する）はログ中に912回現れ、そのうち907回は固有のシフトで揃います。これはこの参照実装自身の2Tサイクル単位の`apu_cycles`バッチ処理（参照実装の[README](../../packages/conform/oracles/sameboy/README_ja.md)を参照）によるもので、波形シーケンス自体の不一致ではありません。全サンプルの値は正しく、ある遷移のサイクルだけが2サイクルの境界のどちら側に丸められるかがたまにずれるだけです。
- **ノイズLFSRの「トリガー時は無音」という規約は同じで、極性だけが逆です。コールドスタートは矩形波と同じ抑制を受けます。** `dsp.ts`はLFSRを`0x7fff`で初期化しビット0を「無音」と読みますが、SameBoyの`prepare_noise_start`は0で初期化しビット0を「オン」と読みます。これは同じ事実を補完的に符号化しているだけで、どちらも新しいノイズチャンネルがトリガーされた瞬間は無音です。Pan Docsの「Noise Channel」および`NR43`の幅ビットが持つ2つのフィードバックタップ（ビット14は常時、幅ビットが立っている場合はビット6も追加）は両実装とも同じです。`script-noise`の52.11 %は矩形波と同じコールドトリガー無音化が原因であり、LFSR自体についての新しい所見ではありません。channel 4のエッジは154713のうち132099がシフト-8で揃っており、これは抑制されたコールドスタートの後に正確に再同期するという特徴そのものです。
- **ゾンビモードのエンベロープ書き込みは実際にコーパスで行われており（`script-envelopes`自身の注記にも「a zombie write mid-note」とある）、単純なケースでは両モデルが一致し、複合ケースでは食い違います。** サイクル20132659で、channel 1が鳴っている最中にNR12が`$A0`から`$A1`へ書き換えられます（periodが0から1、方向は同じ）。`dsp.ts`の`oldPeriod === 0 -> volume++`は書き込みの瞬間に10から11になります。SameBoyの音量も11になります（次の自然なデューティエッジ、1488サイクル後のサイクル20134147で確認でき、これは1デューティ周期以内です。書き込みのそのサイクルで見えない唯一の理由は、その瞬間channel 1のデューティビットがたまたま低かったためです）。サイクル20552090では、NR12が`$A1`から`$A9`へ書き換えられます（periodは1のままですが、エンベロープの方向が反転します）。`dsp.ts`は3を読み、SameBoyは7を読み、その後もそれぞれ自分の値を保持し、収束しません。`vendor/apu.c`の`nrx2_glitch`に付いた本人のコメントがおそらくの理由を示しています：「pre-CGBモデルでは一部が非決定的である。具体的には$x0への書き込みは非決定的に見えるが、$x8は常に期待通りに動く」。DMG-Bでは`nrx2_glitch`が`_nrx2_glitch`を2回、中間値`0xFF`を経由して実行する、pre-CGB-D固有の、単純な閉じた式のないモデルです。`dsp.ts`の単純な1段階の式（blargg自身のグリッチの説明に基づく)はそのモデルではなく、この複合ケース（非ゼロのperiodでの方向反転が、既にずれた音量の上に重なる)がまさに両者が分かれる点です。実機のゾンビモード自体、SameBoy自身の言葉で一部非決定的なハードウェア挙動と認められており、これはどちらの側のバグとも言えない、正真正銘の未解決の疑問です。

**無音から始まる矩形波。** 2026-09-27以降（P2-1）、停止中にトリガーされた矩形波は、開始位置のパターンに関係なく、最初のデューティの1段までデジタルのゼロを出します。Pan Docs：「When first starting up a pulse channel, it will _always_ output a (digital) zero.」SameBoyの`apu.c`も同じで、チャンネルを始動する全てのトリガーでサンプルを抑え、最初のtickで解除します。Gb_Snd_Emuはすぐにパターンを鳴らすため、上のベースラインは無音から音が始まる矩形波の行で一致サイクルが減る形で書き直しました。最大5759（`script-sweep`のch1）で、そうした音1つにつき1段分です。P3-4の参照で測ったSameBoyに対しては、同じ変更で矩形波を含む全ログの一致数が増えます。blarggの12本のROMはどちらでも成功し、これを検査するものはありません。

<a id="power-on-state"></a>
## 電源投入状態

`reset()`は起動音を除くブートROM終了後相当です。電源オン、レジスタと波形RAMはゼロ、フレームシーケンサーは最初の時計直前、ノイズは全ビット1です。実ブート音が残すpulse 1設定と左右マスター音量7は、ROM実行前にハーネスが書き込みます。

<a id="history"></a>
## 履歴

- 2026-09-27：無音から始まる矩形波が、最初のデューティの1段までデジタルのゼロを出すように。Pan DocsとSameBoyの通り（P2-1）。Gb_Snd_Emuのベースラインをそれに合わせて書き直し。
- 2026-09-04：Pan Docsとblarggの資料から実装。波形破損窓をフェッチ前2サイクルへ直し、dmg_sound全12本成功（`f636b9f`）。
- 2026-09-27：2つ目の、より強力な参照実装としてSameBoyのDMG-B `apu.c`を追加（チケットP3-4）。矩形波とノイズに共通する実在の差（実機ではトリガー直後のボイスは瞬時ではない）をGb_Snd_Emuでは示せなかった形で発見し、加えてスイープのオーバーフローとゾンビモードでの相違も見つかった。いずれも確定したバグではなく未解決の疑問として扱う。コールドトリガーの差を直すのはチケットP2-1が追う。
