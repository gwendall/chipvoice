# Konami VRC6 (`vrc6`)

<p align="center">
  <a href="vrc6.md">English</a> &bull;
  <a href="vrc6_ja.md">日本語</a>
</p>


NEXT-14の拡張音源チップの最初の1つ(decision 38)：KonamiがNES/Famicomの一部の自社カートリッジに載せたマッパーチップで、16段階のデューティ比テーブルを持つ2つのパルス(2A03の4種の固定デューティとは異なる)と7ビットの鋸歯状波を追加し、それぞれが独自の12ビット周期(2A03自身の11ビットパルスより1ビット広い)を持ち、コンソール自身の5ボイスを置き換えるのではなく、それらと混ざって鳴ります。各節の方法は[CONFORMANCE.md](../CONFORMANCE_ja.md)にあります。

| **状態** | **作業中**：Game_Music_Emuの`Nes_Vrc6_Apu`に対し、いずれも複数回の有効化／無効化を組み込んだ8本のスクリプトで測定。参照実装は無効化をまたいでいる間の状態を凍結するのに対し、資料（および本コア）はリセットまたはゼロ化するため、生のサイクル単位一致率は35.7 %が上限になる一方、ボードが読む区間ごとのシフト許容一致率は105区間中79.0 %；NSFエクスポート／再生はこのチップを経由；ドライバーはまだ届いていない |

**数値の意味。** 生の見出し数値（35.7 %）は、このチップに関しては特に過小評価です。コーパスはあえて全ボイスを複数回の有効化／無効化サイクルにさらしており（理由は`generate-vrc6.mjs`自身のコメントに書かれています）、Game_Music_Emuの`Nes_Vrc6_Apu` - 直接読んだ`gme/Nes_Vrc6_Apu.cpp`（同梱オラクル内） - は、資料も本コアも行わない、無効化をまたいだ状態凍結を行います。パルスの`run_square`は`volume && !gate && period > 4`が真の間しか16段階の位相を進めません。これはチャンネルが無効化されている間（そこでvolumeが0に強制される）、または「常時オン」モード（`gate`が真）の間は偽になるため、位相は止まった場所で保持され、再有効化後もそこから再開します - 一方nesdev自身の文章（「Eが再びセットされると最初から再開する」）と本コアはどちらも、無効化から有効化への切り替わりのたびにステップ15へリセットします。鋸歯状波の`run_saw`はさらに顕著です。無効化されている間はアキュムレーターにも自身の分周器にも一切触れない分岐を取りますが、nesdevの文章は「アキュムレーターはゼロに強制される」「Eをクリアしても周波数分周器はリセットされない」とはっきり述べており、本コアはそのどちらも文字通り実装しています。オラクルよりwikiページを優先しています（decision 41）。これはどちらの側も知っていると主張する文書化されたハードウェアのリセット値ではなく、本コアが実装のもとにしているwikiページより前に作られた、2005年当時のあるエミュレーター自身の実装に過ぎません。だからこそ`status-data.mjs`自身のボードは、この生の数値ではなく、区間ごとのシフト許容一致率 - 各区間が自分だけの一定シフトを得ればエッジ単位で一致する105区間中79.0 % - を読みます。2A03シートの三角波が、いくつかのログで生の一致率0 %であっても信頼されているのと同じ理由です。

`script-saw-worked-example`は一度も無効化しませんが、その1つの区間は全長にわたって一定の1サイクルシフトに収まります - これは上記の無効化に伴う挙動とは別の、クロッキング順序の規約（どちら側の書き込みが、その着地したサイクルで効くか）であり、ここで測定された中で最小かつ最も機械的な相違です。`script-pulse-periods`自身の最悪の区間（探索で解決できなかった数千サイクル規模のシフト）は、同じソースから読み取れるもう1つのGMEのショートカットと符合します。`run_square`の位相前進ループは、リロードされた周期が4サイクル以下のときは常にスキップされ、これはまさにこのスクリプトの周期0と周期1のケースです - オラクルはナイキストレート付近でトグルを止めますが、実チップおよび本コアは動き続けます。これはソースから読み取ったものであり、エッジ単位で独立に再検証したものではありません。`$9003`（周波数スケーリング／ホールトレジスタ）はここにある全スクリプトで書き込まれますが、オラクル自身のアドレスデコード（`reg_count = 3`）がディスパッチに届く前にそれを落としてしまうため、どちらの方向にも比較可能な信号を与えません。これらはすべて、ソースの該当行とともに[オラクル自身のREADME](../../packages/conform/oracles/game-music-emu/README_ja.md)にまとめてあります。このシートにとっての代償については、下の「既知の差異」を参照してください。

## テストROM

自動化可能なVRC6テストROMは見つかりませんでした。`bbbradsmith/nes-audio-tests`が公開する`db_vrc6.nes`（CC0）は、各VRC6波形を順に鳴らし、聴き手が実カートリッジや実績あるエミュレーターと聴き比べて判定するものです。機械可読な出力を一切行わず、デバッグカートリッジの規約も駆動しません（本ハーネスの6502フィクスチャがすでに2A03とSIDで読んでいるような`$6000`系のpass/failバイトも、ボーダーカラーや完了時ホルトの信号もありません）。そのため`roms:c64`や`roms:dmg`のようには`roms:vrc6`へ組み込めません。このリポジトリのどこにも同梱しておらず、実行するのはCI外の手動・随時のチェックであり、このシートの数値には含まれません。

未測定。`Vrc6MixStage`（`packages/chipvoice/src/chips/nes/vrc6-core.ts`）は、2A03シートがすでに記述している共有のDACとフィルター演算の前段で、VRC6の3ボイスを2A03自身の5ボイスに加算します。そのミックスゲイン（`VRC6_MIX_UNIT_GAIN`）は測定に適合させたものではなく、文書化された式です。上の数式テストは、VRC6側が無音を出している場合に結合段が素の2A03と完全にビット一致することを証明していますが、これは既に部分的に測定済みの2A03ミキサーに今回の追加が回帰を持ち込まないことを示すだけで、8ボイス全てが駆動された結合出力が実際のVRC6カートリッジのライン出力と一致することは示していません。ここでのキャプチャは一切試みていません。実カートリッジ自身のキャプチャだけがこれを解消でき、2A03とSIDの両方がまだ抱えているのと同じP7-8型の欠落です。

<a id="driver-coverage"></a>
## ドライバーの対応範囲

なし。decision 38により、このチケットではVRC6はスタジオのピッカーとアレンジャーから外れています：「チップの前にシート」があり、公開ピッカーに届くのはシートが埋まった後だけで、NEXT-14自身のスコープはチップ、ハーネス、NSF、そしてこのシートであり、ドライバーではありません。結合チップは`"2a03-vrc6"`（`vrc6-core.ts`の`NES_VRC6`）として登録され、スタジオを経由しないコードからは完全に到達可能です - `chips()`、`getChip("2a03-vrc6")`、`chipFor("2a03-vrc6")`、`Chip.create({ chip: "2a03-vrc6" })`はいずれもこれを見つけます - が、`CHIP_IDS`（`project-schema.ts`）には意図的に含まれておらず、プロジェクトもピッカーもアレンジャーの語もこれを選べません。`vp1`／`vp2`／`vsaw`向けのドライバーとアレンジャーの役割は未着手で、[BACKLOG.md](../BACKLOG_ja.md)で追跡しています。

| ボイス | 使用する機能 | 使用しない機能 |
| --- | --- | --- |
| vp1、vp2、vsaw | ハーネスのコーパスとNSFエクスポート／再生（下記参照） | アレンジャーの全役割：リード、ベース、和音、ドラム；出荷される曲からはまだ何も届かない |

<a id="nsf-export-and-playback"></a>
## NSFエクスポートと再生

`exportNsf`（`packages/chipvoice/src/nsf.ts`）は、キャプチャのVRC6レジスタ書き込み（`isVrc6Addr`、コアとハーネスが使うのと同じ10個のアドレス）を、2A03の書き込みと同じ方法でエクスポートされたROMへ流し込み、いずれかが現れると拡張音源ヘッダーバイトのビット0を立てます。これによりそのビットを読むプレイヤー（Famitracker、`foobar2000`、その他多く）は、再生前に自身のVRC6拡張音源を有効化すべきだと分かります。プレイヤーのコード自体はもはや`$4000`からの固定オフセットを保持しません。2レジスタページのストア（`STA $4000,Y`）ではVRC6の3つの独立したページ（`$9000`〜`$9003`／`$A000`〜`$A002`／`$B000`〜`$B002`）には届かないため、2A03かVRC6かを問わず、あらゆる書き込みは今やキャプチャが実際に使うレジスタだけを収めたROM内テーブルへのインデックス経由でディスパッチされ、間接ストア（`LDA table,Y`でゼロページポインタに読み込み、`STA (zp),Y`）で解決されます。これは一律に適用されるため、2A03専用ファイルの出力もバイト列は変わりますが挙動は変わりません。これは既存のCIゲート済みの`nsf-export:check`／`nsf-corpus:check`オラクル一式（すべて実在の2A03音源、コマンドストリームとフレーム書き込みの両方で完全一致、変化なし）で影響がないことが証明されています。`capture-nsf.mjs`（このハーネスがエクスポートされたNSFを再生し直すオフライン6502）は、VRC6ビットが立ったファイルを受け付け、その10個のレジスタへの書き込みを、2A03に対してすでに行っているのと同じ方法でイベントとしてルーティングします。自作のラウンドトリップがこれを`packages/chipvoice/test/nsf.mjs`でエンドツーエンドに証明しています（2A03とVRC6が混在した書き込みをエクスポートし、再生してオリジナルのキャプチャとフレーム単位で照合、2A03専用ファイルが課されるのと同じゲートです）。[`scores/nsf-corpus`](../../scores/nsf-corpus)にサードパーティのVRC6 NSFは追加していません。このプロジェクトが見つけたVRC6ファイルはどれも、コーパス自身の規約が要求するライセンス（CC0、CC-BY、パブリックドメイン、またはそれに準ずる寛容なもので、出典URLを併記）を満たしていませんでした。

| リロードされた周期が4サイクル以下のパルスは、オラクル側では一切トグルしない | いいえ、オラクル側の欠落 | Game_Music_Emuの`run_square`は`period > 4`のときしか位相前進ループを実行しない；本コアはどんな周期でも進み続ける | `script-pulse-periods`自身の周期0および周期1の区間 |
| `$9003`（周波数スケーリング／ホールト）は資料から実装されているが、オラクルとの突き合わせができていない | いいえ、オラクル側の欠落であり本コアのものではない | Game_Music_Emu自身のアドレスデコード（`reg_count = 3`）が、オラクルに届く前にそれへの書き込みをすべて落とす | ホールトビットとスケーリング除数への信頼は、独立した測定ではなく資料のみに基づく |
| 3ボイス結合時のミックスゲイン（`VRC6_MIX_UNIT_GAIN`）は測定に適合させたものではなく、文書化された式である | はい、キャプチャ待ち | 実際のVRC6カートリッジのライン出力はまだキャプチャされていない（「アナログ段」参照） | VRC6側が無音でないときのアナログ段の精度 |

<a id="power-on-state"></a>
## 電源投入状態

`reset()`はVRC6の全レジスタをゼロにします：両パルスと鋸歯状波は無効化・無音、`$9003`のホールトビットとスケーリングビットはクリアされます。これは推測による規約です（VRC6の実機もGame_Music_Emu自身のエミュレーションも、実機の電源投入／リセットシーケンスがカートリッジRAMをクリアし、ドライバーが最初の音符の前に全レジスタへ一度書き込むことを経て、同等の内部状態をゼロのまま残します）。VRC6自身のデータシートが述べる文書化された電源投入デフォルト値ではありません - Konami自身の資料は、レジスタが一度書き込まれた後の挙動を記述するのみで、そのリセット値は述べていません。
