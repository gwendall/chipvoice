# Commodore 64：MOS 6581 SID (`c64`)

<p align="center">
  <a href="c64.md">English</a> &bull;
  <a href="c64_ja.md">日本語</a>
</p>


6581は3ボイスを備え、各ボイスに組み合わせ可能な4波形の発振器とゲート付きエンベロープがあります。隣接ボイス間の同期とリング変調、共有フィルターを使えます。方法は[CONFORMANCE.md](../CONFORMANCE_ja.md)にあります。

| **状態** | **作業中**：各ボイスのデジタル2値がreSID-fpと一致、ドライバーは全役割を再生、アナログ段は資料由来のプロファイル |
| **コア** | 資料から独自実装（`packages/chipvoice/src/chips/c64/sid.ts`）。アナログプロファイルは`dsp.ts` |
| **コアのライセンス** | MIT。参照のreSID-fpはGPLで、ハーネス内だけに置く（決定18） |

**数値の意味。** 全6ストリームの全ログが一致します。全波形の各音高とパルス幅、4組み合わせ波形とノイズ合成時のレジスタへの書き戻し、8レートのノイズとtestビットによるリセット、全ADSRレートとサステイン、各段で数サイクル間隔のゲート、アタック中に現在値より低く設定するレートレジスタ、同期済みの源を含む4比率での同期／リング変調、源のtestビットとゼロ周波数、ドライバー経由2曲を検査します。

初回に直した点は実機の事実に関する2点です。電源投入はリセット線の解除でノイズを1回進めます。またエンベロープのレート8はデータシートの391でなく392サイクルで、kevtrisが実チップから読んだ値に一致します。組み合わせ波形は各組み合わせ6数値のモデルで、全4096項目が参照表と一致します。`pnpm --filter chipvoice-conform fit:c64`で採点します。

この表で新しい4スクリプト（`script-dense-sawtooth`、`script-dense-triangle`、`script-dense-noise`、`script-dense-combined`）は、鋸歯状波・三角波・ノイズ・組み合わせ波形のいずれかをログ全体を通して3ボイス同時に保持します。ほかのスクリプトが検査対象のボイス以外でパルスを使うのに対し、これらは数秒間、全ボイスの12ビット出力がほぼ毎サイクル同時に変化し続けます。これらもreSID-fpと一致します。追加した理由は、以前のハーネスがストリームの全変化を1個ずつオブジェクトとしてメモリに保持していたためです。3つの鋸歯状波を8秒（このコーパスの3倍の長さ）保持しただけでメモリ不足になっていました。typed arrayの列を使う`ChangeStream`とストリーミング比較への変更でこれを解消しました（P7-11）。その厳密なケース、3つの鋸歯状波を8秒間は、このコーパスには含めていません。単独で約1分と1.5ギガバイトほどかかり、上記全部を合わせた数秒間とは釣り合わないため、代わりにオンデマンドで`pnpm --filter chipvoice-conform check:c64:dense`（`packages/conform/corpus/c64-dense`）として実行します。これも一致しており、`check:c64`にもCIにも含まれません。

<a id="the-8580"></a>
## 8580

C64の後半世代（65とC64C）に載った第二のSID：レジスタとエンベロープジェネレーターは同じですが、組み合わせ波形ビットの引き合い方が異なるデジタル波形ジェネレーター、フローティング波形出力とノイズレジスタのtestビットリセットの両方でコンデンサー放電が長く、6581の折れ曲がったDACに対しほぼ線形なDAC、そして自前のフィルターを持つ、新しいプロセスで作られた再設計チップです。以下の各事実は資料または参照表への実測によるもので、reSID-fp自身の8580ソースを本パッケージへ移植したものではありません（decision 41）。各項が出典を示します。

**選択方法。** `Chip.create`、`renderPerformance`、`renderProject`、または楽曲の`settings.model`で`model: "8580"`を指定します。既定の`"6581"`が使えるところならどこでも：

```js
const chip = await Chip.create(ctx, { chip: "c64", model: "8580" });
```

`ChipCreateOptions`を通じてワークレットの`SidProcessor`の`processorOptions.model`、ハーネスや`RenderOptions`／`renderPerformance`自身の`model`フィールドの`c64Chip.digital({ model })`まで伝わります。未知の値は6581にフォールバックします。`SID_8580_PROFILE`と`SID_6581_PROFILE`（`packages/chipvoice/src/chips/c64/dsp.ts`）も、`Chip.create`を経由せずプロファイルを読みたい場合に直接エクスポートされています。

**組み合わせ波形。** 6581と同じ6数値の隣接引き合いモデル、`COMBINED_8580`（`packages/chipvoice/src/chips/c64/sid.ts`）を、reSID-fp自身の8580表に対して独立に適合（`pnpm --filter chipvoice-conform fit:c64 -- --model 8580`）させたもので、reSID-fp自身の`WaveformCalculator.cpp`の8580用`config[1]`の値をそのまま写したものではありません（decision 41：そのファイルは何を測るべきか知るために読んでよいが、移植はしない）。6581自身の数値から1回だけ降下させると4つのうち3つで収束不足だったため、多数のランダムな開始点からの座標降下で各組み合わせの最良値を採用しています。

| 組み合わせ | reSID-fpの8580表との一致率 |
| --- | --- |
| `saw+triangle` | 99.05 % (4057/4096) |
| `pulse+triangle` | 97.51 % (3994/4096) |
| `pulse+saw` | 95.00 % (3891/4096) |
| `pulse+saw+triangle` | 92.60 % (3793/4096) |

いずれも6581の100%には届きません。reSID-fp自身の8580コードは、両チップに使うこの単純なバイアス／ビットごとの引き合いモデルより詳細なトランジスタモデルから表を作るため、完全な適合は期待できません。上のデジタル一致率のブロックはこの不足がどこに現れるかを正確に示しています。組み合わせ波形を選ぶ2ログ、`script-combined`と`script-dense-combined`だけが98.98%と91.19%になり、それ以外は全て100%一致のままです。上の「実機6581との組み合わせ波形比較」に相当する8580版はありません。`libsidplayfp/combined-waveforms`は8580個体もサンプリングしていますが、それを取得して採点することは本チケットの範囲外で、アナログ段を測る誰かに向けて開いたままです（P7-8）。

**波形タイミング。** reSID-fpの`WaveformGenerator.cpp`／`.h`（既存モデルが使う6581R3の定数の隣にある`FLOATING_OUTPUT_TTL_8580R5`／`SHIFT_REGISTER_RESET_8580R5`）から引いた2つのコンデンサー放電時間：波形未選択のフローティング出力がゼロに落ち着くまで8580は6581の約10倍、testビットによるノイズレジスタのリセットは約13倍かかります。いずれも`sid.ts`の`FLOATING_TTL`／`NOISE_RESET`というモデル別定数で、新しい数式ではありません。同じく`WaveformGenerator.h`より：8580には鋸歯状波の組み合わせでのアキュムレーターのプルダウン（6581限定の効果）も、testビット解除時のノイズ書き戻しにおけるswap-exclusion（同じく6581限定）もなく、いずれも`Oscillator.compute()`／`writeControl()`内で`model`により分岐します。

**OSC3の1サイクル遅延。** `WaveformGenerator.h`の`tri_saw_pipeline`：8580では`$D41B`（OSC3）が返す値は、波形ジェネレーター自身のその周期の出力より1サイクル前の鋸歯状波／三角波パイプラインの値です。6581にはこのパイプラインがなく、現在の周期の値を返します。これはレジスタの読み戻しだけの話で（`Sid`クラスが`output`と別に持つ`osc3`フィールド）、音声出力自体は変わりません。

**DAC。** `SID_8580_PROFILE.ladderRatio = 2.0`、`ladderTerminated: true`は、reSID-fpの`Dac`ドキュメント（「非常に精密に一致」、不連続点なし、比は約2.0）からのものです。この比で終端されたラダーは正確に2の累乗の重みになるため、8580の12ビットDACは（この資料の精度の範囲で）線形で、6581の未終端2.2ミスマッチとは異なります。

**フィルター。** `SID_8580_PROFILE.cutoff`、`qLow`、`qHigh`は、素のreSIDの`filter.cc`（同じファイル、NEXT-04が示した同じ「CSG 8580R5 1690 25」の個体）から導きます。6581の折れ曲がった曲線と異なり、`filter.cc`自身の固定小数点式`w0 = 82355 * (fc + 1) >> 11`（`Hz = 12500 * (fc + 1) / 2048`）は正確な直線で、レジスタの両端はfc=0で6.1035 Hz、fc=2047で12500 Hzです。`qLow`／`qHigh`（0.7072／2.5924）も同じファイルの`_1024_div_Q_table`の最初と最後の固定小数点値から得て、同じ式で計算した閉形式`1/Q`と照合済みです。これは`filter.cc`自身の公開済みの表を測定データとして使うもので（decision 41：読むが移植しない）、NEXT-04が求めた通りです。実機8580のライン出力キャプチャではなく、測定した両端の間の形（6581の曲線は1024付近に折れ曲がりがあります）はまだ未確認で、6581と同じP7-8のキャプチャが必要です。

**未測定のまま残るもの。** 6581と同様、自前の実機8580のライン出力キャプチャはありません。上の「実機6581との組み合わせ波形比較」のような、名前付き実機8580に対する組み合わせ波形の独立検証もありません。測定した両端の間のフィルターの形が本当に`filter.cc`の固定小数点式通りの直線か、6581のように折れ曲がりがあるか。そしてADSR表、ノイズLFSRのタップ、ゲート／同期／リング変調ロジック：reSID-fpの`EnvelopeGenerator.cpp`に8580固有の分岐はないため、本パッケージも6581節のエンベロープと同期／リング変調の事実をそのまま引き継いでおり、8580固有の資料での独立確認はしていません。

<a id="power-on-state"></a>
## 電源投入状態

`reset()`はリセット線です。レジスタ消去、ノイズ全1から1回進め、パルス比較器high、エンベロープはレートレジスタ0のリリースです。位相蓄積器は偶数ビットhigh、エンベロープカウンターは0xaaの電源投入値を保ち、時計開始後に最速で減衰します。参照作者の実測とreSID-fpに従います。ドライバーは音量最大、フィルター無効にします。
