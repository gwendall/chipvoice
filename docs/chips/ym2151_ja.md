# Yamaha YM2151 (OPM) (`ym2151`)

<p align="center">
  <a href="ym2151.md">English</a> &bull;
  <a href="ym2151_ja.md">日本語</a>
</p>


NEXT-16のチップ、前半：ヤマハのYM2151、1980年代半ばから後半にかけてのアーケード
基板とホームコンピューター（Sharp X68000、多数のTaito/Konami/Sega/Capcom基板）を
支えた8チャンネル・4オペレーターFMシンセサイザーです。
`packages/chipvoice/src/chips/ym2151.ts`はNuked-OPMを逐行移植したもの -
YM2612とNuked-OPN2についてdecision 17が下したのと同じ選択です -
そのため、この移植自身のダイ解析由来の原典がそのままオラクルになります。
decision 38により、本チケットの範囲ではスタジオのピッカーとアレンジャーの
対象外のままです：チップ本体、そのハーネス、プローブコーパス、そしてこの
シートのみで、ドライバーは含みません。YM2610（OPNB、NEXT-16の後半）は別の、
後のチケットです - [BACKLOG.md](../BACKLOG_ja.md)を参照してください。
各節の方法は[CONFORMANCE.md](../CONFORMANCE_ja.md)にあります。

<a id="digital-parity"></a>
## デジタル一致率

ハーネスである[`conform`](../../packages/conform)が、2つの独立した参照実装 -
[Nuked-OPM](../../packages/conform/oracles/nuked-opm)（この移植自身の原典を、
ネイティブビルドしたもの）と[ymfm](../../packages/conform/oracles/ymfm)
（Aaron Giles、独立、報告専用） - に対して測定します。`generate-ym2151.mjs`
自身のコメントが、コーパスと、1本を除く全スクリプトが従うセトリング時間の
規約を説明しています：

- **`core`**（[`packages/conform/corpus/ym2151/core`](../../packages/conform/corpus/ym2151/core)）：
  全アルゴリズムとop1フィードバック、デチューン（DT1/DT2）と倍率（MUL）、
  エンベロープ全体（AR/D1R/D2R/RR/D1L/TL）、LFRQ/AMD/PMD/AMS/PMSを伴う
  4つのLFO波形すべて、チャンネル8オペレーター4のノイズジェネレーター、
  オペレーターごとのキーオン、Timer AとCSM、そしてステレオL/Rイネーブル -
  機能ごとに1本のスクリプトで、それぞれNuked-OPMに対して文字通り100 %を
  課します。
- **`edge`**（[`packages/conform/corpus/ym2151/edge`](../../packages/conform/corpus/ym2151/edge)）：
  リリース中のキーオン、TL/ARの極端値、MUL 0でのDT2、テストレジスターの
  LFOリセットビット、全NFRQ値、そして2ポート書き込みラッチのセトリング
  ウィンドウ自体を、避けるのではなく意図的に発火させたもの（「既知の差異」
  参照）。コーパス全体でNuked-OPMに対して厳密にゲートします。

各マーカーの間の数値はハーネス（`pnpm --filter chipvoice-conform
baseline:ym2151-*`、下の表1つにつき1スクリプト）が書き込みます。その読み方は
人間の仕事です。CIは毎回全コーパスを再実行し、`core`または`edge`スクリプトの
Nuked-OPMに対する一致数が完全一致でなければ失敗します。
[`packages/conform/test/ym2151-gate.mjs`](../../packages/conform/test/ym2151-gate.mjs)
（`test:unit`の一部なので毎回のpushで実行されます）は、厳密ゲートが実際に
回帰を検出できることを証明します：各ゲートスクリプトの土台となっているのと
同じ`chip.trace()`/`oracle.trace()`/`compare()`を、コーパスログ自身の
書き込みに対して一度（乖離してはならない）、1件の書き込みの下位ニブルを
反転させたコピーに対して一度（乖離しなければならない）実行します。

<a id="test-roms"></a>
## テストROM

機械可読なYM2151テストROM（`$6000`系のステータスバイト、枠色や完了時
ホルトの規約）は見つかりませんでした。VRC6とSunsoft 5Bのシートが自身の
チップについて出したのと同じ結論です。実機アーケードやX68000のこのチップの
VGM吸い出しはローカルでの測定には有用ですが、本プロジェクト自身の
`scores/nsf-corpus`規約がコミットとして受け入れるライセンス（CC0、CC-BY、
パブリックドメイン、またはそれに準ずる寛容なライセンスで、ソースURLを
併記）を一切持たないため、決してコミットせず、gitignoreされた
`.artifacts/`ディレクトリに留めます。これは他のチップの実機キャプチャに
ついて[CONFORMANCE.md](../CONFORMANCE_ja.md)の他所で既に定めている
「ローカル限定」の前例そのものです。

| 破損したレジスター書き込みはトレースを変化させる - このゲートが解禁する一致検証に、実際に検出できるものがあることの安価な証明 | 成功 |

<a id="power-on-state"></a>
## 電源投入状態

`reset()`は`OPM_Reset`自身のブートストラップを厳密に再現します：
リフレクションによる全フィールドのゼロ化、`setIC(1)`、2048回の`clock()`
呼び出し（32×64、64個のスロット／チャンネル添字付き内部状態それぞれで
1回ずつのフルパイプライン巡回）、そして`setIC(0)` - これは実機のIC
（initial clear）ピンが即座のフィールドリセットではなくチップを通す、
その同じシーケンスです。このシーケンスが完了した時点で`dac_output`は
無音（`[0, 0]`）です。まだどのレジスターも書き込まれていないためです。
