# Ricoh 2A03 (`2a03`)

The NES and Famicom's sound, as the CPU had it on the same die: two pulses, a
triangle, a noise generator, and a sample channel. The method behind every section
is in [CONFORMANCE.md](../CONFORMANCE.md).

## Analog stage

Not measured, and no reference unit chosen.

| | |
| --- | --- |
| Reference unit | none chosen |
| Capture | none |
| Tolerance | not set |
| Maximum band error | not measured |
| Corners measured | not measured. Implemented: first-order high-pass at 90 Hz and 440 Hz, first-order low-pass at 14 kHz, the values nesdev gives as approximate |
| Resampling | a box filter over the CPU cycles that make up each output sample; not band-limited |

The mixer is the nesdev non-linear approximation, `95.88 / (8128 / (p1 + p2) + 100)`
for the pulses and `159.79 / (1 / (t/8227 + n/12241 + d/22638) + 100)` for the
rest. A fixed gain of 2.9 follows the filters for headroom. That gain is not
hardware and will be replaced by a calibrated level when a unit is measured.

## Driver coverage

What `packages/chipvoice/src/driver.ts` writes when it plays a note. The core
implements more than this; the rest is written from the wiki and exercised by
nothing chipvoice plays.

| Voice | Exercised | Not exercised |
| --- | --- | --- |
| Pulse 1, 2 | duty; period; constant volume rewritten per frame; length 31 with the halt flag; envelope restart and phase reset on trigger; explicit stop | envelope decay (`constant = false`); length counter expiry; the sweep unit, in either direction |
| Triangle | period; linear counter loaded at 127 with the control flag; length 31 halted; explicit stop | length or linear counter expiry; the ultrasonic mute below period 2, which is implemented |
| Noise | period index; mode; constant volume per frame; length 31 halted; envelope restart on trigger | envelope decay; length expiry |
| DMC | | everything: not implemented |
| Frame counter | 4-step mode only | 5-step mode; the frame IRQ; `$4017` write timing and the reset it causes |

## Known deviations

| What | Deliberate | Why | Affects |
| --- | --- | --- | --- |
| The DMC is not implemented; the mixer takes 0 for it | no | not built yet | every game in the corpus that uses sampled drums will diverge; the mixer's non-linearity means the other channels' levels are also slightly off whenever the DMC would have been non-zero |
| 5-step frame counter mode, the frame IRQ and `$4017` write timing are not implemented | no | no CPU, no caller | `apu_test` will fail those cases |
| The triangle powers on at step 15 (output 0); the hardware at step 0 (output 15) | yes | a held 15 at power-on is a DC step through the high-pass filters, a click at the head of every render | the initial state only; see [DECISIONS.md](../DECISIONS.md) |
| The register interface is decoded commands, not bytes: events carry `duty`, `period`, `volume`, and there are no register reads | yes | the driver is the only writer, and the fields map one to one onto `$4000` to `$400F` | the harness converts byte writes to events, or the core grows a byte port in phase 1 |
| Events are timestamped in samples, not cycles | no | history | bit-exact comparison needs a conversion; VGM export needs the same one. Phase 1 |
| Resampling is a box filter per output sample rather than band-limited step synthesis | partly | simple, fast, and the grit is wanted | aliasing on high pulse notes. Parity is measured before it; the analog sheet reports it |
| Output filters are first-order sections at the approximate corners, with no unit named, and a fixed gain of 2.9 | no | no measurement yet | the analog sheet |
| Envelope, sweep and length counters are implemented from the wiki and verified by nothing | no | the driver never uses them | unknown until the corpus and the ROMs run |

## Power-on state

`reset()` silences every voice and drops the event queue. It does not restore the
power-on state: timers, the LFSR, the frame counter and the triangle's phase keep
whatever they had. Power-on, from a fresh core: every voice disabled, the LFSR at 1
(as the hardware), the frame counter at cycle 0 of the 4-step sequence, the
triangle at step 15 (deviation above), every timer at 0.

## History

Newest first.

- 2026-09-04 · The triangle holds its last value at note off instead of dropping
  to zero. Click on every bass note gone.
- 2026-09-04 · Half frames on the second and fourth steps of the sequence, not
  the first and third. Inaudible with the shipped driver.
- 2026-09-04 · The noise channel ran at half the hardware rate: the period table
  is in CPU cycles and the timer counted at the APU rate. Every drum was an
  octave dark. Golden hash changed with it.
