# 作曲・共有・APIのレビュー

<p align="center"><a href="CREATION-API-REVIEW-2026-09-07.md">English</a> &bull; <a href="CREATION-API-REVIEW-2026-09-07_ja.md">日本語</a></p>

対象は `a0e86918e605d6818a806fbd308b8dad4338fa24`、SDK **0.16.3**。本書は実装計画の提案であり、新機能の出荷報告ではありません。PR #44の移植用音色修正に続くレビューです。人による試聴と実機端末での受け入れ確認は引き続き未完了です。

<a id="verdict"></a>
## 結論

小さく、リミックスできる音楽プレイグラウンドは、このライブラリに適した方向です。一度作曲し、実際の音源チップの制約で結果がどう変わるかを聴き、コードを調べ、そのままゲームに持ち込めることが特徴になります。作曲をデモの中心的な導線にすべきです。

既存のエンジン、正確なtickモデル、決定論的プランナーは維持します。コミュニティの作品発見機能を作る前に、ドキュメントと再生の契約を統一します。問題は公開関数の少なさではなく、コンパクトな作曲画面、完全編曲プレイヤー、SDK、公開サービスの間に重要な機能が分散していることです。

<a id="findings-to-address-first"></a>
## 優先して対処する問題

1. **公開時に新しい音楽モデルを保持できない。** `SongInput`はトラッカーのpatterns/orderを要求し、有効なSDKの`Performance`を拒否します。パート別の表情、パッチ、測定済み音色、ミックス指定も保存できません。共有のためにMIDIを4行へ平坦化してはいけません。
2. **未知の入力フィールドが黙って消える。** 有効なコンパクトスコアに`gain`、`parts`、`mix`を加えたローカル検証では、解析は成功しましたが3項目とも削除されました。これは現在のスキーマの挙動であり、対応機能ではありません。新契約は未知フィールドを拒否するか、定義した拡張として保持すべきです。旧形式の互換性は明示的に管理します。
3. **優れた再生制御がデモ内に留まる。** [LivePlayback](../apps/web/src/audio/LivePlayback.ts)は差替えとコンテキスト所有権、[BufferPlayback](../apps/web/src/audio/BufferPlayback.mjs)はシークと非同期選択、workerは準備を担当します。利用者にファイルのコピーを求めるべきではありません。`Chip.play`は再生中の同じIDを意図的に無視するため、同一IDのオブジェクト変更は汎用的なライブ編集APIになりません。
4. **入口によって音楽ポリシーが違う。** コンパクト再生は作者の音量を維持し、`planPerformance`は既定で自動ミキシングします。これは文書化された差であり、明示する必要があります。全旧スコアを新プランナーへ流すと音が変わります。移行には旧再生ポリシーと可聴回帰fixtureが必要で、型変換だけでは不十分です。
5. **公開IDは音を固定しない。** 公開音声は現行エンジンでレンダリングされます。キャッシュIDはエンジン変更を含みますが、保存曲には再現可能なエンジン・パレット・アダプター世代がありません。安定したURLと固定された音声リビジョンは別の契約です。
6. **文書が構造に追いついていない。** HTTP文書はまだ4行のテキストを説明しています。手書きのOpenAPIとZodは乖離し得ます。OpenAPIには実際のレスポンス項目や認証スキームの一部がありません。`0.1.0`が独立したAPIバージョンなら、その互換性方針を明記すべきです。SDKの中心的なAPI表は`Chip`を重視し、完全楽曲関数は別の場所で説明されています。
7. **作曲が見つけにくい。** ホームのナビゲーションはPlayground / Listening lab / Aboutです。初期表示に開発者APIへの直接導線がなく、コードは「Make a loop」→「View code」に隠れています。似たタイトルでも、完全な原曲と編集可能な旋律教材は別ドキュメントです。

<a id="the-product-to-build"></a>
## 作るべきプロダクト

同じプロジェクトを表示する**Listen、Create、Code**を、1つの楽器として提供します。公開作品には**Explore**、開発者には明確な**Docs / API**を追加します。試聴ラボは検証資料への補助導線に留め、別の独立スタジオは増やしません。

最初の画面には、再生できる例、コンソール選択、短い説明を置きます。JavaScriptでレトロ音楽を作り、エミュレートした音源で聴き、自分のプロジェクトに使えることを伝えます。「Remix this」「Use the API」を用意し、旋律・和声・ベース・ドラムを備えた編集可能なオリジナルのスターターを提供します。ゲームの元コマンド再生は参照として識別し、編集時は移植版であると明示します。

作曲画面には名前付きパート、追加・削除・複製、ピアノロール、ドラムグリッド、セクション反復とループ範囲、テンポ、移調、音色、トリム、ミュート・ソロ、Undo、復旧が必要です。複数パートが同じ役割を持てます。4役割は4トラックや4ハードウェアボイスではありません。高度なパッチ編集は展開式にします。デスクトップではコードと音符を並べ、モバイルではコンパクトな常設トランスポートの周囲で表示を切り替えます。

コード体験は、編集・検証できる音楽データと生成SDK例から始めます。手続き型JavaScriptは別の作成モードとして追加し、処理量を制限した生成器が明示的な乱数seedから同じ音楽ドキュメントを生成します。ビジュアル編集で任意のJavaScriptを逆変換できるかのように扱ってはいけません。「編集可能な音符に変換して切り離す」操作か、コードのみを原本とする方式を選びます。コンパイル失敗時は直前の再生可能な結果を保ち、エラー位置を示します。

ローカル下書きにアカウントは不要です。公開時はタイトル、帰属、可視性、リミックスリンクを持つ明示的なリビジョンを作ります。インポートは公開要求までローカルに留めます。プロフィールは一意のハンドルと別の表示名を持ち、既存アカウントIDを再利用します。旧匿名URLは読めるまま維持し、作者文字列から所有権を推定しません。将来の匿名共有には復旧・削除の権限を用意するか、ローカル下書きリンクに留めます。

索引へ入れるのは**明示的に公開した作品**であり、全インポート、自動保存、編集履歴ではありません。タイトル・作者・タグ・コンソール検索、新着、選定例、お気に入りから始めます。「今週の人気」は十分な利用と重複・自己操作への対策定義後に追加します。技術診断は再生可能性の説明であり、音楽的な好みのランキングではありません。いいね、コメント、フォロー、リアルタイム共同編集は作曲・共有の前提条件ではありません。

<a id="api-direction"></a>
## APIの方向

<a id="one-project-distinct-musical-layers"></a>
### 1つのプロジェクトと異なる音楽層

メタデータ、作成元、参照アセット、希望レンダリング設定を持つバージョン付きプロジェクト外殻を導入します。`Score`はコンパクトな作成形式、`Performance`は正確な音楽タイムラインとして維持し、第3の音符モデルを作りません。リビジョンごとに原本は1つとし、コード・トラッカー・音符の独立した編集可能コピーを持たせません。

準備済み編曲は、対象ボイス割り当て、解決済み音色、レジスターイベント、診断を含みます。原本と対象ポリシーから導出します。ネイティブのレジスター記録は別の原本種別として保持し、編集・移植を原コマンド再生と偽ってはいけません。バイナリのメモリー・サンプルアセットには明示的なシリアライズとハッシュが必要です。`JSON.stringify(Uint8Array)`では十分なファイル契約になりません。

旧Score/Songの入口は動作を維持します。トラッカーからPerformanceへのコンパイラーは、ゲート長、アルペジオ、打楽器、エンベロープ、既存ミックスポリシーの同等性テストの後に導入できます。同等性を示すまでは、共通の窓口の内部で異なる実行経路を維持できます。公開契約の統一に全合成処理の書き直しは不要です。

<a id="small-high-level-surface-advanced-access-retained"></a>
### 小さな高水準APIと高度なアクセスの維持

以下は提案する操作群であり、**既存のメソッド名ではありません**。

| 操作 | 契約 |
| --- | --- |
| 解析・検証 | 境界でunknownデータを受け取り、パス・コード・重大度付きの構造化issueを返す。音符、バイト数、長さ、アセットを制限 |
| 準備 | 原本＋対象＋明示的な移植方針から不変の準備済み編曲とレポートを生成。非同期worker、進捗、取消に対応 |
| 再生・更新 | 読込、再生、一時停止、停止、先頭へ戻る、シーク、ループ。再生意図を維持して定義した境界でテンポ・対象・パート設定を更新 |
| 観測 | 可聴音楽位置、長さ、準備・再生・エラー状態、移植診断。必要な場合は呼出側所有の作業領域 |
| レンダリング・書出し | 同じ準備済みIDからPCMとメタデータを生成。WAVや対応チップ形式への符号化は分離 |
| 機能確認 | 型付きチップID、使用可能ボイス、音色パラメーター、対応入力・出力、キャリブレーション範囲 |

まず役割、音色意図、velocity、表情、移調、テンポマップ、パートのトリム・重要度という音楽的制御を公開します。ボイス割り当て優先度とミックス重要度は分離します。ネイティブFMオペレーター、波形テーブル、サンプル・BRR設定、生レジスターは対象互換性を明示した高度なアクセスとして維持します。全レジスターを共通スライダーにしたり、不明な対象を黙ってFamicomへ置き換えたりしてはいけません。

現在`allowLoss`の既定はfalseです。SDKの厳格な既定を維持します。対話的プレビューは意図的にloss報告を許可できます。レポートはボイス欠落、未対応表情、近似音色、キャリブレーション代替、バスタイミングを区別し、安定したパート・音符IDを使います。決定論的な出力や少ない欠落は、音楽的な良さやゲーム原曲への忠実性を保証しません。

準備は音声コールバック外で行い、古いジョブを取り消し、キャッシュを制限します。テンポスライダーの各イベントで無制限に全曲レンダリングしてはいけません。即時・拍・小節のどこで更新が効くかを定義し、待機状態を公開します。音色変換の即時完了は約束しません。シークは再実行・チェックポイントで持続音、チップメモリー、エンベロープ、効果を復元し、古いnote-onを飛ばすだけにしません。ネイティブのテンポ・音高編集は、その変換を別途実装・検証しない限り移植版になります。

コンテキスト所有権、破棄、非同期resume失敗、遷移も公開契約に含めます。可聴クロックを1つに保ち、準備失敗時は最後に動作した編曲を維持します。バッファ再生とworkletストリーミングは内部戦略で構いません。ストリーミング導入は起動時間・メモリーの測定根拠に基づきます。

<a id="http-and-reproducibility"></a>
### HTTPと再現性

npm SDKはローカルで作曲・移植・再生します。HTTPサービスは公開リビジョンの保存、取得、検索、管理を担当します。音楽編集のたびにサーバーレンダリングを必須にしません。

バージョン付き公開エンドポイントと旧`/s/{id}`の読込互換ブリッジを追加します。不変のドキュメントリビジョン、原本・アセットハッシュ、エンジン、パレット・キャリブレーション・アダプターのバージョン、対象、レンダリング設定を保存します。公開プレビューは固定し、「最新版でレンダリング」は明示的な新しい音声版とします。生成器のseedとコードも保存できますが、再生には検証済み音楽データを使い、公開コードを再実行しません。

要求・応答スキーマ、OpenAPI、エージェント文書、例を同じバージョン付き契約から生成します。認証、ページング、出力パラメーター、エラー、再試行を文書化します。原本の長さとプレビューの長さは分離します。現在HTTPレンダラーは1〜30秒、SDKプランナーは最大10分です。長い公開曲には進捗・取消方針のあるキュージョブとストレージが必要で、同期制限を引き上げるだけでは不十分です。

ユーザーコード実行には、CPU・時間・出力量を制限し、アカウント認証情報を持たない破棄可能な隔離環境を使います。アプリケーションのコンテキスト内で評価しません。公開索引には明示的な可視性、削除・報告、受付制限が必要です。現在のインスタンス内レート制限はローカル限定と文書化されており、分散公開・レンダリングには共有制限が必要です。帰属と再利用宣言はライブラリのライセンスとは別に保存します。これらは提案する公開・コード機能の要件であり、現在のデータ専用エディターが未信頼コードを実行するという指摘ではありません。

<a id="review-evidence-and-limits"></a>
## レビューの根拠と限界

本番の読み取り専用確認とローカルのスキーマ・バンドル検証を実施し、公開曲やアカウントは作成していません。ブラウザーでホーム導線と読み取り専用コードパネル（編集可能フィールドは0）を確認しました。本番の`GET /api/songs`は405を返し、OpenAPI文書は200ですが一覧操作を持ちません。ローカル検証でSDKの有効なPerformanceが公開スキーマで拒否され、未知のコンパクト形式項目が削除されることを確認しました。レビュー用ワークスペースの`.artifacts/creation-api-review`に再実行用スクリプトと観測結果があります。出荷機能ではなくローカル監査資料です。

現行distを使うesbuildのブラウザー向け圧縮検証では、`importMidi`単体は**9,843バイト／gzip 4,247**、`Chip`は**316,709／98,469**、SNESの準備・レンダリングは**278,873／82,782**でした。例示的な入口バンドルであり、ネットワークや起動時間のベンチマークではありません。小さいMIDIの結果からtree shakingは既に動いています。サブパスexportがないだけで全利用者が全コアを取得すると結論づけられません。実際の利用側予算に基づいて実行入口の分割を検討します。

本レビューはAPI・製品設計が対象で、新しい音声の正確性検証ではありません。人の試聴合格、本番規模の容量、JavaScript隔離環境の完成を主張しません。従来のロードマップは完全なDAWとの競争を対象外としています。焦点を絞った作曲・リミックス環境なら、その制限を守りつつ作曲を中心機能にできます。
