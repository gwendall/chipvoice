<a id="where-this-is-going"></a>
## 目指す方向

1つのドライバー、1つの楽譜、複数のチップ。人やエージェントが読めるテキストで曲を書き、Ricoh 2A03、ゲームボーイ、メガドライブ、SNES、C64で、その機種の音源と編曲慣習に従って鳴らします。単なるシンセのプリセットではありません。

以下の3原則が順序を決めます。

**エミュレーションは既存の成果を使う。** 主要音源にはダイ写真、ネットリスト、論理キャプチャ、それに由来するコアが存在します。JavaScriptで一から解析し直すには何年もかかり、精度も落ちます。決定前からある2A03は置換せず検証します。当初の方針では以後を参照コアの移植／WebAssembly化としていました。DMGとC64での資料からの実装という後の選択は、各フェーズと決定記録に示します。

**検証シートが契約。** 一言で「サイクル精密」と称する代わりに、全チップに共通する方法で数値を出した[適合性シート](CONFORMANCE_ja.md)を公開します。シートなしでは出荷しません。

**製品の中心は移植可能な楽譜。** 価値のある難所は個別チップより、その上で役割と意図を表す[楽譜](SCORE_ja.md)と機種固有の編曲です。ブラウザゲームの作曲者、ステージ曲を書くエージェント、NES曲をメガドライブへ移す人が使う層です。

<a id="principles"></a>
## 原則

- **コアを再利用し検証する。** ダイ解析由来の系譜は検証根拠も伴います。
- **チップより先にシート。** 第2チップより前にハーネスとテンプレートを作ります。
- **抽象化より先に第2チップ。** 1例からの一般化を避けます。NESに近いGame Boyを第2例とし、楽譜設計前に`ChipSpec`を検証します。
- **50機種より5つの典型。** フレーム表、波形RAM、FM、サンプル、アナログフィルターで形を確立し、その後を追加にします。
- **毎フェーズで聴けるものを出す。** 長期間ベンチだけに閉じこもりません。
- **半完成10機種より完成2機種。** 60%で止まった大型計画を繰り返さず、維持され、資料があり、導入できるものにします。

### フェーズ0. 修復と固定

この文書を追加したコミットで完了しました。

- [x] ノイズが実機の半速でドラムが1オクターブ低かった問題を修正。`test/clock.mjs`で全ボイスの速度を式に固定。
- [x] ハーフフレームが1ステップ早かった問題を修正。既存ドライバーでは聞こえなかったため未発見でした。
- [x] ノートオフで三角波がゼロに落ちてクリックする問題を修正。
- [x] `test/golden.mjs`で固定曲のハッシュを毎push確認。
- [x] `.github/workflows/ci.yml`でpush／PRの型、ビルド、単体検査。リリースではブラウザ検査も維持。
- [x] READMEの「サイクル精密」をシートへのリンクへ変更。
- [x] 最初の`docs/chips/2a03.md`に未検証を明記。

ドラムがNESらしい音になります。E2Eは公開パッケージとサーバーの出力をバイト比較するため、パッケージ公開とデプロイが必要です。不変キャッシュの音声URLもバイトが変わります。[決定記録](DECISIONS_ja.md)の未決事項を参照してください。

<a id="phase-1-the-bench"></a>
### フェーズ1. ベンチ

最重要であり、それ自体は音を出さない段階です。

1. **チップサイクル単位のイベント。** 0.4.0で完了。`RegisterEvent.at`はサイクル数で、サンプル位置はコアが導きます。参照もVGMもサイクルを使い、フレーム単位のドライバーには影響しません。0.5.0で`$4000-$4017`へのバイト列にし、実機にできない操作を排除しました。
2. **デジタル／アナログ分離。** リサンプリング前のサイクル出力を公開し、アナログ段を名前付き独立プロファイルにします。
3. **ハーネス。** [CONFORMANCE.md](CONFORMANCE_ja.md)の`conform <chip> --corpus --oracle`で、最初の相違を修正可能な形で報告します。
4. **コーパス。** 当初案は実ゲームNSF数百曲を参照プレーヤーでログ化し、スイープ、減衰、両ノイズ、DMC、長さ満了を網羅するものです。短い20本をCIへ。
5. **ROMベンチ。** 完了。最小6502でblarggのAPU ROMを動かし全成功、CI対象。
6. **自動シート。** 数値はハーネス、文章はテンプレートに分離。

CIでNes_Snd_Emuとの比較を行い`docs/chips/2a03.md`を自動更新できれば完了です。**状態：** 実ゲームでなく独自曲と10スクリプトのコーパスという点を除き完了。古い参照のフレーム時刻と三角波開始規約が判明し、ROMで時刻はnesdev側と確定しました。エンベロープ／スイープの現代的参照は残件です。

<a id="phase-2-nes-to-100-"></a>
### フェーズ2. NESを100%へ

1. 全コーパスを実行し相違を修正。
2. DMC追加。0.6.0で完了、コアと比較に含むがドライバー未使用。サンプル打楽器はフェーズ4。
3. 5ステップ時計と`$4017`時刻を追加。ROM成功済み。
4. アナログ参照実機を選び測定しシートへ。ミキサーはblarggのNES録音に一致、フィルターはライン出力待ち。
5. パッケージREADMEとskillからシートをリンクしてリリース。

CONFORMANCE.mdの完了定義を満たせば完了です。

<a id="phase-3-game-boy"></a>
### フェーズ3. Game Boy

1. Pan Docsとblargg資料からDMG APUを実装し、SM83で`dmg_sound`を実行、Gb_Snd_Emuを初参照に。0.8.0で12/12成功。強い参照と実ゲームGBSコーパスはP3-4。
2. 波形チャンネルを根拠に楽器形状、`ChipSpec`、`RegisterEvent`、ドライバーを再設計。0.8.0でフレームを境界に各`ChipDriver`へ分離し、同じ4行を両機種で再生。
3. API公開前にハーネスからシート生成。`docs/chips/dmg.md`で完了。

同じ4行が個別ドライバーで鳴り、シートを生成できれば完了です。

<a id="phase-4-the-portable-score"></a>
### フェーズ4. 移植可能な楽譜

製品の中心で、明確な終点のない段階です。

1. [SCORE.md](SCORE_ja.md)の役割と意図。0.9.0で`Score`、`arrange`、役割別語彙を実装。
2. 役割→ボイス、意図→楽器、機種慣習のアレンジャー。0.9.0で`chips/*/arranger.ts`、`ChipSpec.roles`、`ChipDriver`として両機種に実装。
3. API／保存形式に音色を公開。0.9.0の`intent`は表でなく単語で、機種を変えても意味を保持。
4. イベントからVGM出力。0.6.0の`toVgm`とハーネスのVGM取り込みで実装。対応プレーヤーで再生可能。
5. skillと当初案のMCPに機種慣習を記し、汎用音色でなく機種らしい曲を書けるようにする。実際のエージェント支援はファイルとしてのskillです。

同じ楽譜を2A03／DMGで編曲し、APIが意図を受け、VGMが参照で再生され、skillが機種ごとの書き方を説明すれば完了です。

<a id="phase-5-mega-drive"></a>
### フェーズ5. メガドライブ

0.11.0で当初と異なる形で完了。Nuked-OPN2をWebAssemblyにせずTypeScriptへ逐行移植し、ネイティブ版を参照としました。コーパスの全スクリプト／曲がサイクル単位で一致します（決定17）。PSGはSMS Power資料から実装し参照は未導入（P5-8）。`FmPatch`を楽器に持ち、アレンジャーが単語をパッチへ対応付け、和音はPSGへ送ります。LGPL境界は明示した1ファイルです。残件はFMドラム／LFO（P5-10）、PSG参照（P5-8）、Model 1ライン出力（P5-9）。

<a id="phase-6-snes"></a>
### フェーズ6. SNES

0.12.0で同様にsnes_spcのS-DSPを逐行移植し、ネイティブ版のDSP出力と比較しました。初回からエコー／FIRを含め全ログがサンプル一致しました。BRRは実デコーダーに対し全フィルター／shiftを探索します。`Instrument.sample`はドライバーバンク内の名前、`ChipDriver.memory()`はバンク自体を表し、エコーを特徴に使います。当時の残件は複数ボイス三和音（P6-10）、SPC出力（P6-9）、実機測定（P6-8）です。現在の三和音実装は[パレット](SNES-PALETTE_ja.md)を参照してください。

<a id="phase-7-c64"></a>
### フェーズ7. C64

0.13.0でDMG同様、資料からSIDデジタル部を実装しました。GPLのreSID-fpはハーネスだけでネイティブ実行し（決定18）、全ログの各ボイス2値が一致します。6581アナログは未測定の資料由来プロファイル。4役割に3ボイスを割り当て、3番でドラムが和音を中断する規則をシーケンサーへ置きました。残件は6510上のVICEテスト（P7-7）、ライン出力（P7-8）、編曲のフィルター（P7-9）、8580（P7-10）。

<a id="phase-8-the-site-as-an-instrument"></a>
### フェーズ8. サイトを楽器にする

5チップを遊べるデモの材料にします。[DEMO.md](DEMO_ja.md)にV1と受け入れ条件を定義し、監査と議論を受けた決定20で19を更新します。

この節を書いた時点では`feat/playable-demo`実装済みでレビュー／デプロイ待ちでした。評価報告には完了検査と実機の後続確認を記録しています。最新状態はバックログを参照してください。

楽譜全体保持、Stop／SFX時の予約キャンセルを修復し、3プリセット、明示Play、位置保持の5機種選択、反応する4レーン、4パッドを実装します。簡単な編集、音色、Undo、下書き復元、共有、実行例で体験を完結し、セッション内だけの利用数を測定します。

既存コアとフレームワークを維持し、耳で必要な統合を直します。ライブ録音、制御可能な変奏、MIDI、ステム、豊かな編曲はV1後であり、初期デモ完成の前提ではありません。

<a id="not-on-the-roadmap"></a>
## ロードマップに含めないもの

- **全システムエミュレーション。** 配布ライブラリはCPU、ROM、映像を扱いません。他プロジェクトに任せ、音楽ツールに必要なチップとドライバーを作ります。検証ハーネスのCPUは別です。
- **BeepBox、FamiStudio、Furnaceとの編集機能競争。** デモはDEMO.mdの手軽なループ編集／リミックスを提供し、完全なDAWにはしません。
- **シリコンの再解析。** 第1原則を参照。
- **5典型完成前の多数のアーケードチップ。**
