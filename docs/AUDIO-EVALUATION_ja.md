# ゲーム機ごとの楽曲を評価する

<p align="center">
  <a href="AUDIO-EVALUATION.md">English</a> &bull;
  <a href="AUDIO-EVALUATION_ja.md">日本語</a>
</p>


エミュレーターのテスト合格は良い編曲を意味しません。**デジタルの正しさ**、**信号の健全性**、**音楽的な似方**を分けます。試聴ラボは似せた別の固定入力ではなく、実デモのプリセットをレンダーし、保存済み楽譜も受け付けます。

<a id="reproduce-and-compare"></a>
## 再現と比較

リポジトリ直下で実行します。Node 22、pnpm、C++コンパイラーが必要で、FFmpegは任意です。

```sh
pnpm --filter chipvoice build
pnpm --filter chipvoice-conform test:listening
pnpm --filter chipvoice-web eval:audio --out .artifacts/listening/before
# 1つ変更してchipvoiceを再ビルドし、次を実行：
pnpm --filter chipvoice-web eval:audio --out .artifacts/listening/after --baseline .artifacts/listening/before/report.json
python3 -m http.server 3041 --bind 127.0.0.1 --directory .artifacts/listening/after
```

`http://127.0.0.1:3041`を開きます。生成器へ渡すパスはリポジトリ直下から解決します。既存レポートは置換できないので、実行ごとに新しい出力先を使います。生成ディレクトリは自己完結し、外部要求を行いません。

オプションは`--chips snes`（またはカンマ区切りの`2a03,dmg,md,snes,c64`）、`--preset overworld`、`--seconds 5`、`--mix-only`、`--skip-oracle`、`--scores path/to/score.json`。楽譜ファイルは1つの`Score`か`{id,title,song}`の配列です。既定は全ループで上限180秒。切り詰めた抜粋はレポートで明記し、公開時に拒否します。

レポートはミックスと4分離役割の16ビット・ステレオWAV、楽譜、波形包絡線、平均スペクトル、WAV clamp前の測定を含みます。実際のビルド済みエンジン、プリセット束、ハーネス、参照ソース、楽譜、WAVをハッシュで識別し、Git改訂と作業差分のダイジェストで未コミット状態も記録します。測るのは**ビルド済み**エンジンなので先に再ビルドし、共有証拠にソース改訂／パッチを付けます。

`--baseline`は旧WAVハッシュを検証し、楽譜と長さが一致するケースだけを付けます。サンプルレート違いは拒否します。固定入力でエンジン／編曲器の変更を比べるためのものです。曲の書き直しは両レポートを保ち、楽譜変更として明示的に判断し、エンジン回帰試験と呼びません。旧版にないケースには版比較を付けません。

<a id="what-each-check-establishes"></a>
## 各検査が確かめること

- **親しみのある曲の原典旋律：** 楽譜を独立に復号し、全5役割マップで実シーケンサーのnote sinkを観測します。固定MIDI台帳と音高、開始／解放、欠落／余分な音、全形式、想定外伴奏を比較します。選択415音は音高許容差なし、境界はグリッド丸めの最大1/24拍です。ドライバー／DSP前の採譜を検証するのであって、元ゲームの録音ではありません。[原典、範囲、改変テスト](../scores/README_ja.md)を参照。
- **全5機種の取得再生：** 取得した書込とメモリーを新しいチップへ再生し、オフラインPCMとサンプルごとに比較します（絶対許容差`1e-7`）。予約／取得の不整合を捕らえますが、両側が自分のエンジンなので独立した実機参照ではありません。
- **実楽曲のSNESネイティブ参照：** 同じレジスターとRAMを同梱のネイティブ`snes_spc 0.9.0`へ通し、全デジタル変化のサイクル、チャンネル、整数値を比較します。TypeScript移植と祖先は同じなので、独立した実行ではあっても、独立設計のエミュレーターや実機測定ではありません。既存の適合性ログも実行します。
- **信号測定：** RMS、DC、ピーク、クレスト、不正／クリップサンプル、ステレオcosine。FFmpegの[loudnorm](https://ffmpeg.org/ffmpeg-filters.html#loudnorm)があれば統合LUFSとtrue peakも測ります。信号を説明するもので、機種らしさではありません。短いループのラウドネスレンジの意味は限定的で、隣接サンプル差が非0でも自動的にクリックとは限りません。
- **SNES内部の余裕：** オフライン観測器が、既存DSPのclamp前に符号付き16ビットを超えるdry／echo入力の声加算を数えます。移植のprivateメソッドを包むので構造変更時に更新します。音声や本番再生には手を加えず、観測インスタンスでも参照一致を試します。BRR、補間、FIR、エコーフィードバックなど全飽和段を計器化するものではありません。

`technicalPass`は取得再生、任意のネイティブ参照、有限PCMが合格したことです。`signalWarnings`は別で、過大ミックスを正しく再現しても一致には合格します。既定SNES回帰はdry／echo入力の飽和を拒否し、故意の過負荷レジスターで観測器が検知することも示します。測定試験では無音、音高／ゲイン変更、不正PCM、ステレオ打ち消しも故意に導入します。「本物らしさの点数」は生成しません。

<a id="listening-protocol"></a>
## 試聴手順

1. 楽譜、テンポ、時間、レンダー設定、試聴機器を固定します。ミックスから始め、問題の役割を分離します。分離は楽譜を再レンダーし、声や非線形段が相互作用するため、ステムの和がミックスになるとは限りません。
2. 現在／旧版を1音声時計で比較します。**両方**にLUFSがあればそれを、なければ両方に概略のRMSを使います。静かな側と-23 LUFS／-26 dBFS RMSの低い方まで減衰し、増幅はしません。WAVは変更しません。
3. 「Masquer et tirer au sort」（隠してランダム化）でA/Bを聞き、正体を明かす前に観察を保存します。両方を連続再生し、切替のゲイン時定数5 msでクリックを抑えます。探索的な好みの試験で、統計的に認証されたABXや[ITU-R BS.1116](https://www.itu.int/rec/R-REC-BS.1116-3-201502-I/en)準拠ではありません。
4. 隠れた対応表とWAVハッシュ付きでメモを出力します。正確な音符、楽器、時刻を記し、音色の似方、聞こえる欠陥、好みを分けます。メモは出力までメモリー内にあり、遠隔保存しません。
5. スタイルは「SNESの音」1つではなく機種ごとに複数の明示参照を選びます。望むアタック、持続／ループ、包絡線、音高／ビブラート、低音／ドラム比、同時発音、空間を説明し、正当にアクセスできる録音を使います。別のゲーム曲と本楽譜をnull testできないので、試聴と音楽分析が必要です。

SNESネイティブWAVは32 kHzの生DSPで、仮の出力フィルターを通りません。ブラウザーのリサンプリングとフィルター差は聞こえることがあります。開始は同じタイムラインですがフィルター遅延を補償しません。修正の判断には**旧版**を優先し、ネイティブA/BだけでDSP欠陥を証明しません。

SNES基準を持つ変更後レポートへブラウザー検証を実行します。

```sh
node packages/conform/src/listening/test-browser.mjs http://127.0.0.1:3041 .artifacts/listening/browser
```

非無音の出力、共通A/B開始、ソース切替、匿名／公開、メモ出力、ステムとネイティブ再生、PC／モバイル画像を検査します。人の好みは評価しません。

<a id="initial-investigation-2026-09-06"></a>
## 初回調査、2026-09-06

3プリセット×5機種は15件すべて取得再生が一致し、SNES全3ループもネイティブ`snes_spc`と完全一致しました。それでもドライバーが最大音量を`$7f`へ写していたため、大きいサンプルの和がマスター減衰**前**にクリップしていました。最終PCMはフルスケールを超えず、WAVだけの検査では歪みを見逃しました。

| SNESループ | 修正前のdryミックス・クリップフレーム* | 修正後* | LUFSの前 → 後 |
| --- | ---: | ---: | ---: |
| Overworld | 19.68% | 0% | -6.15 → -17.43 |
| Boss Fight | 12.65% | 0% | -6.79 → -17.84 |
| Midnight | 15.50% | 0% | -6.83 → -18.13 |

\* どちらかのチャンネルで、少なくとも1回の声加算オーバーフローを含む32クロック窓。修正後はdryとecho入力の両カウンターが0です。初回修正では最大音量を`$20`へ写し、4役割の余裕を残しました。DSPの飽和動作は保ちます。8つの独自フルスケール声や別サンプル／エコー設定でも余裕を保証するものではありません。修正3曲と既存SNESログ5個でネイティブ一致は維持します。SNESハッシュは意図的に`5b2fe9e2f23e1872…`から`6b32dac1405316d1…`へ変更し、他4チップは不変です。

第2の欠陥は`recordSong`で、最終レンダーブロックの先頭へstopを書いていました。停止前に時計を要求終了時へ合わせ、早いnote-offを防ぎます。0.31秒のSNES取得で保持音回帰は修正前に0.280204秒で失敗し、今は全5機種で全長の正確な再生が通ります。この取得修正自体はライブ音を変えません。

**後続改善：** 独自のビルド時BRRパレット、系統別の実機包絡線、同時和音はPR #24/#25で実装済みです。ドライバーは現在`$1f`と共有和音振幅予算、控えめなステレオ配置を使います。[パレットの基準と測定](SNES-PALETTE_ja.md)に検査、試聴反復、レビュー修正を記録します。

**未完了：** 選んだ機種別音楽参照との試聴と、SNESライン出力によるアナログ測定です。この調査も参照一致も、その音楽／実機の問いには決着を付けません。

<a id="public-listening-room"></a>
## 公開試聴室

`/lab`はサイトの共通操作で版付き評価集を公開します。音声は必要時だけ読むロスレスFLACです。単独レポートと公開ラボは同じ連続A/B制御を共有し、選択変更で再生意図を保ち、読込中は旧音を続け、新ループ位相へクロスフェードします。[公開と再生の設計](CONTINUOUS-PLAYBACK-LAB_ja.md)を参照してください。

長い旋律の集合は6カートリッジ×5機種の30ケースです。オフライン出力を楽曲時刻0から始め、全ループの終わりを保ちます。レジスター取得はWAVと同じサンプル丸めの終点と、コアの取消可能イベント列を使います。最後の音、44.1／48 kHzで端数サンプルとなるループ、休符後に古い解放を取り消す短音を回帰で検査します。取得再生の証拠を信頼可能にする修正であり、原曲の忠実さを主張するものではありません。

## 完全な多声編曲

[編曲の手順](../scores/arrangements/README_ja.md)は、独立した原典音符／命令の証拠、決定的な機種割当、レジスター取引の検証、完全PCMの公開を分けます。[検証済み集合とレビュー](evals/COMPLETE-ARRANGEMENTS-2026-09-06_ja.md)を参照してください。この段階の公開デッキは`/lab/arrangements`に置かれ、参照と採譜のラベルは意図的に異なる証拠範囲を持ちます。
