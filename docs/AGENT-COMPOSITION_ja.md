# エージェントによる作曲

<p align="center"><a href="AGENT-COMPOSITION.md">English</a> &bull; <a href="AGENT-COMPOSITION_ja.md">日本語</a></p>

Chipvoiceではメロディーだけでなく、曲全体の編曲を扱えます。独立した楽器、和音、正確なタイミングには、`Performance`をソースとするバージョン付き`MusicProject`を使います。[エージェントスキル](https://chipvoice.dev/skill.md)が実行可能な入口で、[llms.txt](https://chipvoice.dev/llms.txt)は短い案内です。従来のトラッカー形式は別の互換経路として残ります。

<a id="discover-the-actual-engine"></a>

## 実際のエンジンを確認する

対象を選ぶ前に[機能カタログ](https://chipvoice.dev/api/v1/capabilities)を取得してください。エンジンのバージョン、プロジェクトのスキーマ、ボイス、割り当て時の競合、Performanceで使えないボイス、同じ音色になるプログラムのグループを収録しています。General MIDIプログラム番号は**0始まり**の0〜127です。汎用音色は近似であり、ゲームの元の音色バンクやリアルなオーケストラを再現する保証ではありません。

プログラムと役割ごとの`voices`には、割り当て可能なボイスと音色を維持できるかどうかが示されます。PSGへの代替割り当てではFM音色が置き換わることがあります。`pitchHz`は変調前のレジスター上の音域です。`null`は不明を意味します。`voiceConflicts`は同じ時間帯に使えない異なるIDの組です。ボイスの単純な合計を、あらゆる編成で使える同時発音数と解釈しないでください。個別の編曲が収まるかはレンダリングと診断で確認します。

JSONとスキルの表は、現在のプロジェクト対象、`ChipSpec`、`performanceInstrument`、`performanceVoices`、`instrumentFitsVoice`、`pitchRange`から生成します。内部ヘルパーのビルド時インポートは意図的なもので、新しい公開SDK APIではありません。機種の仕様を別の手書き表に複製しません。コンテンツハッシュは機能文書を識別し、音声やゲーム原音を識別するものではありません。

<a id="compose-parts-then-allocate-voices"></a>

## パートを作曲し、ボイスに割り当てる

**パート**はメロディー、弦、ベースなどの音楽的な声部です。**ボイス**は物理的な発音資源です。同じ役割のパートを複数持てます。三和音は同時に三つのボイスを使い、メロディーとベースを加えると打楽器の前に五つ必要です。交互に鳴らすなら、曲全体の楽器数は同時発音数を超えられます。

オリジナル曲では、雰囲気、調性、テンポ、フレーズ構成、前景を決めます。覚えやすい動機と応答を作り、セクションごとに編成を変え、終止またはループを意図的に設計します。ベース、対旋律、打楽器は必要な場合に加えます。休符を残し、すべての旋律の重複、低音域の密集和音、全音符の最大ベロシティを避けます。これは出発点であり、ジャンルに依存しない品質スコアではありません。

`priority`はボイス割り当てで音符を保護します。高い値が優先され、先に始まった持続音にも影響します。音量設定ではありません。`mix.importance`は0〜1の存在感、`mix.gainDb`は作者の音量補正、ベロシティは音符の表情です。自動ミックスは利用可能な校正値を使い、保守的な代替処理を診断に記録します。どんな編曲も良い音にできるわけではなく、ハードウェアの振幅制御の制限も超えられません。

小さな機種では、重複を減らし、伴奏とフィルを交互に鳴らし、二音の和声や時間を指定したアルペジオに明示的に編曲します。Performanceの割り当て器は**アルペジオを自動作曲しません**。標準ソースを保ち、対象別の縮約を別文書に保存して変更を説明します。既存曲では確認できた声部だけを追加してください。MIDIは元ゲームの楽器の証明ではありません。

<a id="run-an-original-ensemble"></a>

## オリジナルの合奏を実行する

新しいディレクトリに`chipvoice`をインストールし、[compose-project.mjs](examples/compose-project.mjs)をコピーして、カタログの対象IDを指定し`node compose-project.mjs TARGET`を実行します。同じ実行可能コードがスキルにも掲載されています。八小節・六パートのオリジナル室内楽風テーマを`project.json`に保存し、`preview.wav`と`evaluation.json`を生成します。オーケストラ的な編成ですが、汎用音色は合成音です。

例では四分音符あたり480ティック、拍あたり500000マイクロ秒（120 BPM）を使います。終了ティックは区間に含めません。メロディー、三和音の弦、金管のアクセント、後半の対旋律、ベース、打楽器が含まれます。強弱、フレーズの変化、休符は明示的に作曲され、公開処理は行いません。

試聴用に`allowLoss`を有効にしています。共有前に必ずレポートを読んでください。`allowLoss=false`なら音符の省略でレンダリングが失敗しますが、音色の置き換えなどは別途確認が必要です。対象を動的に選んで再レンダリングし、結果を比較します。拒否された編曲を通すだけの目的で損失許可を有効にしないでください。

<a id="evaluate-before-sharing"></a>

## 共有前に評価する

1. `validateProject`またはHTTPの`/api/v1/validate`で構造と意味を検証します。
2. NodeやWorkerでは`renderProject`、ブラウザーでは`prepareProject`を使います。損失とミックス診断を読み、正確なソース、エンジン、サンプルレートと一緒に保存します。
3. パート別に省略を数えます。通常、メロディーの欠落は弦の重複音の欠落より重大です。音域、音色の代替、未校正ミックスを確認し、理由のある変更を一つずつ加えます。
4. PCMの有限値、RMS、クリッピング、長さ、密集区間、リリース、ループ境界を確認します。同じエンジンとサンプルレートでは同じ入力が同じバイト列になるべきです。異なる機種では異なる音になるのが正常です。
5. 全体と各パートを聴きます。数値計測しかできない場合は、その限界を明記します。決定性やスキーマの正しさだけでは音楽的な良さを証明できません。
6. 承認できる編曲だけを公開し、出典と対象別の縮約を説明します。ゲーム原音への忠実性には、独立して識別されたネイティブ参照も必要です。

HTTPジョブの応答には状態、進捗、固定された音声URLが含まれますが、ローカルの編曲・ミックスレポートは現在含まれません。別途保存してください。ネイティブ再生、キャンセル、音声保存、資源制限は[作成契約](CREATION_ja.md)を参照してください。

<a id="http-requests-and-tool-discovery"></a>

## HTTPリクエストとツール検出

`POST /api/v1/validate`は**プロジェクトそのもの**を受け取ります。`POST /api/v1/projects`は`{project, visibility, parentId?}`を受け取り、Bearerまたはセッション認証と`Idempotency-Key`ヘッダーが必要です。同一リクエストの再試行には同じキーを保持し、ソース、公開範囲、親を変更したら新しいリビジョンとキーを使います。preview/fullジョブを開始して適度な間隔で確認し、failed/cancelledで停止し、ready後にダウンロードします。`Retry-After`に従います。競合時に無条件で別の公開物を作ってはいけません。

[OpenAPI](https://chipvoice.dev/.well-known/openapi.json)には正確な要求・応答があります。歴史的な`/.well-known/mcp.json`は**HTTPツール検出マニフェスト**であり、実装されたJSON-RPC MCPサーバーではありません。バージョン0.2.0では`path`、`query`、`headers`、`body`を分離し、本文スキーマ全体を保ちます。アダプターは各値を正しい場所へ渡し、認証を別に設定する必要があります。これにより、冪等性ヘッダーがプロジェクトのフィールドになったり、検証に余分なラッパーを送ったりする誤りを防ぎます。

匿名公開とMP3リンクは従来の`/api/songs`だけで利用できます。完全なプロジェクトの公開にはアカウントが必要で、生成済みWAVのバイト列を固定します。秘密情報をGitに登録せず、他の作者の保存されたジェネレーターを実行せず、ソフトウェアのライセンスをインポート曲の再公開許可と見なさないでください。

<a id="adding-another-console"></a>

## 新しいコンソールを追加する

まず対象のエンジン、ドライバー、音色と資源の規則、プロジェクトスキーマへの登録を実装・検証します。`projectCapabilities()`がプロジェクトAPIの対応対象を決めます。低水準チップの登録だけでは完全なプロジェクトへの対応を約束しません。

対象がこの一覧に加われば、カタログ、スキルのボイス表、検出API、評価ループに自動的に含まれます。不明な音域は不明と表示します。ハードウェアに新しい規則が必要ならエンジン側のヘルパーを拡張し、文書だけに例外を書かないでください。独自の挙動に対する参照・音声検証と音楽フィクスチャーも追加します。`test-agent-guide.mjs`の仮想追加対象は文書の動的検出を確認するもので、未実装エミュレーターの認証ではありません。

例や指示の変更時には実行可能文書テストを再実行します。配信されたスキルからJavaScriptを抽出し、実装内部を参照せずに実行し、使い捨てデータベースに対してHTTP要求を行い、公開と固定音声を検証します。過負荷の報告と明示的な縮約も別ケースで確認します。これは決定的なエージェント作業の予行演習であり、独立した言語モデルのベンチマークや主観的音楽品質の証明ではありません。
