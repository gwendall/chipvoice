# アーティストとエージェント

<p align="center"><a href="ARTISTS-AND-AGENTS.md">English</a> &bull; <a href="ARTISTS-AND-AGENTS_ja.md">日本語</a></p>

承認された作業順序に沿って、アーティスト単位のエージェント認証、公開前の評価、完全な音声の共有、コンソール別バージョンの比較、オリジナルのピクセルアバターを提供します。所有権は人間のアカウントに残ります。所有者のいない自律アカウントは今回の対象外です。

<a id="identity-and-permissions"></a>
## ID とアクセス権

ひとつの所有者アカウントで最大 20 個のアーティストプロフィールを管理できます。既存の ID、ユーザー名、公開作品を保持します。アーティストごとのメールアドレスは不要です。`/library` でプロフィール、アバター、アクセス権を管理し、`/connect` でエージェントの要求を確認します。

メールでは 30 分間有効な一度限りのログインリンクだけを送ります。従来の `POST /api/keys` もログインリンクを送り、永続キーを作成・送信しません。既存の所有者キーは取り消すまで利用できます。エージェントは所有者のメールやブラウザセッションではなく、専用の `cv_agent_` 認証情報を使います。

[RFC 8628](https://www.rfc-editor.org/rfc/rfc8628.html) を参考にした独自 JSON API であり、**OAuth の実装ではありません**。

1. `{label, scopes}` を `POST /api/v1/agent-requests` に送ると、秘密の `requestToken`、公開用 `userCode`、`verificationUrl`、`expiresIn:600`、`interval:5` を返します。
2. 所有者がリンクを開いてログインします。必要なら認証リンクを再度開きます。開くだけでは許可されません。アーティストとアクセス権を確認し、1、7、30 日の期間を選んで承認するか拒否します。
3. エージェントは `{requestToken}` を `POST /api/v1/agent-requests/token` に 5 秒以上の間隔で送信します。`Retry-After` に従います。pending は通常の待機状態です。denied、expired、consumed なら終了します。承認されたトークンは一度だけ返ります。受信に失敗した場合は認証をやり直します。
4. `GET /api/v1/agent` はプロフィール、アクセス権、有効期限を返します。`GET /api/v1/profile` はアーティストページと SVG アバターの URL を含みます。`/api/v1/agents` の一覧・取り消しは所有者のブラウザセッション限定です。

| スコープ | 許可 |
| --- | --- |
| `projects:read` | 閲覧可能な曲を読み、許可されたアーティストの非公開曲だけにアクセス |
| `projects:write` | そのアーティストの曲を公開・取り下げ |
| `render` | そのアーティストの音声処理を要求・キャンセル |
| `evaluate` | 公開せずにプロジェクトを評価 |
| `profile:write` | そのアーティストのユーザー名、表示名、紹介、アバターを編集 |

エージェントは従来のアカウント・公開 API、他のアーティスト、お気に入り、通報、追加の認証許可を操作できません。無効な認証情報がブラウザセッションや匿名公開に置き換わることはありません。利用枠はアカウント内で共有します。有効な認証情報は所有者ごとに最大 100 個です。管理一覧では有効なアクセスを最近の無効な履歴より先に表示します。取り消しや期限切れは以後のリクエストを拒否しますが、許可済みの処理は完了する場合があります。公開プロフィールには所有者のメールや内部アカウント ID を含めません。秘密情報はハッシュのみを保存します。

<a id="evaluate-before-publishing"></a>
## 公開前の評価

`POST /api/v1/evaluate` は `/api/v1/validate` と同じ生の MusicProject JSON を受け取ります。SDK のインストールは不要で、作品を保存せず、制限付きワーカーで処理します。匿名でも評価でき、エージェントには `evaluate` スコープが必要です。

結果にはエンジンのバージョンとレンダラーの識別値、全体の長さ、音符数、全体の割り当て損失、ミックスのレポートを含みます。ピーク、RMS、クリップ数は 44100 Hz で生成した最初の 2 秒だけを測定します。残りの音声、音楽的な品質、原曲への忠実度を保証しません。ネイティブのレジスタソースには音符台帳がない場合があり、Score は作者のミックスを保持します。厳密な設定ではボイス不足を拒否します。`allowLoss:true` は明示的に音楽的損失を受け入れる設定であり、自動修復ではありません。

上限はリクエスト 4 MB、所有者ごとに毎分 6 回（匿名は IP 単位）、ワーカーヒープ 256 MB、処理時間 30 秒です。データベースの排他制御で評価と公開音声処理を直列化します。混雑時は 429 を返すので `Retry-After` に従ってください。ワーカーを終了してから処理枠を解放します。

<a id="publication-audio-and-variants"></a>
## 公開、音声、バージョン

`Idempotency-Key` を付けて `{project, visibility, profileId?, parentId?}` を `/api/v1/projects` に送ります。プロフィール省略時は所有者の標準アーティスト、またはエージェントに許可されたアーティストを使います。同じキーでアーティスト、ソース、設定、公開範囲、親が異なる場合は 409 です。公開リビジョンは不変です。

音声ジョブは WAV と MP3 を固定して保存します。完了時は `wavUrl`、`mp3Url`、`pageUrl`、`coverUrl` を返し、MP3 に曲名、アーティスト、作品リンクを含めます。チャットツールは `mp3Url` をダウンロードして添付できます。URL を返すだけでは添付にはなりません。

古い WAV だけのジョブは、同じレンダー種別を再度 POST すると保存済み PCM から MP3 を作成します。`mp3Status` を確認してください。WAV と元のエンジン識別値は変えません。変換エラーは `mp3Error` に表示し、WAV は壊しません。プレビューは最大 30 秒です。全曲の書き出しには従来どおり WAV 40 MB、処理 240 秒の上限があります。

`variants` は同一アーティストの、正規化したソースが完全一致する曲のコンソール別最新バージョンを返します。対象コンソールの設定や表示用情報はソースの同一性を変えません。音楽ソースが違えば別の曲です。作品ページで各版に移動でき、Explore は `group=1` で同一曲をまとめます。検索・コンソールの条件を先に適用し、ページ送りは固定スナップショットを保ちます。非公開・限定公開の別版は匿名の検索から隠します。限定公開リンクを直接開いた場合は、その版と公開済みの別版を表示できます。お気に入りは個別の公開リビジョンに属します。

<a id="original-portraits"></a>
## オリジナルのアバター

`PUT /api/v1/profile` と所有者用の `PUT /api/v1/profiles/{id}` は `avatar:{palette,variant}` に対応します。配色は 0–3、バリエーションは 0–15、`null` は元のアバターです。初期値では既存の見た目を保持します。公開プロフィール ID からローカルで SVG を作り、外部アバターサービス、画像アップロード、個人情報、秘密のシードは使いません。公開ページと PNG カバーも同じ描画を使います。エディターの公開パネルでは、曲の元のクレジットと独立して公開アーティストを選べます。

<a id="verification"></a>
## 検証

`apps/web/test-artists.mjs` は使い捨てデータベースと本番ビルドの Next サーバーを使います。実ブラウザでの承認、アバター変更、権限制限・期限切れ・取り消し、旧 API の拒否、別アーティストの非公開曲、決定的な HTTP 評価、秘密の別版を漏らさないグループ化、MP3 のデコード、WAV を保持した変換、英語・日本語のモバイル画面を検証します。既存のアカウント、公開、音声、エージェントガイドのテストも必須です。

`pnpm --filter chipvoice-web build` の後に `pnpm --filter chipvoice-web test` を実行します。スクリーンショットは `.artifacts/artist-lifecycle/` に保存します。本番データの作成や実メールの送信でテストしないでください。

<a id="human-sign-in-and-mail-operations"></a>
## 人間向けログインとメール運用

ヘッダーには、未ログイン時は `/signin` へのリンク、ログイン後は `/library` を開く既定アーティストのピクセルアバターを表示します。`AccountLink` は、プロフィールや曲カードと共通の `PixelAvatar` を再利用します。未ログインでプロンプトを編集すると、生成前にメールフォームが表示されます。編集と再生にはログインが不要です。プロンプトと長さは端末のローカルストレージに保存されます。メールリンクを別タブで開いても下書きが復元され、元のタブに戻るとログイン状態が更新されます。ログイン後に生成を自動実行することはありません。リンクは30分間有効で、1回のみ使用できます。期限切れの場合は再送信フォームを表示します。英語と日本語で同じ機能を提供します。

`useSession` はコンポーネント間で1つの本人情報リクエストを共有します。軽量な `GET /api/auth/session` は本人情報と既定アバターのみを返し、曲や API キーを読み込みません。`sessionStorage` の表示用キャッシュは5分間有効で、画面遷移や再読み込み後も利用します。同じリビジョンで24時間以内の古い情報は、バックグラウンドで再検証する間も表示できます。実際の認証情報は HttpOnly Cookie に保持し、保護された API は各操作を毎回認証します。別の秘密ではないリビジョン Cookie はログイン時に更新、ログアウト時に削除されますが、認証には使えません。フォーカス・表示状態の確認でアカウント変更を検出し、タブ間の通知と `chipvoice-session` イベントでログアウトやプロフィール編集を即時に反映します。通知に本人情報やトークンは含みません。遅延した応答が以前のアカウントを復元することはありません。共有パネルの曲一覧とキーは、パネルを開いたときに読み込みます。

`test-session-cache.mjs`、`test-session-browser.mjs`、`test-auth-http.mjs` は、リクエストの重複排除、再読み込み・フォーカス時の再利用、古いキャッシュ、障害、遅延応答、アカウント切り替え、タブ間ログアウト、実 Cookie による認証と無効化を検証します。`.artifacts/session/` に保存するスクリーンショットでは、英語・日本語のヘッダーと、モバイルの44ピクセルのアカウント操作領域を確認します。

アバターには共通の `Thumbnail` 枠を使います。データが届く前から寸法、縦横比、縮まないレイアウト、落ち着いた背景色を確保します。`PixelAvatar` の ID を省略すると、同じ寸法の空の枠を表示します。ヘッダーとライブラリ・プロフィール見出しは読み込み中も枠を維持し、ライブラリは共有セッションのアバターを再利用します。枠のスタイルは全ページ共通なので、画面遷移でアバターの枠線が変わりません。`test-avatar-layout.mjs` は本人情報の応答を遅らせ、デスクトップ・モバイル・日本語画面で読み込み前後の枠、見出し、ナビゲーションの位置と寸法が同じことを検証します。画像と測定値は `.artifacts/session/avatar-layout/` に保存します。

メールには公式 `domani` SDK、`DOMANI_API_KEY`、`CHIPVOICE_MAIL_FROM`（既定値 `hello@chipvoice.dev`）を使います。ローカルの `.env.local` と Vercel 本番環境にサーバー専用の秘密情報として設定してください。本番環境変数の変更後は再デプロイが必要です。メールボックス限定の専用トークンを使い、所有者の無制限 CLI 認証情報をアプリにコピーしないでください。更新時は有効期限も確認します。2026年9月に設定した本番メールトークンの期限は2027年9月1日です。`DOMANI_BASE_URL` は管理下のテスト用プロバイダー向けで、本番は既定の `https://domani.run` を使用します。

ログイン API の HTTP 202 はプロバイダーによる受付を示し、受信トレイへの到着を保証しません。以前は無効なキーにより本番で503が返っていました。同じトークンで対象メールボックスにアクセスし、ステータスとコードを確認して、無効なキーを更新してください。ログにプロバイダーの本文、メールアドレス、ログインリンクは出力しません。送信失敗時は成功と表示せず、再試行できます。

`test-onboarding.mjs` は一時データベースとローカルメールプロバイダーを使い、Next の実ルート、SDK の HTTP 通信、メールの取得、1回限りのログイン、別タブの下書き復元、非公開曲の生成、失敗と再試行、安全な戻り先、日本語モバイル画面を検証します。通常のウェブテストに含まれ、スクリーンショットは `.artifacts/onboarding/` に保存されます。別途承認された本番確認では、アプリ管理のメールボックスで実際の受信とその新しいリンクによるログインを確認してください。モックの成功から配信成功を推測したり、無関係なメールを読んだり、他人にテストメールを送ったりしないでください。

別途承認された本番確認は `apps/web` から、キーを表示せずに `CHIPVOICE_EVAL_PRODUCTION=1 node --env-file=.env.local scripts/eval-human-signin.mjs` で実行します。転送設定のあるメールボックスでは実行を拒否し、`hello@chipvoice.dev` に新着した該当メールのみを読みます。10秒の非公開曲の生成とMP3のデコードを確認してから、テスト曲を取り下げ、そのテストのセッションのみを無効にします。CIでは実行しません。
