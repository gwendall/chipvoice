# 連続再生と公開試聴ラボ

<p align="center">
  <a href="CONTINUOUS-PLAYBACK-LAB.md">English</a> &bull;
  <a href="CONTINUOUS-PLAYBACK-LAB_ja.md">日本語</a>
</p>


デモと試聴ラボは、持続する再生意図を共有します。テンポ、楽器、楽譜、機種の編集では旧音を続けたまま新音を準備し、楽曲位相を保って音声時計上で短くクロスフェードします。Stopは保留中の読込より優先します。連続編集はまとめ、古い処理が後から上書きできないようにし、ライブ切替のチップは最大2個とします。録音はそのテイクの伴奏を保ちます。

公開`/lab`はサイトの紙、機材、ディスプレイのパレットと、ナビゲーション、機種選択、ボタン、パネルを共有します。版を明記した評価スナップショットとして、3プリセット、5機種、役割分離、音量同期A/B、ネイティブSNES参照、比較対象の匿名化、観察、ダウンロードを公開します。読込時に高価な適合性検査やレンダーを走らせず、過去の証拠を現在のCIと扱いません。音声は必要時に読みます。共有状態を小さな部品カタログで記載し、Storybookは部品群が大きくなり追加ツールが役立つまで延期します。

ローカル評価コマンドを作成と検証の原点に保ち、単独プレイヤーも選択変更で再生を継続します。公開時に原典ハッシュと技術検査を確認し、ロスレス圧縮と重複排除を行い、出所を記録します。CIでは音声コーパスを再生成しません。

検証では、修正前にテンポ変更による停止とラボ選択のリセットを再現します。連続更新、読込中の停止、失敗、ミュート／ソロ、効果音、録音を試し、持続音の固定入力で音声時計上の切替欠落を測り、小数ステップを含む位相を確認します。オフラインのゴールデンを保ち、PC／モバイル画像とキー操作を見て、本番ビルドをテスト・レビューし、可能なら1PRで公開します。

<a id="implementation-and-publication"></a>
## 実装と公開

`LivePlayback`が安定した出力を所有し、チップの引継ぎを直列化します。`Chip.phaseAt`は聞こえる再生位置を進めず予約済み小数位置を読み、`Chip.play(song, position, at)`が同じ時計へ新エンジンを予約します。初期化中は旧エンジンを鳴らし、60 msフェード後に破棄します。シーケンサーは経過済み打楽器を飛ばし、SIDの共有和音／ドラム区間も含め16分音符の残り割合を考慮します。

`BufferPlayback`はReactラボと生成する単独レポートで共有します。デコード済みキャッシュは最大8録音。読込を中断でき、古い結果は捨て、置換失敗では現在の音を保ちます。ペア変更は正規化したループ位相を保持し、A/Bを同時に始めます。`Fade`が両モジュールへ共通の音声時計ランプを供給します。

UIはトークン、ナビゲーション、機種選択、ボタンを共有します。初期部品群のカタログは`/lab/components`で、追加ランタイムやStorybookビルドは不要です。

評価済みレポートを公開するコマンド：

```sh
pnpm --filter chipvoice-web publish:lab .artifacts/listening/NEW/report.json
```

失敗／不完全な証拠を拒否し、全WAVハッシュを検証し、FLACにしてデコード後の16ビットPCM一致を確かめます。同じ録音は1ファイルを共有します。初回スナップショットは17 MiB、固有96録音で、必要時に取得します。マニフェストにエンジン`377636b`と元レポートのハッシュを記録します。過去の証拠なので、ライブエンジンを更新しても黙ってラベルを変えません。元のローカル評価ファイルは不変、非圧縮のまま保ちます。

出典：[Web Audio codec guide](https://developer.mozilla.org/en-US/docs/Web/Media/Guides/Formats/Audio_codecs)、[AudioParam ramps](https://developer.mozilla.org/en-US/docs/Web/API/AudioParam/linearRampToValueAtTime)。

<a id="regression-evidence"></a>
## 回帰の証拠

持続音のブラウザープローブは、128サンプルの音声時計ブロックで共有出力を測ります。テンポ3変更とNES → SNESで正確な小数位置を保ち、ほぼ無音のブロックは0（ピーク閾値1e-5）。要求は0ミリ秒で、短い途切れも許しません。決定的な連続性検査であり、任意の音色変更が同じ波形になる主張ではありません。

このプローブで別の起動バグも見つかりました。後から作る置換エンジンのレジスター初期化オフセットをAudioContext時刻0へ固定していました。作成時へ固定し直してSNESの起動遅延を保ちます。同じ音を原点0と2秒で描き、相対PCMが一致する回帰を追加。修正前の最大サンプル差は0.04544でした。5機種のオフラインゴールデンは不変です。

さらに、失敗する旧エンジンの後の新機種要求、停止エンジンの再利用、録音伴奏の同一性、初回Play前の音量、バッファー読込中断、最大4ソースの重なりを検証します。公開は不完全な集合を拒否し、壊れたFLACキャッシュは検証済みWAVとデコードPCMを比較してから修復します。ブラウザー試験は`.artifacts`へPC／モバイル画像、動画、音声測定を保存し、CIはコーパスを再レンダーせずそれをアップロードします。

## アプリ全体の再生セッション

Web のレイアウトが単一の `PlaybackSession` を所有します。ページを離れても、
選択中の音源は再生・一時停止位置を保持します。次の音源は準備が終わるまで無音で
待機し、明示的な再生操作があった場合だけ現在の音源と交代します。古い音源は
フェード後に解放します。編集画面を開くだけでは再生中の曲は変わりません。
再生を維持するために非表示のページを保持することもありません。

共通の `PlayerControls` をアレンジ、試聴ラボ、ループ編集、作曲画面、公開曲で
使用します。画面下の固定プレーヤーは再生位置、先頭に戻る、リピート、音量を
共有し、モバイルでは折りたたみ表示になります。再生位置は秒単位で、音声出力の
時計に合わせます。毎フレームの位置更新は限られた DOM 要素に反映します。

音源に適した実装を維持します。準備済みの比較音源は `BufferPlayback`、曲全体の
レンダリングは `ProjectPlayer`、パッドや録音は `LivePlayback` を使います。
公開曲は保存済みの音声ファイルを HTML メディア要素でストリーミング再生し、
ブラウザーで再レンダリングしません。選んだ曲の情報と音声だけを取得します。
一覧・ライブラリ・アーティストページから再生待ちリストを作成でき、曲が終わると
一度だけ次へ進みます。ブラインド比較では自動進行を解除し、ページを移動しても
曲の識別情報やダウンロードを隠します。ループは既存の楽譜をそのまま作曲画面へ
引き継げます。

セッションはブラウザーのタブ単位です。再読み込みやタブを閉じると終了します。
次の音源の準備に失敗した場合、現在の曲を維持してエラーを表示します。
`/lab/components` で待機中・読み込み中・コンパクト表示を確認できます。

`test-player-session.mjs` は所有権、競合、失敗、解放、再生待ちを検証します。
`test-player-browser.mjs` は実際の音声コンテキストの継続、公開 WAV の再生、
作者表示、曲の自動進行、デスクトップ・モバイル・日本語表示、ブラインド比較を
検証します。スクリーンショットは `.artifacts/player` に保存します。

## 対話操作向けの逐次再生

SDK 0.18.0 以降、Web の作曲画面は `new ProjectPlayer({preview: true})` を使用します。この SDK のオプションは、オフライン書き出しと同じプロジェクトコンパイラと音源コアを使い、生成できた PCM ブロックから順に再生します。再生前に曲全体を WAV に変換してデコードする必要はありません。`previewMetadata` は長さ・ネイティブ再生の状態・ミックス結果を公開し、`losses` は両方の再生モードで使用できます。プレビューモードの `prepared` は `null` のままです。ファイルが必要な場合は `prepareProject()` または `renderProject()` を明示的に呼び出します。

```js
import {ProjectPlayer} from 'chipvoice';

const player = new ProjectPlayer({preview: true});
// Call play from a user gesture to unlock browser audio.
void player.play();
await player.load(project);
await player.update({tempoScale: 1.25});
player.setTitle('New title'); // Metadata only; no audio preparation.
```

準備中も現在の音を維持し、再生・一時停止の最新の操作を尊重します。表示は音声出力クロックに従います。ワーカーを再利用し、バリエーション・PCM・DSP 状態のキャッシュには上限があります。ただし、未準備の設定へ曲の途中で変更するときは DSP の履歴を再構築する必要があります。音符の位置だけではエンベロープ、サンプル位置、フィルタ、エコーを復元できません。ブラウザの音声解除、未取得のデータ、出力機器の遅延も残ります。既存の `ProjectPlayer()` の既定動作は互換性のため全体バッファ方式を維持します。
